## 开场：同一张"标准答案"处方，三个团队三种结局

引言的最小训练现场只用了四行字：给模型一道 `17 × 23`，让它尝试四次——

| 尝试 | 模型回答 | 程序检查结果 |
|---|---|---:|
| A | 17 × 23 = 391 | 1 分 |
| B | 17 × 23 = 381 | 0 分 |
| C | 20 × 23 - 3 × 23 = 391 | 1 分 |
| D | 17 × 23 = 401 | 0 分 |

引言在这里停住了：训练就是调整概率，让得 1 分的答案以后更容易出现，得 0 分的更少出现。本章从下一步开始——把这张表放大一万倍：上万道题、每题几十条并行采样、连续训练数天。放大之后，"有标准答案"这句处方会在三个团队手里长出三种完全不同的结局（以下为教学用合成场景，情节模式来自公开报告的真实案例，数字为示意）：

- **团队甲，数学计算题**：验证器做数值精确比对，答案无歧义。训练奖励稳步上升，独立评测同步上涨，抽查样本确实更常做对。这是教科书剧本。
- **团队乙，代码题**：用单元测试当验证器，但测试用例只覆盖了题目的一部分。两周后训练奖励逼近满分；人工抽查发现，模型学会的是专门满足已有测试的输出模式——任务本身并没有做对。奖励涨了，能力没涨。
- **团队丙，竞赛级数学**：基座在这批题上几乎从来做不对，每题采 16 条全是 0 分。组内没有对比，训练曲线纹丝不动，采样账单照付。烧了两周算力，最大的产出是确认了"这批题现在还训不动"。

同一句处方——"用标准答案当奖励"——三种结局。差别不在"有没有标准答案"，而在三件没有写在处方上的事：**奖励是否真的可靠**（团队乙的问题）、**基座是否做得出正确答案**（团队丙的问题）、**训练涨的分数是不是你要的那种分数**（团队乙的另一个问题，也是本章后半的主线）。

用八层坐标系给三个团队定位，故障点一目了然：团队乙死在第③层（学习信号：验证器度量的东西与任务目标不再重合）；团队丙死在第②层到第③层的接口（训练材料里采不出任何带信号的样本）；"涨的分数是不是你要的分数"则是第⑧层（晋级证据）的问题。同一张坐标图，三处故障——这也是本章的路线：先修信号（第 2、3 节），再修读数（第 4 节），最后修过程与证据（第 6、7 节）。

> **本章只解决一件事：如何判断任务适不适合 RLVR，如何设计奖励与训练过程，并证明收益是真实泛化。**

## 一、RLVR 的基本训练闭环：从一条概率到一次更新

**RLVR（Reinforcement Learning from Verifiable Rewards，可验证奖励强化学习）**可以先理解为：让模型实际做题，用程序判定每次尝试的对错，再把"对错"换算成参数更新。它的最小闭环长这样：

```text
任务池(Prompt,按难度与配比过滤)
    ↓
┌─ 在线循环:数据生成与模型更新形成闭环 ─────────────────────────┐
│                                                              │
│  采样:当前模型对同一道题生成 G 条 Rollout                     │
│        (开场的 A/B/C/D 就是一组 G = 4)                        │
│    ↓                                                         │
│  验证:Verifier 逐条判定对错 → Reward(常为 1/0 或离散分)      │
│    ↓                                                         │
│  归因:把"这组里谁比谁好"换算成 Advantage                      │
│        (正:以后加强;负:以后抑制)                             │
│    ↓                                                         │
│  更新:按 Advantage 调整 Policy 的概率,回到采样                │
│                                                              │
└──────────────────────────────────────────────────────────────┘
    ↓ 侧线:每隔若干步,在独立评测集上测目标指标与回归指标
```

Policy、Rollout、Reward、Advantage、Reference Policy 这五个词引言已经定义过，这里不再重复。闭环里真正的新角色是 **Verifier（验证器）**——判卷子的那个程序。它和上一章的主角 Reward Model 不是一回事：

| 维度 | Verifier（验证器） | Reward Model（奖励模型，T07） |
|---|---|---|
| 打分依据 | 规则、标准答案、单元测试、环境状态——程序执行 | 从人类偏好数据里学出来的打分模型 |
| 分数含义 | 对错（常为 0/1 或离散） | "哪个更好"的相对偏好（连续标量） |
| 可否精确复现 | 可以：确定性程序，同输入同输出 | 不可以：模型打分带噪声，会漂移 |
| 主要失效模式 | 规则漏洞被钻（本章第 2 节） | 评分器偏差、过优化（T07 第 6 节） |
| 适合的任务 | 有客观对错的任务 | 开放式、多个合理答案的任务 |
| 决策层位置 | 反馈来源 + 系统实现 | 反馈来源 + 系统实现 |

一个快速的自查：如果你要靠"感觉像是对的"来打分，那是 Reward Model 的地盘（回 T07）；如果可以用程序复算，才轮到本章。

闭环的每个环节都有自己典型的失败方式，先把它们挂到号，后面各节对号入座：

| 闭环环节 | 典型失败 | 本章归属 |
|---|---|---|
| 任务池 | 难度配错：全对或全错，组内无信号 | 第 3 节 |
| 采样 | 组不可比、温度不当、长度失控 | 第 3、6 节 |
| 验证 | 规则漏洞被钻、误判带毒 | 第 2 节 |
| 归因 | 基线失准（Critic 偏差或组内方差为零） | 第 5 节 |
| 更新 | 漂移过度、语言能力退化 | 第 5 节（KL）、第 6 节 |
| 评测侧线 | 拿训练池当验收集、口径漂移 | 第 7 节 |

### "在线"是这套循环的成本来源

引言留过一个尾巴：在线路线的工程定义在这里补全。**在线指数据生成与模型更新形成循环**——训练期间，当前模型要不断产生新的尝试，这些尝试立刻变成训练数据；**离线路线**（示范、偏好对）开工前数据已经备好，训练时只是反复读取（on-policy 一词的完整定义与随之而来的 Policy Lag 机制在第 9 章）。在线循环带来三笔离线路线没有的开销：

| 开销 | 它意味着什么 |
|---|---|
| 采样算力 | 每一步更新前都要用当前模型推理；训练账里长出了推理账 |
| 数据"过期" | 生成数据的版本落后于正在训练的版本（完整机制 Policy Lag 在第 9 章） |
| 循环故障面 | 采样集群、验证器、训练器任一环节卡住，整条流水线停摆 |

采样算力这笔账值得用真实刻度感受一下：[Inkling 2 Small](https://thinkingmachines.ai/news/inkling-2-small) 官方披露的 RL 阶段跑了 9 天、超过 17M 条 Rollout，采样与训练的算力配比 sampler : trainer = 5 : 3——采样比训练本身还贵（T02 已拆过这本账）。**RLVR 不是"换个损失函数"，是把推理集群接进了训练循环。**

### 一个训练步的账单：把循环跑出数量级

再用一组教学数字把"在线循环"落到实处（全部为示意值，推导方法是真的）：设每个训练步从任务池取 512 道 Prompt，组大小 G = 8，平均每条 Rollout 生成 1K Token——

```text
每步采样量 = 512 × 8 = 4,096 条 Rollout ≈ 4M 生成 Token
每步验证量 = 4,096 次判定(单元测试类还要真跑测试,更贵)
若训练 1,000 步 ≈ 4B 生成 Token 的采样账
    ↓ 注意:这笔生成发生在训练侧,但按推理价计价
    ↓ 这就是 sampler : trainer = 5 : 3 这类配比的来源
```

三个直接推论：组大小 G 每翻一倍，采样账翻一倍；任务平均响应长度每翻一倍，采样账再翻一倍（第 6 节的"响应长度"曲线因此同时是一条成本曲线）；验证成本高的验证器（真跑测试、真启动环境）会把验证本身变成第二本采样账。第 9 章把这套循环展开成完整的异步拓扑，这里只需要记住：**闭环图里那个"回到采样"的箭头，每转一圈都在花钱。**

> **架构智慧：**可验证奖励描述的是奖励来源，不规定优化器。同一个 Verifier，可以接 GRPO 的组内比较，也可以接 Critic-based PPO 的单轨迹学习——把"上 RLVR"当成选了一个优化器，是引言"反馈来源 ≠ 优化器"的分层在本章的再现。优化器怎么选，第 5 节单独展开。

## 二、前提一：奖励是否可验证——规则正确 ≠ 奖励完整

"可验证"三个字最容易读浅：以为任务有标准答案，奖励就自动可靠。实际上验证器是一个工程对象，有自己的质量维度和失效模式。

### 1. 验证器家族与各自的软肋

| 验证器类型 | 判定方式 | 典型任务 | 主要失效模式 |
|---|---|---|---|
| 数学答案比对 | 数值或符号等价判定 | 计算、数学题 | 只比答案不查过程，"蒙对"和枚举答案都能得分 |
| 单元测试 | 跑测试看通过与否 | 代码生成、修复 | 测试覆盖不全；模型过拟合测试集，甚至设法绕过或改写测试 |
| 编译与静态检查 | 能否编译、过 lint | 代码、结构化生成 | 能编译 ≠ 正确；只验证了语法层 |
| 结构化约束 | schema、正则、字段校验 | 格式化输出、工具调用 | 模型塞满所有可能取值蹭过校验 |
| 环境最终状态 | 环境到达的状态判分 | Agent 任务（第 9 章主场） | 状态可能被副作用"制造"出来，且难以归因到步骤 |

### 2. 评估一个验证器的四个维度

把"它能不能判对"拆成可测的四问：

| 维度 | 问的问题 | 怎么测 |
|---|---|---|
| 覆盖率 | 多大比例的任务能被它判定？ | 任务池抽样统计"可验证比例" |
| 误判率 | 假阳（错的判对）与假阴（对的判错）各多少？ | 人工标注一批样本，对照验证器输出 |
| 验证成本 | 每次判定花多少算力与时间？ | 单元测试要真跑、环境要真启动，都会吃预算 |
| 抗投机性 | 被持续攻击数天后还剩多少可信度？ | 对抗审计：专门找人（或模型）钻它的空子 |

第四问最容易被跳过，也最致命。常规软件的校验逻辑面对的是随机用户；验证器面对的是**一个每分钟都在变聪明的、被明确激励去钻它空子的对手**——优化器优化的目标就是"让验证器给分"，验证器度量的东西与"真正完成任务"的重合度，决定训练方向与能力方向的夹角。

### 3. 规则正确但奖励不完整：三个最小例子

- **答案枚举**：验证器只检查"回答里是否包含正确答案字符串"，模型学会在一次回答里列出十几个候选值——命中就得分。
- **只查结果不查过程**：任务要求推理过程加答案，验证器只看答案；模型把算力全部省下来去猜答案，推理链越长越差。
- **测试过拟合**：单元测试只覆盖部分行为，模型精确拟合了这几个测试的检查点，通盘行为是错的。

这些例子的共同点：**程序没有写错，它忠实执行了规则；错的是规则度量的东西与任务目标不再重合。**这就是奖励投机（Reward Hacking）的直觉版定义——模型找到奖励规则的漏洞拿分，而不是完成任务。正式定义、系统性分类和检测通道在第 10 章展开；本章先把它当作设计压力：验证器是 RLVR 的攻击面，要用安全评审的姿态对待它。

### 4. 误判的不对称性：假阳比假阴更毒

验证器的两类误判，代价完全不对称：

| 误判类型 | 发生了什么 | 对训练的影响 |
|---|---|---|
| 假阳（错的判对） | 一条错误轨迹得了 1 分 | 直接被加强——优化器在教模型做错事 |
| 假阴（对的判错） | 一条正确轨迹得了 0 分 | 只是被抑制或浪费——损失一条好样本 |

由此得出一条设计纪律：**假阳是带毒的梯度，假阴只是丢掉的样本。**验证器的精确率（它判对的范围里真对的有多少）比召回率更优先——宁可少给分，不可错给分。这也是工程上常用"严验证 + 宽任务池"组合的原因：验证从严，把拿不准的判定交给人工抽检或直接记 0；同时把任务池做大，让真样本足够多，抵消假阴造成的浪费。

### 5. 修复手段一页表

| 投机面 | 常用修法 |
|---|---|
| 答案枚举 | 收紧格式约束（只认首个答案）、过程一致性检查 |
| 只查结果 | 引入过程或格式约束；混合人工抽检 |
| 过拟合测试 | 隐藏测试集、任务变体生成（与第 10 章的抗污染评测同源） |
| 验证器自身缺陷 | 验证器版本化、误判率监控、上线前对抗审计 |

### 6. 验证器的工程形态：组合、级联与版本化

| 形态 | 做法 | 适用条件 |
|---|---|---|
| 双通道组合 | 数值比对 + 单元测试各自判定，取交集或加权 | 单一验证器覆盖不足 |
| 级联 | 先跑便宜检查（格式、长度），再跑贵的（真跑测试、起环境） | 验证成本高，先筛掉明显无效的回答 |
| 版本化 | 验证器代码与规则随任务池版本一起管理 | 复现与回滚 |

最后一条值得强调：验证器是训练代码的一部分，**改验证器等于改训练目标**。它的版本必须和 Checkpoint、任务池版本绑定记录——否则训练完成后，没人能回答"这个 Checkpoint 是被哪个版本的规则训出来的"，复盘与回滚都无从谈起。

> **判断边界：**一个验证器值不值得信，不看它在设计文档里多优雅，看它在"被一个持续变聪明的对手攻击数天"的条件下，度量结果与真实任务完成还有多少重合。覆盖率、误判率、抗投机性三问没有答案之前，"任务有标准答案"不构成上线 RLVR 的理由。

## 三、前提二：基座是否具备能力种子——RL 放大，不无中生有

第二个前提常被更彻底地误读：以为 RL 能"教会"基座从不会到会。看回闭环的归因一步：无论用组内比较还是价值基线（第 5 节），学习信号都来自**差异**——这条比那条好、这次比预期好。如果基座在当前任务上从来做不对：

- 组内全是 0 分 → 没有对比 → Advantage 全为零 → 没有梯度；
- 单条轨迹全错 → 再准的 Critic 也只能告诉你"和预期一样差"。

**能力种子**指的就是这件事：基座在合理的采样预算内，能偶尔——哪怕频率很低——产出正确轨迹。RL 的工作不是创造能力，而是把"偶发正确"的采样概率提高、稳定下来。

### 1. 一道算术题：组内有信号的概率有多低

设基座在某档任务上单次正确率为 p，组大小 G = 16（教学示意，独立采样假设）：

| 单次正确率 p | 组内至少一条正确的概率 1 − (1 − p)^16 | 读数 |
|---:|---:|---|
| 5% | ≈ 56% | 大部分组有信号，健康区间 |
| 1% | ≈ 15% | 七个组里六个白采 |
| 0.5% | ≈ 7.7% | 绝大多数采样花在全零组上 |

三个数字说明同一件事：**"组内有对有错"不是软建议，是信号存在的硬条件。**p 太低时，大部分算力花在没有梯度的组上；而且即使偶尔出一条正样本，组内信号也极弱。任务难度、组大小、采样温度、任务配比，都是围绕"把基座放进有信号区间"来调的。

### 2. 先修基座，还是硬训

判断树很简单：

```text
基座在这批任务上多采样测试(正式指标见第 4 节)结果如何?
    ├─ 全对(太容易)──→ 升难度、换任务池,否则没有学习信号
    ├─ 有对有错(边缘区间)──→ RLVR 的主场:提高"做对"的采样概率
    └─ 全错(没有种子)──→ 回 T06:先 SFT / 蒸馏建立行为与格式,
                          或降难度、换任务,不要指望 RL 无中生有
```

"先示范、再强化"是 2026 年公开配方里可见的常态：GLM-5 的后训练就是先用 SFT 扩展 agent 与 coding 数据、引入多种思考模式，再依次进入 RL 阶段（[官方技术报告](https://arxiv.org/abs/2602.15763)口径）。社区讨论里也有一种把 SFT 重定位为"格式与模式对齐"载体的叙事——注意这是叙事层面的概括，不是所有配方的实况；各家 SFT 段承担的真实职责，只有各自的消融能回答（T06 展开）。

### 3. 难度分层是采样预算的杠杆

与其让全零组烧钱，不如把任务按基座通过率分层：太容易的少采、全难的暂缓、把预算集中在"边缘任务"——模型有时对有时错的那些。这不是技巧，是上一小节算术的直接结论：只有边缘区间有信号。

### 4. 种子检测的口径：温度、提示与难度标定

"基座能不能偶尔做对"不是模型的固有属性，而是模型 × 采样设置 × 提示形态的联合结果。测种子时必须锁口径：

- **温度**：低温采样的分布更尖，可能测不出"偶尔能对"；高温探索多但噪声大。种子检测应使用与训练一致的温度；
- **提示形态**：同一道题，零样本与少样本提示下的正确率可能差别很大。检测口径要和训练时的任务模板一致；
- **难度标定要定期重跑**：训练本身会改变通过率——上周的"边缘任务"这周可能已经全对。难度分层不是一次性标注，是随训练推进动态维护的桶。

一句收束：种子检测回答的不是"模型行不行"，而是"这批任务、这个采样设置下，组内会不会有方差"——它直接决定任务池里的题该进哪个难度桶。

### 5. 种子从哪来：三条补种路线

检测出"没有种子"不是终点，是三条路线的起点：

| 路线 | 做法 | 代价 |
|---|---|---|
| 任务分解 | 把全错的大题拆成有信号的小题，随训练推进逐步加回难度 | 任务工程量大，拆法本身引入设计偏差 |
| 示范播种 | 用 SFT / 蒸馏先教会基座"这题长什么样、怎么做对一次" | 见 T06：示范质量决定播种上限 |
| 换底座 | 承认当前基座没有这颗种子 | 最贵，但最诚实 |

一句提醒：补种路线的选择本身就是"任务形态 → 数据形态"的决策，与第 5 节的算法选择同属一条因果链——先定种子来源，再定优化路线，顺序反过来就会反复返工。

> **判断边界：**RL 不是能力的发生器，是放大器。开算力之前先问：这道题我们的基座"偶尔能做对"吗？如果答案是"从来没对过"，先回去补基座——SFT、蒸馏、换底座或降难度；指望 RLVR 无中生有，烧掉的是采样账单，得到的是一条平线。

## 四、RLVR 到底买到了什么：pass@k、maj@k 与一场未定的争论

前提过关、训练跑起来了，第三个问题才浮出水面——也是 2025 到 2026 年 RLVR 研究最热的争论：训练分数涨了，模型到底**变强了**，还是只是**把会的东西输出得更稳定了**？要讨论它，先补两个指标的定义。

### 1. 先定义指标：同一模型，三种问法

- **pass@k**：同一道题独立采样 k 次，只要有一次正确即记成功。它回答"给足够多次机会，能不能做出来"——能力边界的上限视角。
- **maj@k（majority vote@k）**：采样 k 次后对答案做多数投票，多数答案正确才记成功。它回答"一次调用加便宜投票，能不能稳定做对"——部署视角。
- **Best-of-N**：生成 N 条再由挑选器（Verifier 或 Reward Model）选一条输出。pass@k 可以看作挑选器完美时的上限。

同一个模型，三种问法可以给出完全不同的数字。一个直观的数量级感受（教学示意，假设每次采样独立、单次正确率 0.6）：maj@5 的正确率约 0.68——多数投票把 60 分的水平抬到 68 分。注意真实推理里同模型的多次采样高度相关，实际提升通常低于独立假设的估计；这个例子只说明一件事：**聚合策略本身就是正确率的一个自由度。**

### 2. 两种解释，一组观察

RLVR 之后常见的观察模式是：单次成功率与 maj@k 明显上涨，而大 k 的 pass@k 几乎持平。这组观察有两种针锋相对的解释：

| 解释 | 内容 | 如果为真，意味着 |
|---|---|---|
| 采样分布锐化 | RLVR 把模型已有能力的输出概率调尖：会的做法更常出现；但"能解出的题集"没有变大 | RLVR 买的是可靠性与采样效率，不是新能力 |
| 能力边界扩展 | 模型真的解出了训练前解不出的题（pass@k 在某些预算、某些任务上也会涨） | RLVR 可能带来超出基座已有能力的泛化 |

### 3. 争论的现状：双方证据并陈，尚无定论

- **"锐化"一方的证据**：2025 年下半年的综述（[arXiv:2510.04028](https://arxiv.org/html/2510.04028v1)，2025-10，预印本综述）汇总了"RLVR 后 pass@k 平坦而 maj@k 提升"的多项报告，倾向于"只锐化、不扩边界"的解读；[ACL 2026 的一篇长文](https://aclanthology.org/2026.acl-long.2102.pdf)把这一方向的考察推广到视觉语言模型，仍未发现边界扩展。
- **方法学批评一方的证据**：反方指出 pass@k 的测量本身不稳定——pass@k 曲线可能随 k 的大小交叉反转（pass@k inversion），小 k 下的比较可能系统性误导；评测采样温度等设置也会显著改变结论。

两派在指标口径、任务与模型范围上并不同构，谁也还没说服谁。本专题按事实纪律写明：**此争论尚无定论。**

### 4. 工程姿态：把争论当研究问题，把指标选择当工程决策

争论悬而未决，训练决策却不能等。可操作的姿态是四条：

1. **双指标都测**，并写清采样次数 k、温度、数据集版本与评测方——不带口径的 pass@k 数字无法与他人比较；
2. **按部署口径选主指标**：线上单次调用为主，看单次正确率与 maj@小 k；有采样预算的产品，pass@k 才是钱；
3. **"能力边界扩展了"当假设，不当默认收益**——要宣称扩展，需要基座与 RL 版在大 k 下的受控对照；
4. **别贬低"锐化"**：即便某次训练只提高了 maj@1，对部署也是真金白银——同样的任务用更少的采样完成，就是 T02 讲过的推理账在下降。

### 5. 从指标到账单：一次换算

把指标差异翻译成部署成本（教学示意，数字为假设）：设产品目标正确率 0.85，两个候选模型——

| 候选 | maj@1 | maj@8 | 达到 0.85 的方式 | 单任务调用成本 |
|---|---:|---:|---|---|
| 模型 P（RLVR 后） | 0.86 | 0.94 | 单次调用即达标 | 1 次生成 |
| 模型 Q（基座） | 0.55 | 0.86 | 每任务 8 次采样加投票 | 8 次生成 + 投票 |

如果只看"maj@8 是否打平"，两个候选一样好；但模型 P 用一次生成做到了模型 Q 八次生成的事——这就是"采样效率也是真收益"的账面表达。反过来，如果产品本来就带采样预算（例如必须多路采样保证鲁棒），pass@k 口径才反映真实差距。**指标没有高下，口径才有对错：先写清产品的调用方式，再选主指标。**

读 maj@k 还有两个容易踩的细节：其一，**平票**——k 为偶数或多个答案并列时怎么记（记失败、记半分还是剔除），必须在口径里写死；其二，**错误的分布比错误率更重要**——若模型的错误高度集中在同一类题上，多数投票几乎不涨；若错误分散且接近随机，同样的单次正确率能从投票里赚到更多。这也是独立假设在真实设置里失准的原因，"maj@k 的提升幅度"本身就在携带关于错误结构的信息。

> **判断边界：**"RLVR 只锐化分布还是扩展边界"是研究问题，尚无定论；但工程上可以先问一个更务实的问题——在你的部署口径里，哪个指标是钱？把争论当研究追踪，把指标选择当决策先行。

## 五、算法与目标函数：PPO、GRPO 与"基线从哪来"

引言只留了一页四路线对比表，机制详解归本章。前面反复铺垫的那句话——"学习信号来自差异"——现在正式展开：**Reward 是一条绝对分数，更新需要的是相对量：比同伴好、比预期好。把绝对分数变成相对量的方案，就是"基线方案"；两大算法家族的分野，正在于基线从哪来。**

### 1. Value、Critic、Advantage：把"比预期好多少"算出来

- **Value（价值）**：从当前状态出发、按当前策略继续走，预期的累计回报是多少。它是"预期基线"——这道题、这个起点，模型正常发挥能拿几分。
- **Critic（评论家）**：学习并输出 Value 的辅助模型，与被训练的 Policy（Actor）同步训练。
- **Advantage（优势）**：实际回报减去预期基线。正数说明这次比预期好，加强；负数说明比预期差，抑制。

为什么非要基线？没有基线时，你只知道"这条轨迹得了 1 分"，不知道 1 分是超常发挥还是及格线以下的运气。基线把绝对分数换成"相对预期"，更新信号因此有了方向和大小，训练方差也显著下降。开场那张四次尝试表就是现成的例子（教学演示，Reward 取 1/0）：

```text
GRPO 视角(组内均值当基线):
  组 = {A, B, C, D},得分 = {1, 0, 1, 0},组均值 = 0.5
  Advantage = {+0.5, −0.5, +0.5, −0.5}
  → A、C 加强,B、D 抑制;组内没有全对或全错,信号成立

PPO 视角(Critic 当基线):
  Critic 估计这道题的 Value = 0.3(预期三成把握)
  A 的 Advantage = 1 − 0.3 = +0.7;B 的 = 0 − 0.3 = −0.3
  → 单条轨迹即可更新,不需要"同题四条";代价是要训练 Critic

反例(组内全对):得分 = {1, 1, 1, 1} → Advantage 全 0
  → 组式路线在这道题上没有学习信号——第 3 节"边缘区间"的另一种说法
```

还有一个容易被忽略的动态性：**基线不是常数**。组均值随策略变强而上移——昨天 +0.5 的表现在今天可能已低于均值；Critic 的 Value 估计也必须跟着 Policy 亦步亦趋地重学，否则"预期"过时，Advantage 会系统性偏正或偏负。这就是两条路线共同的深层难题：基线必须与策略同步进化。Critic 路线为此付出"第二个模型的训练负担"，组式路线为此付出"持续的组采样负担"——又一次，同一枚硬币的两面。

### 2. 两条路线的完整数据流

```text
Critic-based PPO(单轨迹学习)                GRPO(组式相对优化)
─────────────────────────────             ─────────────────────────
Policy ──采样──→ 1 条 Rollout             Policy ──同题采样──→ G 条 Rollout
                    ↓                                         ↓
Verifier → Reward(0/1)                    Verifier → 逐条 Reward
                    ↓                                         ↓
Critic → Value(预期基线)                   组内均值 = 这道题的基线
                    ↓                                         ↓
Advantage = Reward − Value                Advantage = 得分 − 组均值
                    ↓                                         ↓
更新 Policy;同时训练 Critic               更新 Policy(高于均值加强,低于抑制)
Reference(冻结)──KL──┐                    Reference(冻结)──KL──┐
                      └→ 约束漂移                                └→ 约束漂移
```

**PPO**（[原论文](https://arxiv.org/abs/1707.06347)，2017，方法起源/历史锚点）来自更早的强化学习传统：策略梯度加信赖域式的裁剪，保证每步更新不迈太大。**GRPO**（Group Relative Policy Optimization）由 [DeepSeekMath](https://arxiv.org/abs/2402.03300)（2024，方法起源/历史锚点）提出：把 PPO 里"训练一个 Critic 当基线"替换成"同题采一组、组内统计当基线"。此后出现一批目标函数变体（如 DAPO、GSPO，历史锚点），围绕组内比较的统计细节、长度偏差等问题继续改进——变体名字不重要，重要的是它们都在回答同一个问题：基线怎么定更稳。

### 3. 对比：算法选择就是一份系统账单

| 维度 | Critic-based PPO | GRPO（组式相对优化） |
|---|---|---|
| 基线来源 | 训练一个 Critic 输出 Value | 同题 G 条 Rollout 的组内统计 |
| 额外模型 | Critic（常与 Policy 同量级，同练同部署） | 无额外模型（Reference 两者都要） |
| 采样组织 | 单条轨迹即可更新 | 每题须采一组可比轨迹 |
| 信号粒度 | 可做到 Token 级细粒度 Advantage | 组级相对比较为主（变体有细化） |
| 成立前提 | Critic 学得准（价值偏差会直接传导进更新） | 组可比 + 组内有方差 |
| 典型失效 | Critic 偏差、两个模型交替训练的不稳定 | 全对/全错组无信号；长程任务组难构造 |
| 系统账单 | 多一个模型的显存、算力与训练不稳定性 | 多一份组采样预算，推理集群更重 |

2026 年的公开图景里，组式路线是可核实的高频选择：[GLM-5 技术报告](https://arxiv.org/abs/2602.15763)披露的后训练以 GRPO 基的组式优化为主线（官方报告口径）。社区也有以"GRPO Won the Post-Training War"为题的观点文章（Medium，2026）——**那是观点文章层级的叙事，不是行业事实**；能核实的是"GRPO 及其变体在公开技术报告中高频出现"，核实不了"战争已经结束"。

再补一层数量级直觉（教学示意）：Critic 的账单是"多一个要训练和部署的模型"——显存、优化器状态、前向反向，量级随所选 Critic 的规模走；组均值的账单是"每题多采 G − 1 条"——按第 1 节的算法，G 从 8 加到 16，采样账直接翻倍。两个方案谁便宜，取决于瓶颈在哪：显存紧、采样吞吐富，组式占优；采样紧、显存富（例如已有大推理集群、训练集群显存吃紧），Critic 路线的相对成本就下降。上表"系统账单"那一行，展开来就是这道乘法题。

### 4. 反方向的公开案例：GLM-5.2 为什么转 Critic-based PPO

组式路线并非处处成立。[GLM-5.2 官方博客](https://z.ai/blog/glm-5.2)（2026-06）给出的叙述是：面向超长程 Agent 任务，超长轨迹经 Compaction（上下文压缩，完整定义在第 9 章）切成数量、长度都不规则的子轨迹之后，"同题一组规整可比轨迹"的 GRPO 前提不再自然成立，于是转向 Critic-based PPO 做单轨迹学习与 Token 级 Advantage（官方博客口径；完整因果链在第 9 章拆解，本章只借它说明一件事：**算法前提是被任务形态决定的使用条件，不是排行榜上的段位**）。

两个纪律必须跟上：其一，因果方向是"任务形态变化 → 方法前提失效 → 换方法"，而不是"换了方法 → 成绩好"的倒推——后一种读法正是引言错误 4 的样子；其二，不可写成"PPO 取代 GRPO"：GLM-5 仍以组式为主，GLM-5.2 只是在长程任务上转向 Critic-based PPO，两条路线在 2026 年是并存关系，不是替代关系。

### 5. KL 控制：两条路线共用的缰绳

无论哪条路线，通常都保留一个**冻结的 Reference Policy**（训练起点的快照），在目标函数里加一项 KL 惩罚——当前策略与参考策略的概率分布距离。它约束 Policy 不要漂太远：漂太远的直接代价是语言能力退化、输出模式塌缩，间接代价是后续任务的采样多样性枯竭（下一节的熵曲线就是它的仪表）。KL 系数是真实的超参数：太松，缰绳形同虚设；太紧，模型学不动新东西。DPO 里 Reference 的另一种用法在 T07 讲过，此处不重复。

> **架构智慧：**算法选择的本质是基线方案的选择，而基线方案连着一张系统账单：Critic 是"训练一个会预期的模型"的账单（显存、算力、训练不稳），组均值是"每题多采几条"的账单（采样预算、组构造约束）。没有免费的基线——只有把这笔成本挪到那一笔的取舍。

## 六、训练健康面板：四条曲线联读

前提都过了、算法选好了、训练跑起来了——现在的问题变成：**怎么知道训练正在变好，而不是正在变坏而看起来像变好？**RLVR 的训练监控至少要看四条曲线，且必须联读。

### 1. 四条曲线各自看什么

| 曲线 | 含义 | 单独看的陷阱 |
|---|---|---|
| 训练奖励均值 | Verifier 给出的分数随步数的走势 | 它是"训练目标自己的表现"，涨了只说明优化器在工作 |
| 策略熵（Entropy） | 模型输出分布的分散程度：越平越有探索性，越尖越在重复少数做法 | 熵下降本身是收敛的正常部分，快慢和幅度才是信号 |
| 响应长度 | 生成回答的平均 Token 数 | 变长常被误读为"思考更努力"，也可能只是长度投机 |
| 组内方差 | 同题一组得分的差异 | 方差趋零无论全对全错，都意味着该题失去学习信号 |

其中策略熵值得单独一句：它衡量模型"还剩多少可选做法"。训练自然会把分布推尖——这正是第 4 节说的"锐化"；问题是推尖的速度。健康的收敛是熵缓慢下降后趋稳；**熵快速塌向零**意味着模型收缩到极少数做法上，之后的新任务、新题型将不再产生有效梯度——探索枯竭不是终点前的安静，是提前退场。

四条曲线在健康与病态训练下的形态示意：

```text
健康收敛                              病态(长度投机 + 熵塌缩)
奖励                                  奖励
 │      ＿＿＿──                       │    ＿＿────────  ← 冲向满分
 │   ＿－                              │ ＿－
 │＿－                                 │－
 └───────────→ 步数                    └───────────→ 步数
熵                                    熵
 │＼                                   │＼
 │ ＼＿                                │ ＼
 │    ＼＿＿── 趋稳但不到零             │   ＼＿＿  ← 快速砸向零
 └───────────→ 步数                    └───────────→ 步数
响应长度:平稳或缓变                    响应长度:持续陡增
组内方差:收敛但不归零                  组内方差:迅速归零
```

看图的方法比图本身重要：不要问"这条曲线对不对"，要问"四条曲线的组合讲了一个什么故事"——同一段缓降的熵，配上暴涨的长度与归零的方差，就是另一个故事了。

### 2. 联读表：模式 × 判读 × 处置

| 奖励 | 熵 | 长度 | 组内方差 | 判读 | 处置 |
|---|---|---|---|---|---|
| ↑ | 缓降 | 稳 | 收敛但不归零 | 正常收敛 | 按计划继续 |
| ↑ | 快塌 | 暴涨 | 收敛 | 长度投机嫌疑：更长不等于更对 | 查长度与得分的相关性；加长度惩罚或归一化 |
| ↑ | 快塌 | 稳 | 归零（全对） | 奖励饱和 + 探索枯竭 | 升难度、换任务池，重置探索 |
| 平 | 平 | 稳 | 归零（全对） | 任务太容易，没有信号 | 升难度 |
| 平 | 平 | 稳 | 归零（全错） | 能力种子不足（开场团队丙） | 回 SFT / 降难度，暂停 RL |
| ↑ | 缓降 | 稳 | 正常 | 独立评测持平 → 投机嫌疑 | 抽查高分组样本；对抗审计验证器 |

最后一行是联读的灵魂：**训练侧四条曲线全部"健康"，独立评测却不动——这个组合本身就是最重要的报警信号。**它与 T07 的过优化镜像同构：那里是 RM 分数涨而人工盲评不涨，这里是 Verifier 分数涨而独立评测不涨。训练奖励永远不该单独充当验收证据。

### 3. 案例拆解：GLM-5 的顺序 RL 与能力遗忘的官方修复

多阶段 RL 的能力遗忘，2026 年有一次官方级的公开披露。[GLM-5 技术报告](https://arxiv.org/abs/2602.15763)（2026-02）披露其后训练采用顺序 RL（GLM-5 对自家三阶段安排的称呼，不是业界标准术语）：SFT 之后依次跑 Reasoning RL → Agentic RL → General RL 三个阶段；报告明确承认，多阶段顺序 RL 会侵蚀先前阶段的技能——后一段的训练分布挤占前一段的行为，前一阶段辛苦学来的能力在后续阶段回退。官方的修复是在流水线末尾加一段 on-policy cross-stage distillation（跨阶段在线策略蒸馏），用蒸馏段把被侵蚀的早期能力补回来（官方报告口径；蒸馏机制本身在 T06）。

这张配方表对健康面板的教益有三条：

- **能力遗忘不体现在训练奖励上**——每个阶段训练自己的任务池，奖励都很好看；它体现在跨阶段回归评测上。没有回归集，遗忘不可见；
- **"再训一段修复"是真实存在的工程手段**，但它是官方承认的代价，不是免费午餐——顺序 RL 的账单里必须计入修复段的采样与训练成本；
- 多任务混合是另一条可见路线：[Kimi K3.1 Pro 官方博客](https://www.kimi.ai/blog/kimi-k3-1-pro)称其在数百个任务上做大规模联合 RL（large-scale joint RL across hundreds of tasks，官方口径）——联合训练让任务间互相牵制，遗忘压力换成了奖励设计与任务配比的复杂度。两条路线的完整对比属于第 9 章与第 11 章。

把第一条教益落成工具，就是一张**跨阶段回归矩阵**（教学示意，数字为编造）：

| 能力维度 | SFT 后 | Reasoning RL 后 | Agentic RL 后 | General RL + 蒸馏后 |
|---|---:|---:|---:|---:|
| 数学推理 | 62 | 71 | 66 ↓ | 70 |
| 代码 | 58 | 60 | 74 | 73 |
| 指令遵循 | 81 | 78 ↓ | 75 ↓ | 80 |
| 通用问答 | 70 | 69 | 66 ↓ | 71 |

矩阵的用法：每一行是一个"不允许无声回退"的能力维度，每一列是一个阶段边界；箭头标出回退处，超出阈值的格子就是修复段（如 GLM-5 的跨阶段蒸馏）要瞄准的靶子。没有这张矩阵的团队，要等到产品层面"模型怎么变笨了"的反馈，才发现第 2 阶段就把能力训丢了。

> **判断边界：**四条曲线联读也只能给出"嫌疑"，不能给出"定罪"。奖励涨而独立评测不涨，可能是投机、可能是过拟合任务池、也可能是评测集不敏感——最终裁定靠抽样人工审查与对照实验，不是再多画一条曲线。

## 七、实验归因与停止条件：证明收益是真的

最后一个问题是全章的收口：训练结束后（或者进行中），怎样证明收益是真实泛化，而不是任务池记忆或验证器投机？

### 1. 归因的基本盘：三版对照 + 两种预算口径

| 对照 | 回答的问题 |
|---|---|
| Base（未后训练） | 能力有多少是基座本来就有的？ |
| Base + SFT | 示范段贡献了多少？（T06 的方法在此复用） |
| Base + SFT + RL | RL 段的边际贡献是多少？ |

比较时必须声明预算口径，这是 T02 的 T² 逻辑在 RLVR 的延伸：

- **固定采样预算**：每题同样 k 次采样下比正确率——回答"同等采样成本谁强"；
- **固定计算预算**：把 RLVR 让回答变长的额外生成成本也算进去——回答"同等总算力谁划算"。

一个模型可能 maj@1 赢而大 k 的 pass@k 输：它把算力花在"把会的题做稳"。这是部署优化，不是能力扩展——两种收益都是真的，但必须分开命名，混在一个数字里就都无法归因。

还有第三个容易被漏掉的变量：任务配比。如果 RL 版顺带改了任务池里的题型混合，任何单一口径的对比都不再是纯能力对比——任务配比是第②层的变量，对照实验必须把它锁死。

### 2. 评测纪律

- **任务池与验收集分离**：训练用的题不能进验收集；同源题要去重、做变体（抗污染的完整方法在第 10 章）；
- **双指标**：maj@k 与 pass@k 都测，标注 k、温度与数据集版本；
- **分布外任务**：留一批与训练任务不同构的题，检验泛化而非记忆；
- **重复运行**：RL 训练的随机性不小，关键结论要多次运行看方差，单次运行的分数差不足以决策；
- **回归集**：非目标能力（通用问答、安全行为、指令遵循）不回退——第 10 章的门禁在此预演。

### 3. 归因的三个常见坑

- **坑一：对照的起点不同**。拿"SFT 版的旧分数"比"RL 版的新分数"，中间隔着数据更新、提示模板更换与评测集改版——变量没锁住，差值不可归因。**纠正**：所有版本用同一套冻结的评测资产重跑一遍；
- **坑二：评测口径漂移**。月初测 maj@8（温度 0.7），月末测 maj@8（温度 1.0）——温度是 pass@k 与 maj@k 的共同自由度，口径一变，涨跌都可能是测量噪声。**纠正**：口径写进评测配置文件并版本化；
- **坑三：挑最好的种子汇报**。RL 训练跑三个随机种子，只汇报最好的那一个。单次最好值是选择效应，不是期望水平。**纠正**：汇报均值与方差，或直接按最差种子做决策。

### 4. 两个 2026 年的"同底座"对照锚点

归因最强的证据形态，是基座变量被天然固定的对照：

- **GLM-5.3 vs GLM-5.2**：[官方博客](https://z.ai/blog/glm-5.3)与模型卡称两者使用同一个 base model（744B 总参 / 40B 激活，官方口径），仅重写后训练流水线，Terminal-Bench 3.0 从 4.6 提到 28.3（官方模型卡报告值，同一基准版本内比较；TB3.0 与 TB2.0、TB4.0 不可跨版本比较）。它说明后训练可能带来量级变化——但同时必须限定：这是综合性 agentic 指标，不能推出每项能力同幅度提升，更不能反推提升全部来自某一个 RL 阶段；
- **Kimi K3.1 Pro vs K3**：复用 K3 底座（2.8T 总参 MoE）、把算力大幅加注后训练（数百任务联合 RL，官方口径）。与 GLM-5.3 互证了"底座不动、纯后训练刷新旗舰"在 2026 年是可重复的工程路线。

两个锚点共同服务于本章的归因框架：**底座固定时，变化只能来自后训练——这正是对照组要人造的条件，它们天然就有。**

### 5. 停止判据一页表

| 观察（联读后） | 判读 | 动作 |
|---|---|---|
| 奖励平 + 方差趋零（全对） | 奖励饱和 | 升难度、扩任务池 |
| 奖励平 + 方差趋零（全错） | 种子不足 | 回 SFT / 降难度 / 换任务 |
| 奖励涨 + 独立评测平 | 投机嫌疑 | 抽查 + 对抗审计验证器，修奖励 |
| 熵快速塌缩 + 多样性下降 | 探索枯竭 | 调 KL、温度、任务混合 |
| 回归集显著回退 | 能力遗忘 | 回放数据、混合训练、降学习率，或蒸馏修复（GLM-5 路线） |
| 双指标涨且回归稳 | 有效 | 可继续；考虑扩任务或进下一阶段 |

### 6. 归因报告的最小模板

| 字段 | 示例（示意） |
|---|---|
| 对照版本 | Base @ckpt-1200 / +SFT v3 / +RL v3-step8k |
| 评测资产 | 验收集 v2（与训练池题面去重）、回归集 v1，均冻结 |
| 口径 | maj@8，温度 0.7，与训练采样设置一致；pass@32 附测 |
| 结果 | 目标集 0.61 → 0.74；pass@32 0.79 → 0.81；回归集 −0.4%（阈值 2% 以内） |
| 抽查 | 高分组 50 条人工审查：2 条投机嫌疑，已定位验证器缺陷 |
| 结论 | 晋级；验证器缺陷转问题单，下一轮修复后复测 |

它的作用与 T02 的预测台账相同：不是填表仪式，而是让每一次晋级决定可复盘——三个月后回看时，"当时凭什么放行"必须能从这张表里读出来。

> **架构智慧：**RLVR 的验收证据组至少五件：目标指标涨、pass@k 口径也测、独立评测不背离、回归集不回退、抽样无投机。少一件，收益就只是"训练目标自己变好了"——那不叫能力，叫自我满足。

## 八、工程产物：RLVR Training Plan

把全章收进一张可复用的计划表。它对应引言 Training ADR 骨架的第 3、4、8、9 段（学习信号与信用分配、候选方案假设、验证与门禁、退出条件），每项都必须标口径：

**输入项：**

| 字段 | 示例值 | 口径来源 |
|---|---|---|
| 任务定义 | 数学计算 + 代码小题混合；按基座通过率分难度层 | 假设场景 |
| 任务来源与泄漏检查 | 内部题库 + 合成变体；与验收集做题面级去重 | 假设场景 |
| 验证器 | 数值比对 + 单元测试双通道；误判率抽检每日 1% 样本 | 设计值 |
| 奖励函数 | 结果 0/1；格式违例 −0.1；无过程奖励（v1） | 设计值 |
| 采样策略 | 组大小 G = 16；温度 1.0；最大长度 4K Token | 设计值 |
| 算法与 KL | GRPO 系组式优化；KL 系数初值 0.04，按熵曲线回调 | 设计值 |
| 健康面板 | 奖励 / 熵 / 响应长度 / 组内方差，每 N 步快照 + 报警阈值 | 设计值 |
| 对照实验 | Base / SFT / RL 三版；固定采样与固定计算双口径；独立验收集 + 回归集 | 设计值 |

**输出项：**

| 输出 | 判据 |
|---|---|
| 继续 / 停止 / 修奖励 | 停止判据表（第 7 节），触发即执行，不现场辩论 |
| 晋级 | 证据组五件套齐（目标、双指标、独立评测、回归、抽查） |
| 回滚条件 | 熵塌缩、回归回退、投机实锤，任一触发即回滚到上一 Checkpoint |

这张表的两个纪律：**停止条件在开算力之前写好**——训练进行到一半时，没有人能客观地决定"再烧三天试试"；**验证器字段与奖励函数字段分开**——第 2 节的全部内容就在提醒，这两者会悄悄不再重合。

### 开训前检查清单

- [ ] 验证器四问（覆盖率、误判率、验证成本、抗投机性）有书面答案；
- [ ] 验证器已版本化，误判率监控在面板上可见；
- [ ] 基座种子检测完成，任务池按通过率分好了难度桶；
- [ ] 独立验收集与训练任务池完成题面级去重；
- [ ] Base / SFT / RL 三版对照与双预算口径写进实验计划；
- [ ] 四曲线面板与报警阈值配置完毕；
- [ ] 停止判据与回滚条件已过评审——在开算力之前。

> **架构智慧：**RLVR Training Plan 的价值不在计划文档本身，而在那些开算力之前就被迫写下的答案：验证器四问、种子检测、停止判据。训练开始之后，所有没写下来的判断，都会被"再跑一会儿看看"悄悄替代。

## 九、六种最常见的错误判断

### 错误 1："有标准答案"就等于"奖励可验证"

标准答案是必要条件，不是充分条件。覆盖率、误判率、抗投机性三问没有做完之前，验证器只是"一段还没被攻击过的代码"。**纠正动作**：上线前做对抗审计，把验证器的投机面当攻击面清单来管理。

### 错误 2：只看奖励曲线就宣布训练健康

奖励是训练目标自己的分数，它涨只证明优化器在工作。团队乙的单元测试骗局里，奖励曲线是全场最好看的一条。**纠正动作**：四曲线联读 + 独立评测 + 高分组人工抽查，三件缺一不可。

### 错误 3：把边界之争当成已有定论

无论方向——"RLVR 只是锐化"或"RLVR 扩展了边界"——目前都拿不出足够广的证据。单点的 pass@k 比较还受 inversion 与温度敏感的方法学批评。**纠正动作**：双指标、标口径、按部署口径选主指标，把"边界是否扩展"写成待验证假设。

### 错误 4：基座没有能力种子也硬上 RL

组内全错没有梯度，采样账单照付。RL 是放大器，放大的是"偶发的正确"。**纠正动作**：训练前先做基座多采样测试，把任务配到"有对有错"的边缘区间；全错的批次退回 SFT 或降难度。

### 错误 5：抄算法结论，不抄算法前提

看到 GLM-5.2 转 Critic-based PPO 就跟进，却没有长程、变长、经 Compaction 的轨迹形态；或反过来宣布"PPO 取代 GRPO"。前提是被任务形态决定的使用条件：GLM-5 与 GLM-5.2 用不同算法，是因为任务形态不同。**纠正动作**：重走一遍"任务形态 → 数据形态 → 方法假设 → 系统拓扑"的因果链，确认约束同构再复用。

### 错误 6：拿训练任务池当验收集

训练分布上涨是优化的定义，不是泛化的证据。任务池与验收集同源，等于让学生给自己出考卷。**纠正动作**：题面级去重 + 独立验收集 + 分布外任务 + 重复运行，四件套写进计划表。

读完六个错误可以看出规律：它们没有一个是"算法用错了"，全是"前提没问就开了算力"——奖励的前提、监控的前提、指标的前提、种子的前提、算法的前提、验收的前提。RLVR 的工程难度不在算法本身，而在把这几道关口一一过掉；这正是本章把"前提"放进章名的原因。

## 本章小结

- **"有标准答案"只是入场券**：RLVR 的前提是奖励可靠且难以投机（覆盖率、误判率、抗投机性三问）、基座具备能力种子（组内有对有错）。
- **规则正确 ≠ 奖励完整**：验证器是攻击面，面对的是被明确激励钻空子的对手；投机检查要进训练监控，不能只在上线前做一次。
- **RL 放大能力，不无中生有**：组内全错没有梯度；任务配到"有对有错"的边缘区间，是采样预算的第一杠杆。
- **pass@k 与 maj@k 双指标**：前者是能力边界的上限视角，后者是部署视角；"锐化还是扩边界"尚无定论，指标选择按部署口径先行。
- **算法选择 = 基线方案选择**：PPO 用 Critic（模型账单），GRPO 用组均值（采样账单）；前提由任务形态决定——GLM-5 与 GLM-5.2 分道，是任务形态不同，不是段位不同。
- **四曲线联读 + 独立评测**：奖励、熵、长度、组内方差单看都会骗人；奖励涨而独立评测平，是最重要的报警组合。
- **能力遗忘是真实代价**：GLM-5 官方披露顺序 RL 侵蚀前段技能、需要末段蒸馏修复——多阶段配方的账单必须计入修复段。
- **归因靠对照，不靠分数**：Base / SFT / RL 三版对照、双预算口径、独立验收集、分布外任务、重复运行；同底座纯后训练（GLM-5.3、K3.1 Pro）是 2026 年可见的最强归因锚点。
- **归因报告让晋级可复盘**：对照版本、冻结评测资产、双指标口径、抽查结论落成一张表——"当时凭什么放行"必须随时读得出来。
- **工程产物是 RLVR Training Plan**：停止条件在开算力之前写好，验证器字段与奖励函数字段永远分开检查。

> **下一章的问题：**RLVR 常有明确的答案或验证器;真实 Agent 任务却可能包含几十步工具调用、状态变化和长程目标。下一章把学习环境本身作为核心工程对象。

## 基础术语速查

本章新引入或重新定义的词按出现顺序集中在此；引言的通用术语（Policy、Rollout、Reward 等）不再重复。

| 术语 | 初学者可以先怎样理解 |
|---|---|
| RLVR | 用规则、标准答案、单元测试或程序验证器当奖励来源的强化学习；"更好"由程序判定，不由人或打分模型判定 |
| Verifier | 判定结果对错的程序（数值比对、测试、编译、schema、环境状态）；打分可精确复现 |
| Reward Model | 学出来的打分模型，把"哪个更好"变成标量分数；与 Verifier 的区别：一个学偏好，一个执行规则（T07 主场） |
| Rollout 组 | 同一道题并行采样出的一组可比回答；GRPO 的基线与学习信号都来自组内 |
| 组内方差 | 组内得分的差异；全对或全错（方差为零）的组没有学习信号 |
| pass@k | 同题独立采样 k 次，只要一次正确即记成功；"能不能做出来"的上限视角 |
| maj@k | 采样 k 次对答案做多数投票，多数正确才记成功；接近"一次调用加投票"的部署视角 |
| 策略熵（Entropy） | 模型输出分布的分散程度；越平越有探索性，越尖越在重复少数做法 |
| Value / Critic | 从当前状态继续走下去的预期回报；Critic 是学习它的辅助模型 |
| Advantage | 实际得分减预期基线，决定一条轨迹被加强还是抑制 |
| KL 控制 | 用冻结 Reference 的 KL 距离约束 Policy 不要漂太远的缰绳 |
| 奖励投机（Reward Hacking） | 模型找到奖励规则的漏洞拿分而不是完成任务；正式定义与检测通道在 T10 |
