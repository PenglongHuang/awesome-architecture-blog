## 开场：模型会背答案，却不会解决新问题

先看一个工程现场（教学合成场景，数字为示意；但现象不是合成的——本章第五、六节的 2026 案例会给出它的真实版本）。

一个团队从预训练主线（T02--T05）的产物里接过刚下线的 Base Model，目标很简单：让它变成一个能干活的助手。做法也是行业最熟悉的那种：

- 数据组花六周标注 **5 万条「指令 -- 回答」示范**，人工质检后做 SFT，训两个 epoch；
- 演示日一切顺利：模型遵循指令、分点作答、语气得体、拒绝有害请求——格式、风格、结构全对；
- 两周后业务接入两类新任务（长文档抽取、多轮澄清问答），模型开始"照着格式胡说"：结构漂亮，内容错得稳定；
- 复盘评测：与训练示范**同分布**的题目通过率 82%，**换一批新题型**只有 41%；
- 应激反应是堆数据——示范扩到 25 万条（同一批标注规范、同一类任务形态）再训一轮，新题型通过率 41% → 44%。

| 评测口径 | 5 万条示范 | 25 万条示范 | 变化意味着什么 |
|---|---:|---:|---|
| 同分布题型（与示范同类） | 82% | 88% | 还在涨：格式与任务模式确实可以堆出来 |
| 新题型（分布外） | 41% | 44% | 几乎不动：这 20 万条买不到分布外的能力 |

同一个模型、同一个训练方法，两张成绩单讲的是两件事。第一张叫**训练集拟合**——模型学会了"这类题该长什么样"；第二张才叫**能力迁移**——模型把示范里的解法用到了没见过的任务上。堆量只买到前者。这不是标注团队的失败，而是示范这种信号本身的性质：**示范告诉模型"正确长什么样"，却不告诉它"为什么这样对"，更不告诉它"走错之后怎么回来"。**

> 预训练得到的是基础能力。要让模型按照指定方式回答、推理和执行任务,需要选择合适的学习信号。先从示范学习开始。

这是上一章章末留下的问题。本章把"从示范学习开始"拆开：SFT 到底在教什么（第一节）、该往参数里写多深（第二节）、把别的模型的示范搬过来叫蒸馏，搬的是什么（第三节）、数据来自谁的分布为什么是分水岭（第四节）、多阶段训练为什么会让前面教的又丢掉（第五节）、以及怎么证明这一切值得（第六节）。

> **本章只解决一件事：如何选择 SFT、参数高效微调、全参数微调和蒸馏，并判断它们能否带来可迁移能力？**

在引言的学习信号光谱表里，本章占据的是第一行：

| 光谱级行 | 最小训练数据 | 需要在线 Rollout | "更好"由谁定义 | 典型代价 |

| **示范**（SFT / 蒸馏，T06） | Prompt＋示范答案 | 否（OPD 例外，第四节） | 写示范的人 | 上限受示范质量与覆盖约束 |

后三行（偏好、可验证奖励、环境奖励）分别在 T07--T09 展开。本章反复出现的判断句式——"这件事示范教得会吗"——就是在问：目标能力是否落在第一行的典型代价之内。

一个口径先钉住：**示范数据有两种计数方式**——"条"（样本数，一问一答算一条）与"Token"（示范回答的实际长度总量）。5 万条平均 800 Token 的示范，约 4 千万 Token；本章第三节 Inkling 2 Small 的 H4 阶段约 34B Token 轨迹，如果同样按 800 Token 一条折算，相当于 4,000 万条以上的量级（折算仅为建立直觉，两者数据形态完全不同）。两种口径换算着看，才不会被"5 万条"和"34B Token"哪个大的问题绊住。

## 一、SFT 的学习机制：模型在示范里学什么

### 1. 损失在算什么：只对示范回答部分的每个 Token 训练

**SFT（Supervised Fine-Tuning，监督微调）**可以先理解成：拿"Prompt＋示范答案"这种成对数据，在 Base Model 上继续训练。它的学习目标在机制上极其朴素——还是预测下一个 Token，但只对**示范回答部分**的 Token 计算损失：

```text
[Prompt 部分]   请把这段合同的关键条款整理成表格……
                 ↑ 这些 Token 不计损失(模型不必学"用户会说什么")
[回答部分]      好的,以下按条款编号整理:| 1 | 租金 | …
                 ↑ 逐 Token 计算损失:让示范里每个下一步的概率变高
                 ↑ 优化目标 = 示范回答上全部 Token 损失的平均
```

这就是**Token 级损失（Token-level Loss）**：SFT 不存在"这道题答对了"这样的题目级信号，只有"这一步更像示范了"的逐步信号。把一条示范拆开看（教学示意）：

```text
一条示范:Prompt 200 Token + 回答 300 Token
训练时:只有回答的 300 个位置各产生一个损失
       每个位置的问题都是"看见了同样上文,下一步该给什么"
最终更新方向 = 300 个位置损失的平均对参数求梯度
含义:示范里每个"下一步"都平等地投票决定参数往哪走——
     模型学到的是"这 300 步的顺序与内容",不是"这道题对了没有"
```

这个视角直接解释了开场场景——模型能精确学会"先说'好的'、再给表格、再收尾"的模式，因为每一步都有示范可模仿；但"怎么从一堆合同里准确抽出条款"如果基座不会，示范只展示了结果，没有展示过程。

再看训练时的一个细节：**Teacher Forcing（教师强制）**——训练中每一步预测都以"示范的正确上文"为条件，模型从来没有在"自己写错了上一步"的情境里被训练过。它没学过如何从错误恢复，因为示范里不出现错误。这不是 SFT 的 bug，而是示范信号的边界：**示范是成功案例的集合，不是纠错过程的集合。**

### 2. 数据量与轮次：为什么"再训一轮"经常是反向操作

示范数据通常不大（相对预训练），于是一个实际的诱惑是反复多跑几个 epoch。示意一下会发生什么（曲线为教学示意，非任何真实实验）：

```text
验证集损失
 │＼
 │  ＼                    ___———

 │     ＼＿          ———

 │         ＼＿＿—— ← epoch 1 末:接近最优

 │                  ＼＿＿＿
 │                          ＼＿＿＿＿ ← epoch 3+:训练损失还在降,
 └──────────────────────────────→ 训练 epoch     验证损失开始回升
     训练损失单调下降;验证损失先降后升
```

**训练损失下降、验证损失回升**，就是示范从"教会模式"变成"背诵样本"的信号：模型开始记住这 5 万条本身，而不是泛化它们背后的解法。所以 SFT 的实用纪律与 T03 的数据消融一脉相承：**加数据的优先级永远高于加 epoch**；验证集必须与示范分布有差异，否则这条曲线根本测不出来（开场场景的同分布评测集就测不出过拟合）。

### 3. 示范数据的四个变量

同样的"5 万条"，质量不同结果完全不同。T03 讲过的数据方法论（质量评分、消融、固定预算对照）在这里全部适用，SFT 侧再加四个专项变量：

| 变量 | 它决定什么 | 常见的坑 |
|---|---|---|
| 质量 | 每 Token 搬进参数的东西有多干净 | 一条格式完美但事实错误的示范，是负资产 |
| 覆盖 | 哪些任务形态在示范里出现过 | 没覆盖的形态，模型只能靠基座泛化硬撑 |
| 难度 | 示范解法与基座能力的距离 | 难度远超基座的示范，学出来是背诵而不是解法 |
| 多样性 | 同一任务形态下表述与路径的方差 | 单一风格的示范会把模型收窄成一种腔调 |

开场场景里 20 万条数据买不到分布外能力，问题就出在覆盖与难度：新增数据与原有数据同形态、同难度，扩大的是"已知岛屿的面积"，不是"海岸线的长度"。

### 4. SFT 教得会什么：一张诚实的清单

把"1,000 条示范就能对齐"和"SFT 只能教格式"两种流行说法都放到证据前，清单是这样的：

| SFT 能稳定教会 | 依赖条件 | SFT 常教不会 |
|---|---|---|
| 输出格式、风格、结构 | 少量高质量示范即可 | 基座完全没有的知识与技能 |
| 任务模式（"这类题这么做"） | 示范覆盖到位 | 覆盖外的任务形态迁移 |
| 行为边界（拒绝、澄清、引用） | 示范里要有正反例 | 超越示范质量的判断力 |
| 一部分知识与技能 | 基座有种子、示范给路径 | 从错误中恢复、自我纠错 |

两个历史锚点把这张清单的两端钉住了。

**左端（教会格式可以非常便宜）**：[LIMA](https://arxiv.org/abs/2305.11206)（Zhou 等，2023，方法起源/历史锚点）用 **1,000 条**精选示范对 65B 基座做 SFT，得到的模型在相当比例的人评对话上可与当时的强指令模型相提并论。作者由此提出"表面对齐"假说：模型的能力与知识几乎全部来自预训练，对齐阶段主要教会的是用户偏好的交互形式。1,000 这个数字意味着：对齐一个已经很强的基座，示范的"质"与"选法"可以远比"量"重要。

**右端（能力别指望示范堆出来）**：InstructGPT（2022，方法起源/历史锚点，[论文](https://arxiv.org/abs/2203.02155)）的流程从方法起源上就把 SFT 定位为第一步——人类示范 SFT 在前，Reward Model 与 PPO 在后；它从来没有把"能力上限"寄托在示范阶段。

### 5. 2026 年的叙事走向：SFT 是 off-policy 模仿阶段

把上述机制放进 2026 年的实践语境，能看到一条清晰但**尚未盖棺**的叙事走向：**SFT 被定位为 off-policy（离线/模仿）阶段——教格式与模式；能力提升主要来自 RL 阶段。**这个叙事的载体包括两篇 2026 年的实践文章（《Why off-policy training isn't enough: SFT, RL, and the limits of distillation》，2026-03-25；《On-policy distillation, part 1: the 2026 open-model post-training》，2026-07-08；均为实践者文章而非同行评审论文，标题与日期来自本专题证据库），也与 [GLM-5 技术报告](https://arxiv.org/abs/2602.15763)的编排一致——SFT 放流水线最前端打底，三个 RL 阶段跟在后面出能力。

但把它写成纪律之前，必须加三重限定：

- "SFT 只能教格式"是对叙事的过度压缩——上表左列是 SFT 稳定能教会的，收益取决于数据、模型与训练设置；
- "能力提升主要来自 RL"在多数公开报告里缺乏同预算的纯 SFT 对照，属于经验判断而非受控结论；
- 该走向描述的是旗舰与头部开源模型的实践，小模型与垂域场景未必同构。

> **判断边界：**叙事可以指导你从哪里开始怀疑，但不能代替你自己的对照实验。"SFT 教格式、RL 出能力"是一个值得当作先验的走向，不是一个可以跳过验证的结论。你的模型、你的数据、你的任务，需要你自己的消融来裁决。

## 二、写入深度：LoRA / PEFT 与全参数微调

### 1. 同一批示范，三种写法

决定做 SFT 之后，第一个系统决策是**写入深度**：让多少参数动起来。三种典型范围：

```text
全参数微调(Full FT):   W ← W + ΔW,所有参数都更新
头层/适配层微调:        只动输出层或新增小模块(参数量常 <1%)
LoRA(低秩适配):         W 冻结,旁边加低秩旁路 ΔW = B·A
                        可训练参数 ≈ r × (d_in + d_out),
                        r=8/16 时通常不足全参的 1%
```

**LoRA（Low-Rank Adaptation）**与同属 **PEFT（Parameter-Efficient Fine-Tuning，参数高效微调）**家族的方法，直觉是：微调带来的权重变化量本身是低秩的——不需要动全部参数，就能表达"这次适配"的方向。可训练参数少了，优化器状态随之等比例缩小，这就是它省显存的机制来源。

### 2. 一笔可以复算的显存账（教学示意）

为什么优化器状态是关键变量？以 AdamW 训练为例（数值为教学示意，机制是真实的；完整四本显存账在 T05）：

```text
假设 7B Dense 模型,BF16 参数 + FP32 优化器状态

全参数微调:
  参数 7B × 2 字节          = 14 GB
  梯度 7B × 2 字节          = 14 GB
  优化器状态 7B × 8 字节    = 56 GB   ← 一动:每个可训练参数背两份
  (动量与方差,各 4 字节)              FP32 状态
  合计仅"参数+梯度+状态"    ≈ 84 GB,还没算激活值

LoRA(r=16,仅旁路可训练,可训练参数设为 0.5%):
  参数 7B × 2 字节          = 14 GB(冻结,可共享同一基座)
  梯度+状态:只按 35M 可训练参数计 ≈ 0.35 GB
  增量部分小两个数量级
```

**它意味着什么**：全参与 LoRA 的差距不是"快一点"，而是"要不要为每个任务复制一整套训练状态"。这也是第二节末尾"多租户插拔"服务形态的物理基础——一个冻结基座常驻显存，多个几十 MB 级的适配器按请求切换。

```text
服务形态对比(示意):
全参微调产物:  [模型A] [模型B] [模型C]   每个都是完整权重,各自部署
LoRA 产物:     [冻结基座] + {适配器A | 适配器B | 适配器C}
               基座常驻,适配器按请求热切换——显存与运维的量级差异
```

### 3. 两本账的对比

| 账项 | LoRA / PEFT | 全参数微调 |
|---|---|---|
| 可训练参数 | 不足全参的 1%（典型配置） | 100% |
| 优化器状态显存 | 只覆盖旁路参数 | 覆盖全部参数（见上方示意账） |
| 目标域学习上限 | 受低秩增量表达力约束 | 上限最高 |
| 对基座的扰动 | 基座冻结，扰动被限制在旁路 | 全参数都可能漂移 |
| 遗忘风险 | 较低 | 较高 |
| 工程形态 | 适配器可插拔、可热切换、可多租户 | 每个版本都是完整权重的 checkpoint |

这张表里最容易被误读的一行是"上限"。LoRA 的低秩不是免费的午餐：[《LoRA Learns Less and Forgets Less》](https://arxiv.org/abs/2405.09673)（Biderman 等，2024，预印本）在代码与数学任务上系统对比了两种写法，结论刻在标题里——**LoRA 在目标域学得比全参少，但对源域能力的遗忘也比全参少**。两个"更少"是一对连体结论，不是矛盾，也不能只引用一半：拿它证明"LoRA 更安全"和拿它证明"全参更强"都对了一半，完整的工程含义是——**写入深度是在"学多少新东西"和"忘多少旧东西"之间选点，不是在"省钱和不省钱"之间选点。**

### 4. 怎么选：从目标能力与回归评测出发

| 判断输入 | 倾向 LoRA / PEFT | 倾向全参数 |
|---|---|---|
| 目标能力的性质 | 新格式、新行为、新语气——基座知识已够用 | 注入大量新知识/新技能，超出低秩增量的表达范围 |
| 基座保护要求 | 多租户共享一个基座，按任务插拔适配器 | 接受通用能力回退，且有回归评测兜底 |
| 显存预算 | 只想为旁路参数背优化器状态 | 扛得住全参优化器状态（先回 T05 算显存账） |
| 迭代节奏 | 适配器版本化、秒级回滚 | 每个版本是完整权重，存储与分发成本高 |

注意这张表没有"规模小就选 LoRA"这种规则——决定写入深度的是**目标能力与不可回退清单**，不是参数量本身。一个 7B 模型要吃进一个新领域的知识库，全参仍可能是对的选择；一个 300B 模型只是换个回复格式，LoRA 足矣。

> **架构智慧：**LoRA 不是"预算打八折的全参微调"，而是另一种取舍：用目标域的学习上限，换基座的稳定性与工程灵活性。评审"用不用 LoRA"的正确问法不是"哪个便宜"，而是"这次要写进去的东西，低秩增量装得下吗；写深了之后，哪些能力不许跟着动"。

## 三、蒸馏：把 Teacher 的什么搬给 Student

### 1. 三种搬运对象

示范不一定要人类来写。**蒸馏（Distillation）**指让一个模型（Teacher，教师）向另一个模型（Student，学生）输出学习信号。按"搬什么"分三种：

| 类型 | 搬运对象 | 数据形态 | 前提条件 |
|---|---|---|---|
| Logit 蒸馏 | Teacher 在每个位置的概率分布（软标签） | 需要 Student 训练时访问 Teacher 的 logits | 通常要求同词表或可对齐，Teacher 常驻在线 |
| Response 蒸馏 | Teacher 生成的完整回答 | 回答文本本身，等同"示范数据来自 Teacher" | 只需 Teacher 的输出文本，可离线 |
| Reasoning Trace 蒸馏 | Teacher 的完整推理轨迹（含过程） | 长思维链/步骤序列 | 轨迹质量决定上限，常配正确性过滤 |

Response 与 Trace 蒸馏在训练机制上就是 SFT——区别不在损失函数，而在**示范来自谁的分布**：人类专家写的，还是另一个模型生成的。Logit 蒸馏则更进一步：搬的不是"最终选了哪个词"，而是 Teacher 在每个位置的概率分布（软标签），信息量比单个答案大得多，但工程前提也更重。

软标签为什么值钱？看一个教学示意（数字为编造的直觉示例）：

```text
某个位置,上下文是"三角形的内角和是____"
硬标签(普通 SFT/Response 蒸馏):  答案"180"       → 1 个词的信息
软标签(Logit 蒸馏):
  Teacher 的分布:  "180" 0.82 | "一百八十" 0.09 | "360" 0.02 | …
含义:软标签顺带告诉 Student
  - 哪些表述是同义的("180"与"一百八十"很近)
  - 错误也有远近("360"不是随机错,是相邻的概念混淆)
  - Teacher 对这一步的确定程度(0.82,不是 1.0)
一条轨迹上每个位置都带这样的分布 → 信息密度远高于纯文本
代价:Student 训练的每一步都要实时拿到 Teacher 的 logits
     (离线存全部词表分布,存储量按词表大小×Token 数膨胀)
```

所以三者的工程形态是递进的：Response 蒸馏只需要文本（可以离线、可以囤货），Trace 蒸馏需要长轨迹（离线但过滤成本高），Logit 蒸馏需要在线访问 Teacher 的内部输出（最重、信息最密）。选择搬运对象，本质是选择**为每 Token 的信息量付多少基础设施费**。

### 2. 历史锚点：R1-Distill 把"轨迹蒸馏"变成了标准动作

[DeepSeek-R1 论文](https://arxiv.org/abs/2501.12948)（2025，方法起源/历史锚点）的蒸馏实验是这条路线的标志性节点。论文报告：**把 R1 生成的推理输出蒸馏给小模型（用 R1 采样出的约 80 万条样本做 SFT，学生为 Qwen/Llama 系 1.5B--70B 的 Dense 模型），效果好于在当时配置下直接对这些小模型做 RL**。这组对照（口径：论文实验设置）诞生了开源圈沿用至今的 R1-Distill 系列做法：拿强 Teacher 的轨迹 SFT 小模型。

为什么"Teacher 轨迹＋SFT"能赢过"小模型自己 RL"？机制上的直觉：**推理任务的 RL 要靠探索**——小模型自己采样，很难碰到正确解法，奖励稀疏、学习缓慢；而 Teacher 已经把"搜索的解"固化在轨迹里，蒸馏等于**把 Teacher 付出的搜索成本一次性折现给学生**。这同时暴露了它的成本结构：Teacher 生成 80 万条轨迹的推理算力，就是这场"折现"的价格。

它的教学价值在结论的**边界**上：

- 对照对象是"当时的 RL 配方 + 这些小模型"——结论不能外推为"蒸馏永远优于 RL"，更不能跨规模、跨任务外推；
- 80 万条轨迹意味着蒸馏的账单里有 Teacher 的推理成本（T02 的三本账在这里生效）；
- 轨迹蒸馏买到的能力仍以 Student 容量为上限，Teacher 多强都不能让 1.5B 学会它装不下的东西。

### 3. 2026 案例：Inkling 2 Small 的 H4 阶段

蒸馏在 2026 年的现役形态，可以看 [Inkling 2 Small](https://thinkingmachines.ai/news/inkling-2-small) 的官方披露（口径均为官方页面）：H4 阶段用**约 34B Token 的最高质量轨迹**训练，轨迹**主要采样自 Kimi K3 及自家早期模型**，经正确性与对齐过滤后入库。

这个案例先纠正一个直觉：**蒸馏不必是"大模型 → 小模型"**。Inkling 2 Small 自己是 594B 总参/17B 激活的 MoE，Teacher 是 2.8T 总参的 Kimi K3——只要学习信号来自另一个模型的分布，就是蒸馏。它展示的现役纪律有三条：

- Teacher 生成的轨迹**逐条过正确性与对齐过滤**——Teacher 会出错，照单全收会把错误一起搬进来；
- 轨迹是**推理算力换来的资产**（H3＋H4 合计约 354B Token 轨迹，均为官方披露口径），蒸馏预算要含 Teacher 的采样账；
- 蒸馏只是这条流水线的一段（H1/H2 预训练 → H3/H4 轨迹训练 → RL），不是替代其他阶段的银弹。

### 4. Teacher 选择清单

| 检查项 | 问题 | 不合格的样子 |
|---|---|---|
| 能力对口 | Teacher 在目标能力上经独立评测强于 Student 底座 | 只看 Teacher 名气，目标能力恰好是它的弱项 |
| 错误率 | 生成错误能被过滤管线接住吗 | Teacher 错误率高于过滤预算 |
| 口径一致 | 词表/格式/工具协议与 Student 兼容或可映射 | 轨迹里满是 Student 学不了的私有格式 |
| 许可与条款 | 输出用作训练数据的授权是否明确 | 用竞品 API 输出蒸馏，条款不清 |
| 稳定性 | Teacher 版本会被升级打断吗 | 蒸馏到一半 Teacher 换代，前后数据不同质 |

### 5. 四种失败模式

| 失败模式 | 现象 | 根因 |
|---|---|---|
| 口径背诵 | Student 学会了 Teacher 的表述习惯与结构，解法没学到 | 示范只有结果，过程超出 Student 理解或示范覆盖 |
| 错误迁移 | Teacher 错的地方 Student 跟着错 | 没有正确性过滤，或过滤标准与目标能力错位 |
| Teacher 偏差搬运 | Teacher 的风格、倾向、格式癖好被当成"知识"学走 | 软标签/轨迹里风格与能力混在一起，无法分开 |
| 容量上限 | 加数据也不涨了 | Student 参数量与结构装不下目标能力 |

### 6. 对照原则：蒸馏必须赢过"同预算直接训练"

判断蒸馏是否值得，基准**不是**"Student 比它自己过去强"——那几乎必然成立，因为没有对照。诚实的归因至少要两组对照：

```text
对照组 A:同预算直接训练
  同样的算力/数据预算,不用 Teacher,
  直接在 Student 底座上继续训练(继续预训练 + SFT/RL)
  → 蒸馏赢,才证明"Teacher 的信号"本身有价值

对照组 B:推理成本对照
  蒸馏出的 Student vs 直接部署 Teacher
  → Student 只有在"能力够用的任务区间"里更便宜,才值得存在
```

R1 论文的结论之所以有分量，正因为它做了 A 类对照（蒸馏 vs 直接 RL）；开场的 5 万条示范之所以没有说服力，因为 25 万条那轮连"同分布堆量有没有用"都没分开验证。对照组 B 则把 T02 的推理摊销账带进来：Teacher 生成 34B Token 轨迹的采样成本，分摊到 Student 的整个生命周期是否划算，是产品决策，不是训练决策。

把第三节到这里的判断合并成一棵决策树：

```text
要迁移的能力,基座/Student 自己够得着吗?
 ├─ 够得着 → 格式与模式类:直接 SFT(人写或合成示范)
 └─ 够不着 → 别人的模型够得着吗?
      ├─ 够不着 → 蒸馏无用:能力超出可获得信号的上限(容量/许可/成本)
      └─ 够得着 → 用它的什么?
           ├─ 只要结果(回答) → Response 蒸馏 + 正确性过滤
           ├─ 要过程(推理)   → Trace 蒸馏(注意 Student 容量上限)
           └─ 要逐步对齐分布 → Logit 蒸馏 / OPD(第四节)
```

> **判断边界：**"蒸馏有效"永远是一个带口径的陈述：哪个 Teacher、哪个 Student、什么任务分布、对照是谁、预算怎么固定。去掉口径的"蒸馏比 RL 好"或"RL 比蒸馏好"，都是把一次实验当成了定理。

## 四、On-policy 与 Off-policy 蒸馏：数据来自谁的分布

### 1. 问题从 Student 第一次走偏开始

第三节的所有蒸馏形态共享一个性质：Student 学习时看到的都是 **Teacher 的输出分布**——这叫 **Off-policy 蒸馏（离线蒸馏）**。它有个结构性弱点，与第一节的 Teacher Forcing 同源但更严重：

```text
Off-policy 蒸馏的数据流:
  Prompt → Teacher 生成示范 → 过滤 → 静态数据集 → SFT Student
                                          ↓
                          Student 学的是"Teacher 会怎么做"
                          但 Student 上线后走的每一步,都出自它自己的分布;
                          一旦它的开头与 Teacher 分叉,后面没有任何示范教它回到正轨

On-policy 蒸馏(OPD)的数据流:
  Prompt → Student 自己 Rollout 生成轨迹(在线进行)
                ↓
          Teacher 对 Student 的轨迹逐段/逐 Token 给出信号
          (软标签、逐 Token 损失或序列级偏好)
                ↓
          Student 在"自己的分布"上被修正——错在哪,就在哪学
```

**On-policy（在策略）**的意思不是"对公众开放"，而是**训练数据由当前模型自己生成**——学习信号落在学生实际会走的状态上。这就是 **OPD（On-policy Distillation，在策略蒸馏）**：Teacher 不再提供"标准答案"，而是在 Student 自己的尝试上提供"你这一步应该是什么"的对照。

用一个最小对照感受差别（教学示意）：

```text
任务:多步计算 A → B → C
Student 的典型错误:第一步就选错路径,后面全偏

Off-policy 蒸馏:示范永远是"正确路径 A→B→C",
  Student 错开头的那些状态,训练数据里根本不存在 → 错误状态无人纠正

OPD:Student 走出 A→B'→C''(它自己的真实分布),
  Teacher 在 B'、C'' 这些"学生真会走到的位置"上给出对照信号
  → 纠正发生在学生实际会犯错的地点
```

### 2. 收益、成本、风险

| 维度 | 说明 |
|---|---|
| 收益：修复分布偏移 | Student 在自己会犯错的分布上被纠正，而不是在 Teacher 的完美分布上做题 |
| 收益：暴露真实弱点 | off-policy 数据里 Student 的系统性弱点根本不会出现——它没参与数据生成 |
| 成本：在线基础设施 | 需要 Student 持续 rollout＋Teacher 常驻打分，在线数据管线与同步问题全部出现（T05/T09 的系统账单） |
| 风险：Teacher 偏差照样迁移 | 换了数据来源不等于换了能力来源——Teacher 错，Student 在自己的分布上跟着错 |
| 风险：复杂度高一档 | 采样、过滤、信号回传、版本同步；离线一条批处理脚本的事，在线是一套系统 |

这里要回对一次引言的光谱表：表里"示范"一行标注"不需要在线 Rollout"——那是离线 SFT 与 off-policy 蒸馏的口径。**OPD 是示范信号的在线变体**：信号本身仍是"Teacher 认为的正确"，但数据由 Student 在线生成，于是"需要在线 Rollout"这一列开始从"否"翻向"是"。光谱的分级说的是信号强度，不是方法名的户口。

### 3. 何时值得把蒸馏搬到线上

| 判断输入 | 倾向 off-policy（离线蒸馏/SFT） | 倾向 on-policy（OPD） |
|---|---|---|
| Student 与 Teacher 的分布距离 | 任务形态接近，Student 已能大致复现 | Student 开头就容易走偏、错误形态多 |
| 错误代价 | 离线评测能兜住 | 错误状态需要被显式纠正（如多步任务） |
| 基础设施 | 只有批处理训练栈 | 已有 rollout 管线与 Teacher 常驻服务（或愿意建） |
| 预算 | Teacher 采样一次性付清 | Teacher 持续计费＋rollout 算力持续发生 |

### 4. 三个层级的证据，不许互相冒充

OPD 的讨论里最容易混淆的是三种不同强弱的陈述：

| 层级 | 陈述内容 | 本章对应的证据 |
|---|---|---|
| 论文提出的方法 | 机制、实验设置、适用边界 | OPD 的机制与实验来自研究文献（方法层） |
| 模型报告中的具体实践 | 某模型在自己的流水线里怎么用、报告自述效果 | GLM-5 报告：末段用跨阶段 on-policy 蒸馏修复能力回退（第五节拆解） |
| 行业普及程度 | 多少团队在用、是否"中心技术" | "OPD 成为 2026 开源后训练的中心技术"出自 2026 年实践文章的叙事（本章第一节与第四节引用的两篇），是观察性判断，不是定论 |

三层混写就会出现"GLM-5 用了所以这就是标准做法"式的推理错误——T01 立下的规矩在这里再次生效：**复用推理，不复制答案。**

> **架构智慧：**off-policy 与 on-policy 之分，本质是"数据分布权"归谁。离线方法把分布交给数据生产时点（便宜、可控、会过期），在线方法把分布交给当前模型（新鲜、对症、要养一套系统）。这条权衡线会贯穿 T07（偏好数据过期）、T08（在线 Rollout）、T09（Policy Lag）——在 T06 先把它立起来。

## 五、能力保持与遗忘：多阶段训练的隐藏账单

### 1. 顺序训练的默认结局是回退

后训练很少只训一段。典型的编排是 SFT → 各能力方向的 RL → 安全微调，每一段都在优化自己的目标。问题在于：**参数只有一份**。第 k 段把参数推向目标 A 的最优，第 k＋1 段推向目标 B 的最优时，A 的表现大概率回退——这就是后训练语境下的**灾难性遗忘（Catastrophic Forgetting）**，工程口径叫**能力回退**。

它不是偶发事故，而是多阶段训练的默认结局。区别只在于：有的团队在发布前用能力矩阵发现了它，有的没发现。

### 2. 案例拆解：GLM-5 的顺序 RL 与末段蒸馏修复

[GLM-5 技术报告](https://arxiv.org/abs/2602.15763)（2026-02，官方一手披露）给出的后训练流水线是这条风险线的完整标本。按报告原文，其编排为：

```text
GLM-5 后训练流水线(官方报告口径)
  SFT:扩展 agent/coding 数据,引入三种思考模式
    ↓
  Reasoning RL → Agentic RL → General RL
  (报告称为 sequential RL:对自家三阶段的顺序称呼,非业界标准术语)
    ↓
  末段:on-policy cross-stage distillation(跨阶段在策略蒸馏)
    ↓
  作用:修复顺序 RL 造成的早期阶段能力回退
  (官方明确承认:多阶段顺序 RL 会侵蚀前段技能,蒸馏段负责修复)
```

三个教学点，每个都要带口径：

- **回退被官方承认存在**。这不是外部猜测，是报告自述：顺序推进的 RL 阶段会侵蚀前面阶段已建立的技能。旗舰流水线也逃不掉遗忘，一般团队没有理由假设自己能逃掉。
- **修复是专门花钱做的**。GLM-5 没有指望"训多了自然就好"，而是把一个蒸馏段编进流水线末尾，用（按报告的机制描述）跨阶段的 on-policy 蒸馏把前段能力拉回。这意味着在它的预算表里，**遗忘的对冲是显式成本项**。
- **成绩锚（如引用须带口径）**：SWE-bench Verified 77.8、Terminal-Bench 2.0 得分 56.2（发布时开源最高；口径：报告披露，TB 版本 2.0，不可与 3.0/4.0 分数比较——第六节展开）。

一条硬纪律：**这是 GLM-5 对自家配方的工作报告，不是"顺序 RL＋末段 OPD"作为通用最佳实践的证明。**它证明的是"多阶段回退是真实风险、修复需要显式工程"这个结构性事实，不是"照抄这个顺序就能得到同样的模型"。

### 3. 对冲手段一览

| 对冲手段 | 做法 | 代价 |
|---|---|---|
| 回放（Replay） | 把旧阶段的数据混进新阶段训练 | 数据要留档、配比要调，冲淡新目标的学习信号 |
| 混合训练 | 多目标数据同批混训而非分段串行 | 训练调度复杂化，多目标可能互相牵制 |
| 阶段性能力矩阵 | 每阶段结束跑全能力矩阵，回退超阈值即阻断晋级 | 评测本身要算力与纪律（第⑧层门禁） |
| 跨阶段蒸馏修复 | 末段用蒸馏把前段能力拉回（GLM-5 的选择） | 多一个阶段的全套成本：数据、训练、评测 |

四者不互斥，旗舰流水线通常组合使用。选择的原则只有一条：**对冲成本要和回退风险一起进预算表**——如果遗忘风险高到需要专门一个修复段，那这个段的算力与数据成本属于方案的固有成本，不是"额外开销"。

以回放为例感受一下"对冲不是免费的"（示意配比，非任何真实配方）：

```text
第 3 段(Agentic RL)的训练数据桶:
  ├─ 新目标数据(agent 轨迹)      70%
  ├─ 回放:第 1 段 SFT 数据        15%   ← 保指令遵循与格式
  ├─ 回放:第 2 段 Reasoning 数据  10%   ← 保推理链格式
  └─ 通用能力回放数据              5%   ← 保基座泛化

两个方向的代价:
  回放太少 → 第 3 段训完,前两段能力回退,矩阵亮红灯
  回放太多 → 新目标的学习信号被稀释,第 3 段本身推进变慢
配比怎么定?没有先验答案——用能力矩阵的回退幅度反向校准:
  回退超阈值 → 该来源回放份额上调;连续两轮无回退 → 可下调
```

### 4. 能力矩阵：遗忘的门禁

对冲是否有用，看的是**能力矩阵**——"能力项 × 评测集"的对照表（T03 引入的归因工具在这里转岗为门禁）：

```text
            指令遵循   代码   数学   长文抽取   拒答边界
SFT 后        82       61     55      41        88
RL-代码段后   80       74     54      40        86   ← 代码涨,其余基本守住
RL-通用段后   71       58     60      39        84   ← 通用涨,代码明显回退!
末段修复后    79       71     59      41        87   ← 修复段把回退拉回
(教学示意数字,非任何真实模型;门禁逻辑是真实的)
```

门禁规则只有一条：**晋级看整张矩阵，不看单列最高分。**哪一列的回退不可接受，应该在训练开始前写进 Training ADR 的第 8 段（验证与晋级门禁），而不是出事之后补。

矩阵本身也有账：每个格子是一次（或多次）评测跑分，矩阵越全、轮次越密，评测算力越可观。务实的做法是分层——**每阶段必测核心行（目标能力＋已知高回退风险项），发布前跑全矩阵**；这和 T10 的分层评测是同一件事在两个阶段的表现。

> **判断边界：**"新能力提高、旧能力退化"不是失败，是多阶段训练的常态；失败的是没有矩阵、没有阈值、没有修复预案就把回退发布出去。GLM-5 的末段蒸馏说明：到了旗舰规模，遗忘对冲已经是流水线的一等公民，不是善后工作。

## 六、收益归因：蒸馏与后训练增益是否值得

### 1. 先把对照组摆齐

第五节问"有没有回退"，本节问"增益本身值不值"。归因框架承接第三节的两条对照，扩成三问：

```text
问题 1:增益来自哪个信号?
  SFT?蒸馏?RL?数据?——固定预算,逐段消融,而不是整条流水线只报最终分
问题 2:相对什么而言?
  同预算直接训练对照(第三节对照组 A)+ 推理成本对照(对照组 B)
问题 3:代价进了哪本账?
  Teacher 采样费、回退修复费、评测费——都记进 T02 的研发账
```

下面两个 2026 案例分别回答"后训练增益可以有多大"与"增益的口径怎么读"。

### 2. 案例拆解：GLM-5.3——同一个底座，只重写后训练

[GLM-5.3 官方发布](https://z.ai/blog/glm-5.3)与[官方模型卡](https://huggingface.co/zai-org/GLM-5.3)（2026-08-14）披露了一组适合本章的对照（口径：官方模型卡报告值，同一基准版本）：

| 指标 | GLM-5.2 | GLM-5.3 | 变化 |
|---|---:|---:|---|
| Base Model | 744B 总参-A40B 激活（官方口径） | 同一 base model，不重训 | 底座不变 |
| Terminal-Bench 3.0 | 4.6 | 28.3 | 约 6 倍 |
| DeepSWE v1.1 | 46.2 | 66.9 | ＋20.7 |
| Agents' Last Exam | 23.8 | 28.5 | ＋4.7 |

这组数字对后训练决策的含义：

- **后训练编排可以是能力的主变量。**底座一分钱没花（相对预训练而言），能力差距全部来自重写的后训练流水线。T01 用这组数字说明后训练的量级，本章的用法更进一步：它同时是"示范＋蒸馏＋RL 这套组合拳"的上限证据——同一个基座，信号设计不同，Terminal-Bench 3.0 上 4.6 与 28.3 的差距就是信号与编排的差距。
- **6 倍不可外推。**Agents' Last Exam 只从 23.8 到 28.5（约两成）。不同任务的提升幅度差一个数量级——"后训练有量级效应"是真的，"每个任务都有 6 倍空间"是读表错误。读增益的通用纪律：**倍数要看绝对分的基数**（4.6 → 28.3 的 6 倍与 46.2 → 66.9 的＋20.7 分，可能是同一种改善的两种读法）。
- **收益与风险同源。**官方披露中 ExploitBench 成绩翻倍（网络攻防能力，官方口径），并因此引发 dual-use 安全讨论——能力增益与安全风险是同一枚硬币，判定标准在 T10 展开。

### 3. 案例拆解：Kimi K3.1 Pro——三个月一代的后训练迭代

[Kimi K3.1 Pro](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)（月之暗面，2026-10-23 发布）给了后训练增益的另一种口径（数据均为所引公开材料口径）：

- 2.8T 总参的原生多模态 agentic MoE——与三个月前的 Kimi K3（2026-07，官方论文口径 2.8T 总参/104B 激活/896 专家选 16）同量级；
- Artificial Analysis 的 K3.1 Pro 评测文章报告其 AA Intelligence Index 排名第 4，Terminal-Bench 4.0 得分 **65.7%**（含 86 个 CLI 任务）；
- 2026-11-05 如期开放权重，发布物约 **5.6TB**；Agent Arena 开源权重第一（注意：开源第一不等于全场第一——2026-07 全榜由 Claude Fable 5（High）领跑，且 Arena 自家论文披露 83 个开源模型合计仅占 29.7% 的榜单数据，开源代表性存在争议）。

两个数字必须现场"翻译"：

- **5.6TB 意味着什么**：5.6TB ÷ 2.8T 总参 ≈ 每参数 2 字节，正好是 BF16 精度权重的体积（本文推断，以官方发布物为准）。无论哪种精度档位，消费级单机都装不下——**权重开放 ≠ 可自部署**（T02 已立的三分法：权重开放、账本透明、可自部署是三个独立命题；K3 系训练 Token 与卡时未披露，账本不透明）。
- **三个月一代、总参不变**意味着什么：参数量级不动而榜单成绩持续上移，公开口径下的主要变化在后训练与数据侧。但注意边界：官方未在所引材料中披露基座是否完全复用，"同参数量级"不等于"同一底座"，不得写成"K3.1 Pro 完全复用 K3 底座"——精确结论以模型卡/技术报告披露为准。这正是"底座复用与后训练增益"类案例的通用纪律：**复用是官方披露的事实时才能写成事实，否则只是假设。**

### 4. 一个高频翻车点：Terminal-Bench 的版本口径

本章引用过三个 Terminal-Bench 分数，它们分属三个版本，**不可跨版本比较**：

| 分数 | 模型 | 基准版本 | 合法比较范围 |
|---|---|---|---|
| 56.2 | GLM-5 | Terminal-Bench 2.0 | 只能与 TB 2.0 分数比 |
| 4.6 → 28.3 | GLM-5.2 → GLM-5.3（同底座） | Terminal-Bench 3.0 | 版本内对照有效（这正是它有价值的原因） |
| 65.7% | Kimi K3.1 Pro | Terminal-Bench 4.0（含 86 个 CLI 任务） | 只能与 TB 4.0 分数比 |

跨版本直接比大小（例如拿 65.7% 与 28.3 比"谁强"）是评测引用里最常见的静默错误：任务集都换了，分数不在同一把尺子上。写进任何报告前，基准版本号必须与分数同行。

### 5. 归因检查表

| 检查项 | 不合格的表现 | 合格的标准 |
|---|---|---|
| 对照组 | 只比"Student 的过去"或"训练分布内复述" | 同预算直接训练对照＋推理成本对照 |
| 信号消融 | 整条流水线只报最终分 | 分段归因：SFT/蒸馏/RL 各自贡献可分离 |
| 回归检查 | 只看目标能力 | 能力矩阵全项，回退阈值事先写明 |
| 独立评测 | 与训练数据同源的评测集 | 分布外任务、独立评测、多次运行 |
| 口径完整 | 裸分数、裸参数量 | 基准版本、参数口径（总参/激活）、阶段、评测方 |

### 5.1 把三问跑回开场场景

用这张表回看开场的团队，问题出在哪一行一目了然：

| 三问 | 开场团队的实际答案 | 判定 |
|---|---|---|
| 增益来自哪个信号？ | 只有一段 SFT，没有消融；25 万条那轮只有一个变量（数据量）但没分分布 | 部分合格：单变量改对了，分布没拆 |
| 相对什么而言？ | 只跟自己比（5 万 → 25 万条版本）；无同预算对照、无推理成本问题 | 不合格 |
| 代价进了哪本账？ | 只算了标注成本；没算评测口径混用（同分布集）造成的虚假安全感 | 不合格 |

如果他们当时只做一件事，最划算的是哪个？按本章的推导：**先把"新题型 41%"变成一组定义清楚的目标能力与验收指标**（第①层），再决定是补数据覆盖（第②层）、换写入深度（第⑤层）、还是引入 Teacher 蒸馏（第②层换分布来源）。方法选择的争吵，十有八九是第①②层的账没算清。

### 6. 光谱的下一级预告

本章所有手段共享一个天花板：**示范只能传递"已经知道怎么做的事"**。当任务存在多个合理答案（写作风格、回答取舍），示范无法定义"更好"；当任务有客观对错但解法要探索，示范只能给 Teacher 已找到的解。前者是 T07 的偏好信号要解决的问题，后者是 T08 的可验证奖励的地盘。判断"该不该离开第一级信号"的信号，恰恰来自本章的归因检查表：当同分布堆量与蒸馏对照都停止产生收益，而目标能力仍然够不着时，就是换信号级别的时机。

> **架构智慧：**"我们的模型变强了"是营销陈述；"在同一底座、同一基准版本、同预算对照下，这组信号带来了这组矩阵变化，回退在阈值内"才是工程陈述。后训练的每一分收益，都应该能用这张检查表复述出来。

## 七、工程产物：SFT / Distillation Strategy（示范与蒸馏策略表）

把本章的判断压成一张可直接带进评审的表。每个字段都有对应的"不合格即打回"标准：

| 字段 | 要填什么 | 打回标准（示例） |
|---|---|---|
| 目标能力与验收指标 | 要迁移什么能力；用什么评测判定；哪些能力不许回退 | "更好用"这类不可检验目标 |
| 示范来源与分布 | 人类标注/Teacher 生成/混合；覆盖哪些任务形态；与线上分布的距离 | 来源不明，或与目标任务形态不重合 |
| Teacher 选择与过滤 | 谁、什么版本、强在哪；正确性过滤标准 | Teacher 能力未经独立评测；轨迹不过滤 |
| Student 容量 | 底座与参数口径；容量是否装得下目标能力 | 目标能力明显超出容量仍未做预算对照 |
| 写入深度 | LoRA/PEFT/全参；依据（目标性质＋回退清单） | "预算够所以全参"式无依据选择 |
| 数据策略 | on-policy/off-policy；在线基础设施需求；Teacher 采样成本记账 | 选 on-policy 却没有 rollout 系统预算 |
| 阶段编排与遗忘对冲 | 各阶段顺序；回放/混合/修复段；能力矩阵门禁阈值 | 多阶段串行却无任何回退检测 |
| 对照实验 | 同预算直接训练对照；推理成本对照；消融计划 | 缺对照组 A 或 B |
| 验收门禁 | 全矩阵晋级线；独立评测；退出条件 | 只看目标榜单单列 |

开场场景用这张表复盘一遍（示意填写）：目标能力写的是"通用助手"（不合格——不可检验）；应改成"指令遵循＋长文抽取＋多轮澄清三项达标，通用能力不回退超过 3 个点"。于是缺口立刻显形：5 万条示范的覆盖里根本没有长文抽取，新题型 41% 不是训练问题，是**第②层（训练材料）就没对齐第①层（能力目标）**。这就是这张表的用途：让假设在花算力之前先暴露。

这张表与 T01 的 Training ADR 九段骨架对应：字段 1 对应第 1 段（能力目标），字段 2--3 对应第 2 段（训练材料），字段 4--7 对应第 3--6 段（信号、候选方案与系统影响），字段 8--9 对应第 8 段（验证与晋级门禁）。学完 T07--T09 后，它会长成完整的 Training ADR（T11 的 capstone）。

## 八、六种最常见的错误判断

### 错误 1：把 SFT 当成教能力的万能键

SFT 稳定教会的是格式、任务模式与行为边界；能力上限受示范质量与覆盖约束（引言光谱表第一级的典型代价）。2026 年"SFT 是 off-policy 模仿阶段、能力提升主要来自 RL"是值得参考的实践走向，但它是经验叙事，不是可跳过验证的定理——你的场景要你自己的对照来裁决。

### 错误 2：把"复述准确"当"能力迁移"

训练分布内 82% 与分布外 41% 是两张成绩单。评价 SFT/蒸馏只看同分布评测，等于只看第一张。合格的迁移证据必须包含分布外任务与能力矩阵，且在训练开始前定义好。

### 错误 3：把 LoRA 当"便宜的全参"

《LoRA Learns Less and Forgets Less》的连体结论是：LoRA 目标域学得少、源域忘得也少。它不是折扣版全参，而是"学习上限换基座稳定与工程灵活"的另一种取舍。决策输入是目标能力与不可回退清单，不是价格表。

### 错误 4：蒸馏只跟 Student 自己比

"蒸馏后比蒸馏前强"几乎必然成立，因为缺对照。归因至少要过两道门：同预算直接训练对照（证明 Teacher 信号本身有价值）与推理成本对照（证明 Student 比直接部署 Teacher 便宜且够用）。

### 错误 5：Teacher 的输出照单全收

Teacher 会出错、有风格偏差，软标签与轨迹里能力与毛病混在一起。没有正确性过滤与对齐过滤的蒸馏，是把 Teacher 的错误分布一起搬进 Student——Inkling 2 Small H4 的过滤工序不是可选项。

### 错误 6：多阶段训练不做回归评测

顺序优化多个目标，参数只有一份，能力回退是默认结局而非事故——GLM-5 官方承认回退存在并专门编排了末段蒸馏修复。没有能力矩阵与晋级阈值的多阶段流水线，等于把回退的发现时机交给上线之后。

## 本章小结

- **SFT 的机制是 Token 级模仿**：只对示范回答部分的每个 Token 推高概率，配 Teacher Forcing。它稳定教会格式、任务模式与行为边界；能力上限受示范质量与覆盖约束。
- **"教会了"有两种，必须分开验收**：训练集拟合（同分布高分）与能力迁移（分布外可用）。合格证据 = 分布外任务 + 能力矩阵，且验收标准先于训练写明。
- **2026 年的叙事走向是"SFT 定位为 off-policy 模仿阶段（教格式与模式），能力提升主要来自 RL"**——值得当作先验，不可当作定理；引用时注意它来自实践文章与模型报告，缺同预算纯 SFT 对照。
- **写入深度是"学多少"对"忘多少"的选点**：LoRA 目标域学得少、源域忘得也少（预印本结论）；决策输入是目标能力性质与不可回退清单，不是价格。
- **蒸馏按搬运对象分三种（Logit/Response/Trace），本质是"示范来自另一个模型的分布"**。失败模式：口径背诵、错误迁移、Teacher 偏差、容量上限；对冲：正确性与对齐过滤（Inkling 2 Small H4 的 34B Token 轨迹是现役样板）。
- **蒸馏必须赢过同预算直接训练，并过推理成本对照**——只跟 Student 自己比不构成证据（R1-Distill 的结论正因为做了对照才有分量，且其口径不可外推）。
- **On-policy 蒸馏把数据分布权交还 Student**：在自己的 rollout 上被 Teacher 修正，修复分布偏移，代价是在线基础设施与工程复杂度；"OPD 成为开源后训练中心技术"是观察性叙事，与"GLM-5 用它修复回退"是两个层级的陈述。
- **多阶段训练的默认结局是能力回退**：GLM-5 官方承认顺序 RL 侵蚀前段技能，并把蒸馏修复编进流水线末段——遗忘对冲是显式成本项，能力矩阵是门禁。
- **后训练增益可以有量级效应（GLM-5.3：同底座 TB 3.0 4.6→28.3），但不可外推到所有任务**；引用任何分数必须带基准版本（TB 2.0/3.0/4.0 不可跨版本比较）与参数口径。
- **权重开放 ≠ 训练透明 ≠ 可自部署**：K3.1 Pro 开放 5.6TB 权重（约每参数 2 字节）但消费级硬件难以部署，训练账本未披露。

> **下一章的问题：**示范告诉模型「应该怎么做」,但很多任务存在多个合理答案。下一章讨论如何定义偏好,并把偏好变成可优化的奖励信号。

## 基础术语速查

| 术语 | 初学者可以先怎样理解 |
|---|---|
| SFT（监督微调） | 拿「Prompt＋示范答案」继续训练基座，把示范回答里每一步的概率推高 |
| Token 级损失 | SFT 实际优化的量：只对示范回答部分的每个 Token 计算损失再平均 |
| Teacher Forcing | 训练时每一步都以示范的正确上文为条件；模型从未练习从自己的错误里恢复 |
| LoRA / PEFT | 冻结原权重，只训练旁边的低秩增量；参数高效微调的一类 |
| 全参数微调 | 所有参数都更新；上限高、显存贵、对旧能力的扰动也大 |
| 蒸馏（Distillation） | 让 Student 向 Teacher 学习：搬软标签、搬回答、或搬推理轨迹 |
| Response / Trace 蒸馏 | Teacher 生成回答或完整推理轨迹，过滤后作为 Student 的示范数据 |
| On-policy 蒸馏（OPD） | Student 在自己在线生成的轨迹上学习，Teacher 提供修正信号 |
| 能力回退 / 遗忘 | 后一阶段训练让前一阶段已学会的能力下降；多阶段训练的默认风险 |
| 回放（Replay） | 把旧阶段数据混进新阶段训练，对冲遗忘 |
| 能力矩阵 | 「能力项 × 评测集」对照表，识别新能力提高、旧能力退化，兼作晋级门禁 |
| 口径背诵 | Student 学会了 Teacher 的表述习惯却没学会解法；蒸馏的典型失败模式 |
