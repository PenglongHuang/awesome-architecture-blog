> 一句话点题：**训练方案不是算法排行榜，而是一条从能力目标到晋级证据的决策链。**

---

> **🧠 基础模型训练决策专题 · 引言 · 本专题只练一件事**
>
> 把任何训练提案翻译成"目标→材料→信号→归因→优化→组件→系统→证据"的推理链。本引言不展开任何机制的推导——那些属于后续十章各自的决策现场；这里只交给你三样东西：全书地图、公共语言和阅读路线。读完你不必会推导公式，但应该能说出任何一个训练方案"正在回答哪一层的问题"。

---

## 开场：一个最小的训练现场

给模型一道 `17 × 23`,让它尝试四次：两次算对，程序验算给 1 分；两次算错，给 0 分。接下来训练系统要做的事只有一件——**调整模型内部的概率，让得 1 分的答案以后更容易出现，得 0 分的更少出现**。模型内部没有一条条写死的 `if` 规则，只有数量巨大的可学习数字(参数);所谓训练，就是用某种信号去调这些数字。

真正的问题从这一步才开始：分数由谁来打？功劳和责任归到哪一步？每次调多少？要不要让模型继续尝试新的做法？每多回答一层，就多出一类工程对象——数据、奖励、信用分配、优化方法、辅助模型、集群拓扑、评测证据。

本专题把这条推理链固定为八层，后续十章各占一个决策现场：

```text
目标 → 材料 → 信号 → 归因 → 优化 → 组件 → 系统 → 证据
```

为什么需要一张地图？去旁听一次真实的方案评审会：提案人花二十分钟讲某个新方法的论文与榜单，然后被三个问题打回——"我们的数据长什么样？""Critic 的显存从哪出？""哪些能力不允许回退？"提案答不上来，不是因为他不聪明，而是因为**方法名字和工程决策之间隔着一条完整的推理链，而团队还没有一套公共语言来走完它**。

这张地图先给全局，再逐层深入。它的用途不是让你记住十个章名，而是让你在任何一次讨论里都能问出那句最关键的话：

> 我们现在讨论的是第几层的问题？

## 一、模型生产的生命周期与全书地图

在进入任何一章之前，先把训练决策放回完整生命周期：

```text
大规模原始数据
    ↓ 预训练:反复预测下一个 Token ──────── T02 预算 / T03 数据 / T04 骨架 / T05 训练系统
Base Model(基础模型)
    ↓ 后训练:示范、偏好、可验证奖励、环境 ─ T06 示范 / T07 偏好 / T08 可验证 RL / T09 Agentic RL
候选产品模型
    ↓ 能力 / 安全 / 回归评测与发布门禁 ──── T10 安全与评测
发布模型
    ↓ 编排、演进与投入决策 ─────────────── T11 训练编排与战略
```

这张图上的三个阶段，连同两个最常被误用的词，先用一句话说清：

- **预训练(Pre-training)**:让模型从大规模数据中学习语言、知识和基础能力，主要目标通常是预测下一个 Token。
- **Base Model(基础模型)**:预训练得到的模型。它已经会续写和解决一些问题，但不一定稳定遵循指令，也未必具有产品要求的行为和安全边界。
- **后训练(Post-training)**:在 Base Model 上继续训练，让它更会遵循指令、表达偏好、推理、使用工具和遵守安全约束。
- **Fine-tuning(微调)**:不是从零训练，而是在已有模型参数的基础上继续训练；SFT、偏好优化和强化学习后训练都可能改变已有参数。

全书十章沿两条主线展开：

```text
T02 预算 → T03 数据 → T04 骨架 → T05 训练系统     (预训练主线)
                        ↓ 交付 Base Model + Checkpoint + 能力基线
T06 示范 → T07 偏好 → T08 可验证 → T09 环境 → T10 门禁 → T11 战略   (后训练与治理主线)
```

**预训练主线(T02--T05)先决定投入，再决定材料、结构和系统；后训练与治理主线(T06--T11)让学习信号逐级增强，最后形成可验证的训练与发布闭环。**

### 预训练主线(T02--T05)

| 编号 | 章名 | 核心问题 |
|---|---|---|
| T02 | 预算总账 | 训练一个模型究竟要花多少钱，预算应该投在哪里？ |
| T03 | 数据工程 | 什么数据能带来目标能力，如何证明数据处理有收益？ |
| T04 | 模型骨架 | Dense、MoE、长上下文和多模态应该怎么选？ |
| T05 | 训练系统 | 如何让模型在有限硬件上稳定、高效地训练？ |

### 后训练与治理主线(T06--T11)

| 编号 | 章名 | 核心问题 |
|---|---|---|
| T06 | 示范学习 | SFT 和蒸馏分别能教会模型什么？ |
| T07 | 偏好学习 | 如何定义"更好",并把偏好转成可靠的优化信号？ |
| T08 | 可验证强化学习(RLVR) | 什么时候可验证奖励有效，怎样防止模型钻奖励空子？ |
| T09 | Agentic RL | 如何训练模型在工具和环境中完成长程任务？ |
| T10 | 安全与评测 | 如何证明模型达到发布要求，且没有绕过安全约束？ |
| T11 | 训练编排与战略 | 如何编排训练阶段、演进模型族并做投入决策？ |

两条主线之间不是单向流水，而是有明确的交接物：预训练主线交付的是 Base Model、Checkpoint 和一套基础能力基线；后训练主线接收它们，交付的是有行为边界的产品候选。交接物质量不过关，后一章的任何方法都救不回来——这是全书最重要的接口约定。

地图表格先不加链接，避免章节尚未就位时出现断链；预训练主线的前两站入口在这里：[T02 · 预算总账](/tutorial/t02-scaling-budget-three-ledgers/)与[T03 · 数据工程](/tutorial/t03-data-recipe-quality-synthesis/)。

### 预训练与后训练：同一坐标系，不同决策现场

两条主线延续同一模型族的主体骨架，但数据、学习信号和控制系统并不相同：

| 判断层 | 预训练的典型问题 | 后训练的典型问题 |
|---|---|---|
| 能力目标 | 通用语言、代码、数学、长上下文基础能力 | 指令遵循、偏好、推理、工具使用、安全行为 |
| 训练材料 | 大规模 Token 序列与数据混合 | 示范、偏好对、合成数据、Rollout 轨迹 |
| 学习信号 | 主要来自目标 Token | 示范目标、偏好、Reward、Verifier、环境反馈 |
| 辅助组件 | 数据管线、训练器、Checkpoint | Reward Model、Critic、Verifier、环境、Rollout Workers |
| 晋级证据 | 基础能力曲线、扩展收益、污染检查 | 目标行为、能力回退、安全、Reward Hacking |

一个说明后训练权重的真实锚点：GLM-5.3 的官方模型卡称它与 GLM-5.2 使用同一个 base model、只重写后训练流水线，Terminal-Bench 3.0 分数从 4.6 提到 28.3(官方模型卡报告值，同一基准版本)。这个数字既说明后训练可能带来量级变化，也不能推出"所有任务都有同等提升"——怎样解读这类证据，第 11 章展开。

> **架构智慧：**预训练与后训练的区别不是"大工程"与"小修小补",而是两套不同的决策现场：前者在赌数据与算力的配比，后者在赌信号与约束的设计。任何"后训练只是微调"的说法，都过不了上面这张对照表。

## 二、先分清三种"架构"

讨论训练时，"架构"一词至少指向三种结构，混用会直接导致决策错位。这三种结构也正好解释全书的组织方式。

### 1. 模型架构：一次前向计算怎样发生(→ T04)

它描述模型内部的计算结构：Dense(每个 Token 经过稠密参数)、MoE(只激活被路由选中的少数专家)、Attention(决定关注哪些上下文)、多模态编码器与连接器。模型架构主要改变参数容量、激活计算、显存、通信和推理特征。它和 PPO/GRPO 不在同一层：前者改变模型怎样计算，后者改变模型怎样学习。

### 2. 训练方法：模型根据什么信号更新(→ T06--T09)

它描述学习目标与更新方式：Next-token Prediction、SFT、DPO、PPO、GRPO、蒸馏等。训练方法改变训练样本形态、损失或奖励信号、是否需要在线 Rollout,以及参数怎样被更新。

### 3. 训练系统架构：哪些组件一起把方法运行起来(→ T05)

它描述工程系统：数据生产与版本管理、Actor/Critic/Reward Model/Verifier、Rollout 集群与训练集群、同步或异步流水线、Checkpoint、评测门禁与模型注册。

三者最终形成一条约束链：

```text
能力目标
  ↓
模型架构 + 训练方法
  ↓
需要怎样的数据、计算图和辅助模型
  ↓
训练系统拓扑、资源账单和故障边界
  ↓
评测证据是否证明这次选择值得
```

举个例子：选择 GRPO 不只是换一个 Loss(损失函数，即系统衡量训练目标偏差的计算规则)——系统不再训练 Critic,但必须为同一 Prompt 生成多条可比较 Rollout,并维护完整的样本组；选择 Critic-based PPO 也不只是换算法——系统要部署和训练 Critic,为它分配显存与 GPU,并处理价值估计的偏差。方法层的每一个选择，都会在系统层长出新的组件和账单。

> **判断边界：**一种技术只有在改变数据形态、计算图、系统拓扑、资源账单或失败模式时，才是本专题重点讨论的架构问题。只换名字、不改变任何约束的"新方法",进不了决策链。

## 三、学习信号光谱：四条路线一页表

后训练的核心变量是学习信号。从示范到环境，信号逐级增强：示范告诉模型"正确长什么样",偏好告诉它"哪个更好",可验证奖励告诉它"对不对",环境奖励只告诉它"任务最终成没成"。SFT、DPO、GRPO、PPO 等方法的机制详解分发到 T06--T09 各章，引言只保留这一页光谱：

| 信号 | 主属章 | 最小训练数据 | 需要在线 Rollout | 独立 Critic | "更好"由谁定义 | 典型代价 |
|---|---|---|---:|---:|---|---|
| **示范**(SFT / 蒸馏) | T06 | Prompt + 示范答案 | 否 | 否 | 写示范的人 | 上限受示范质量与覆盖约束 |
| **偏好**(DPO / RM) | T07 | Prompt + Chosen/Rejected 偏好对 | 核心训练通常不需要 | 否 | 标注者或 AI 评审 | 偏好质量、评分器偏差与过优化 |
| **可验证奖励**(RLVR) | T08 | Prompt + Rollout + 可验证 Reward | 是 | 取决于优化器 | 规则、答案、单元测试或 Verifier | 验证成本与防投机；采用 GRPO 时还需组采样与组内方差 |
| **环境奖励**(Agentic RL) | T09 | 多轮交互轨迹 + 环境反馈 + Reward | 是 | 视任务而定 | 环境最终状态与过程信号 | 环境工程、长程归因、异步拓扑 |

先记住一条最小区别：

> **监督学习**主要让模型模仿已有正确示范；**强化学习**则让模型实际尝试，根据 Reward 判断结果好坏，再调整 Policy,使高回报行为以后更常出现。

表里的"需要在线 Rollout"一列值得单独解释："在线"不是指模型对公众开放，而是指**数据生成与模型更新形成循环**——训练期间要让当前模型不断产生新尝试，再把这些经验送回训练器。离线路线(示范、偏好对)开工前数据已经备好，训练时反复读取；在线路线则要额外处理采样成本、数据"过期"(生成数据的版本落后于正在训练的版本)和环境故障。这些工程词的完整定义在 T08、T09。

光谱也不是单行道。有了明确的可验证任务，不代表必须跳过 SFT——基座还不会稳定输出目标格式时，通常先用示范建立行为，再进入强化；反过来，偏好信号也常与规则奖励混合使用，同一条流水线里出现多种信号是常态而非例外。真正的判断永远是：目标能力在哪，信号能不能可靠地定义"更好"。

每条路线的一句话直觉：

- **SFT** 回答"正确示范长什么样";
- **DPO 类**回答"已有的两个答案里，更希望模型倾向哪一个";
- **GRPO 类**用同题多次尝试的组内比较换掉 Critic;
- **Critic-based PPO** 用额外价值模型换取单轨迹学习与细粒度归因。

一个预告：GLM-5.2 因为长程 Agent 任务的轨迹形态变化，从组式路线转向 Critic-based PPO——这条"任务形态→数据形态→方法假设→系统拓扑"的完整因果链，第 9 章拆解。

> **判断边界：**这张表不是先进程度排名。输入数据不同、学习问题不同、需要的系统组件也不同——换方法不是换一个名字，而是换一组前提和一张资源账单。

## 四、反馈来源 ≠ 优化器：最常见的概念混写

"RLHF 还是 PPO"这类问题，几乎每个团队都争论过。问题在于这些词位于不同的决策层。

- **RLHF(Reinforcement Learning from Human Feedback)**描述利用人类反馈塑造模型行为的一类流程。经典的 InstructGPT 路线是：

```text
人类示范 → SFT
人类比较模型回答 → 训练 Reward Model
Reward Model 打分 → PPO 更新 Policy
```

所以 PPO 可以是 RLHF 流程内部使用的优化方法，二者不是互斥选项。
- **RLAIF** 把人类直接评价替换成 AI 评价，以降低标注成本、扩大规模。它同样不规定最后的优化器：AI 反馈可以产生偏好对再做 DPO、训练 Reward Model 再做 PPO,或与规则、安全原则、人工抽检共同组成奖励。
- **可验证奖励**指奖励来自数学答案、单元测试、编译结果、游戏胜负或环境状态。它描述奖励来源，不是特定优化器；同一种可验证奖励可以搭配 GRPO 的组内比较，也可以搭配 Critic-based PPO 的单轨迹学习。

因此，正确的分层方式是：

| 决策层 | 它回答什么 | 典型选项 |
|---|---|---|
| **反馈来源** | 谁来定义"更好" | 人类、AI、规则、Verifier、环境 |
| **数据组织** | 训练材料长什么样 | 示范、偏好对、单条 Rollout、成组 Rollout、长程轨迹 |
| **信用分配** | 最终结果怎样归因 | 整条轨迹、过程奖励、Critic、组内相对基线 |
| **策略更新** | 参数怎样稳定变化 | SFT、DPO、PPO、GRPO 等 |
| **系统实现** | 需要哪些组件 | Actor、Critic、Reward Model、Verifier、Reference、Rollout Workers |

> **架构智慧：**遇到"A 还是 B"时，第一问不是谁更强，而是 **A 和 B 是否在回答同一个问题**。一个描述反馈从哪里来，另一个描述参数怎样更新，它们就可以同时存在，不能被放进单选题。

## 五、训练决策的八层坐标系

以后遇到任何模型训练方案，都沿这八层从上往下拆。越靠上越接近"为什么训练",越靠下越接近"系统怎样承载":

```text
① 能力目标:到底想让模型变好在哪
        ↓
② 训练材料:模型实际看到什么
        ↓
③ 学习信号:系统怎样定义"更好"
        ↓
④ 信号粒度与信用分配:好坏归到哪一步
        ↓
⑤ 优化方法:参数怎样更新
        ↓
⑥ 模型与辅助组件:运行时需要哪些模型
        ↓
⑦ 训练系统拓扑:这些组件如何生成、训练和同步
        ↓
⑧ 晋级证据:怎样证明收益大于新代价
```

每层一行，并标注主展开章：

| 层 | 一句话 | 主展开章 |
|---|---|---|
| ① 能力目标 | 先写可检验的目标，而不是"我们要上 RL" | T02 / T11 |
| ② 训练材料 | Token、示范、偏好对、成组 Rollout 或环境轨迹——数据形态决定方法前提 | T03 |
| ③ 学习信号 | 目标 Token、人类偏好、AI 评价、规则、Verifier 或环境结果 | T07 / T08 |
| ④ 信号粒度与信用分配 | 好坏落在整条轨迹，还是每个 Turn / Step / Token | T08 / T09 |
| ⑤ 优化方法 | SFT、DPO、PPO、GRPO 等参数更新方式 | T06--T09(收束于 T11) |
| ⑥ 模型与辅助组件 | Policy 之外要不要 Reference、Critic、Reward Model、Verifier | T05 / T09 |
| ⑦ 训练系统拓扑 | Rollout 与训练怎样同步，组件如何分配显存与 GPU | T05 / T09 |
| ⑧ 晋级证据 | 消融、回归、反投机检查与发布门禁 | T10 |

后续每一章开篇都会用这张坐标系定位自己：预训练主线主要工作在第①②⑥⑦层，后训练主线集中在第③④⑤层，第⑧层贯穿全书并在 T10 展开，第⑤层的"怎样选"最终在 T11 收束。

### 拿一个提案走一遍

假设会上有人说"我们上 RLVR 吧"。用坐标系逐层翻译，提案就变成一串必须回答的问题：

```text
① 能力目标:哪个可验证指标要提升?哪些能力不许回退?
② 训练材料:任务从哪来?同题能便宜地采出多条可比答案吗?
③ 学习信号:验证器是谁?它打分可靠、难以钻空子吗?
④ 信用分配:分数落在整条回答,还是逐步骤?
⑤ 优化方法:组内相对比较够用,还是需要价值模型?
⑥ 组件:要加 Verifier、Reward Model 还是 Critic?显存从哪出?
⑦ 拓扑:采样与训练同步还是异步?环境故障怎么处理?
⑧ 证据:和 SFT 版、基座版怎么对照?怎样排除投机?
```

八问走完，原提案要么变成一份可执行的方案，要么自己暴露出"其实第②层就凑不齐数据"。这正是坐标系的用途：**在花算力之前，先让假设破产。**

> **架构智慧：**训练方法不是从论文标题直接落到集群配置。中间必须经过"目标—材料—信号—归因—优化—组件—系统—证据"八层翻译；跳过任何一层，复杂度都不会消失，只会转移到你没看的那一层。

## 六、最小术语集

全书共用的词汇只有 8 个，先记住它们在链条里的位置：

```text
Prompt
  ↓
Policy(当前策略)── 不漂离 ── Reference Policy(冻结参考)
  ↓ Rollout(实际尝试一次)
Response / Trajectory
  ↓
Reward(这次结果得多少分)
  ↓
Advantage(比预期基线好多少)→ 据此更新 Policy
```

- **Token**:模型读写文本的基本单位，一个汉字或英文单词的一部分都可能占一个或多个 Token;
- **Policy**:当前模型关于"下一步生成什么"的概率规则，训练就是调整它；
- **Reference Policy**:训练开始前冻结的模型快照，用来约束当前模型不要漂移太远；
- **Rollout**:让当前模型完整尝试一次，生成一条答案或轨迹；
- **Reward**:对已经产生的结果给出的分数；
- **Advantage**:实际表现相对预期基线好多少，训练据此决定增谁减谁。

加上两个"指引型"词条：**Checkpoint**(训练快照与恢复所需的状态，完整状态机在 T05 定义)与 **Fine-tuning**(在已有参数上继续训练，而不是从零开始)。其余术语——Critic、Value、Credit Assignment、Verifier、Policy Lag、Compaction、Reward Hacking、消融实验等——都在各章首次使用处自行定义，引言不要求你预习。

## 八、五种最常见的错误判断

这五种错误贯穿全书，先立在这里作为全局警告。

### 错误 1:按发布时间排列先进程度

新方法可能只在特定数据、任务、模型或硬件约束下更合适。离开原约束，结论不自动成立。**纠正动作**:引用任何方法时，同时写下它原论文的任务、数据和规模口径。

### 错误 2:把不同层级的概念做成单选题

"RLHF 还是 PPO"类似于问"支付流程还是数据库事务":一个描述整体流程，一个描述其中可能采用的机制。**纠正动作**:对照第四节的决策层表，先给两个词各找一行位置；能各归其位的，就不是选择题。

### 错误 3:只比较算法效果，不画系统拓扑

如果比较没有计入 Reward Model、Critic、Rollout、环境和通信成本，算法收益就不是完整的工程收益。**纠正动作**:任何方案比较必须附一张组件图，标出每个框占用的显存与 GPU。

### 错误 4:复制别人的答案，不复制别人的约束

看到 GLM-5.2 使用 Critic-based PPO 就跟进，却没有长程、变长、经 Compaction 的轨迹，也不需要 Token 级信用分配——复制的只是结论，不是推理过程。**纠正动作**:复用前先重走一遍"任务形态→数据形态→方法假设→系统拓扑"的因果链，确认自己的约束与对方同构。

### 错误 5:分数提高就宣布架构成立

一次改动可能提高目标榜单，同时损害通用能力、安全性、训练稳定性或单位算力效率。模型晋级必须看一组证据，而不是一个最好看的数字。**纠正动作**:晋级评审只认证据组——目标提升、非目标不回退、无投机迹象、有受控消融，缺一项都不放行。

> **判断边界：**复用推理，不复制答案。每个训练决策都要写清候选方案的前提、系统影响、消融证据和退出条件——这正是下一节模板的用途。

## 九、每个训练决策都写成一份 Training ADR

训练实验经常只记录配置和最终分数，却没有记录"为什么选择这条路线"。本专题沿用[08 · 架构决策记录与演进](/tutorial/adr-and-evolution/)的 ADR 方法，把每次训练决策写成九段骨架：

```markdown
# ADR-Txx:训练方案决策标题

1. 能力目标——提升什么,用什么指标判断,哪些能力不能回退
2. 工作负载与训练材料——样本是 Token、偏好对还是交互轨迹
3. 学习信号与信用分配——谁定义"更好",信号落到哪一步
4. 候选方案及其假设——每个方案成立需要哪些数据、采样与稳定性前提
5. 决策——选什么,为什么当前约束更匹配它
6. 系统影响——新增或删除哪些模型、数据管线、队列与 GPU 角色
7. 代价与失败模式——复杂度被转移到了哪里,最可能怎样失败
8. 验证与晋级门禁——做哪些消融,什么回退会阻止 Checkpoint 晋级
9. 退出条件——出现什么信号时切换方案或回滚
```

这份骨架强迫团队把"某篇论文效果很好"翻译成当前系统能够检验的假设。它的价值在三个时刻最明显：立项时(第 4 段逼你列备选)、评审时(第 7 段逼你说出失败模式)、复盘时(第 8、9 段留下的门禁和退出条件，就是下一次决策的起点)。完整模板与端到端的 capstone 演练在第 11 章；从下一章起，每学完一个决策现场，你都能往这九段里多填一段。

## 本章小结

- **训练方案不是算法排行榜，而是一条决策链**:目标 → 材料 → 信号 → 归因 → 优化 → 组件 → 系统 → 证据。
- **全书两条主线**:预训练(T02--T05)先决定投入、材料、结构与系统；后训练与治理(T06--T11)让学习信号逐级增强，最后形成发布闭环。两条主线的交接物是 Base Model、Checkpoint 与能力基线。
- **三种"架构"必须分开**:模型架构(T04)、训练方法(T06--T09)、训练系统(T05)——它们分别改变模型怎样计算、怎样学习、怎样被运行起来。
- **学习信号是一条光谱**:示范→偏好→可验证→环境，逐级增强；换信号就是换前提和资源账单，不是换名字。
- **反馈来源 ≠ 优化器**:RLHF/RLAIF/可验证奖励描述"更好"由谁定义，SFT/DPO/PPO/GRPO 描述参数怎样更新，二者可以自由组合。
- **八层坐标系是全书的公共语言**,每章开篇用它定位自己。
- **复用推理，不复制答案**:任何"某模型用了 X 所以我们也用 X"的提案，都要先过八层翻译，再写进 Training ADR。

> **下一章的问题：**地图的第一站不是选模型，而是算钱——给定目标能力与部署形态，训练一个模型到底要花多少？这笔有限预算又该分给模型参数、训练 Token,还是更高质量的数据？
