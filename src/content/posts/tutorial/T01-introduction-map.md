模型能读懂一份合同，却不一定能按要求把付款日期、金额和违约责任整理出来。有时它漏掉字段，有时把日期抄错，有时原文根本没有写，它也会填上一个看似合理的答案。

遇到这些问题，很容易想到“再训练一下”。但这句话还没有说明训练要改变什么。我们是想让它知道更多合同知识，学会一种输出格式，还是在不确定时少作猜测？目标不同，准备的数据、采用的方法和检验效果的方式都会不同。

这一篇先从这里讲起。后面的章节再分别讨论预算、数据、模型结构和具体训练方法。

## 一、模型原本会的东西从哪里来

先看我们手上这个模型。在接触合同抽取任务之前，它已经能阅读中文、理解日期、辨认金额，也能生成一段通顺的解释。这些能力有相当一部分来自预训练。

语言模型预训练常用的任务是预测下一个 Token。Token 是模型读写文本的基本单位，可能是一个汉字、一个词，也可能只是词的一部分。训练时，模型根据前面的文本预测后面的内容，再根据预测与真实文本之间的差异调整参数。

例如，给出“本合同自双方签字盖章之日起”，训练材料里的后续内容可能是“生效”。模型需要为后续 Token 分配概率。大量这样的预测发生在不同文本里，模型逐渐学到语言结构、知识关联和一些解题规律。实际训练涉及的材料、计算量和优化过程复杂得多，但这仍是理解预训练的一个起点。

预训练得到的模型通常称为 **Base Model，基础模型**。它具备了很多能力，却未必会稳定地按照用户的要求使用这些能力。继续写一段像合同的文字，与准确地抽取眼前这份合同，是两个不同的任务。

为了让模型更好地遵循指令、使用工具、处理偏好与安全要求，还需要后训练。SFT、偏好优化和强化学习都可能出现在这个阶段。日常说的“微调”通常指在已有参数上继续训练，具体采用哪种目标和更新方式，还需要进一步说明。

```text
大规模数据 → 预训练 → 基础模型 → 后训练 → 候选模型 → 评测与部署
```

如果使用现成的开放权重模型，我们往往从中间开始。预算和数据不足以支持从零预训练，并不妨碍研究怎样改善一个已有模型；不过，仍然需要先测清它已经会什么、具体差在哪里。

## 二、同一个任务，可以怎样教给模型

回到合同抽取。下面是一个简化的教学例子，假设任务要求模型读原文，按固定字段输出结果，缺少的信息保留为空。

首先可以暂时不训练：把字段定义、输出格式和几条示例写进提示，给模型完整的原文。如果效果已经满足要求，就没有必要仅仅为了这个任务再增加一个训练环节。只有在提示、材料供给和现有能力都检查过之后，留下的差距才值得进一步分析。

### 给它看正确的做法

如果主要问题是格式不稳定，或者模型常常不知道缺失字段该怎样处理，可以准备一批“输入合同片段 → 正确抽取结果”的示范，用 **SFT（监督微调）**训练。

训练时，模型学习在给定输入下生成示范里的目标 Token。示范里怎样处理缺失字段、怎样引用原文，都会影响它学到的行为。只给完整、整齐的合同做示范，模型到了缺页、含糊或格式混乱的输入上，仍可能出错。

由另一个模型提供示范，也可以成为蒸馏的一种形式。蒸馏还可能使用教师模型的概率分布等信号，具体机制在 T06 展开。无论示范来自人还是模型，都需要检查学生能否把所学用于未见过的合同。

### 比较两种回答的取舍

若任务从字段抽取扩展到风险解释，两个答案可能都引用了正确条款，但一个更清楚地交代了不确定性，另一个语气过于肯定。这时很难只靠一个标准字符串判对错，却可以比较哪个回答更合适。

这类比较可以形成偏好数据：同一个输入，保留一对候选回答，并标注更偏好哪一个。DPO 可以直接用这样的偏好对训练策略；另一条路线是先训练 Reward Model（奖励模型），再用它的评分参与后续优化。

关键在于先约定比较标准。若标注者只是更喜欢篇幅长、措辞肯定的答案，训练可能强化这些特点，而未必提高解释的准确性。

### 让它尝试，再根据结果学习

对于金额、日期等能够可靠核对的字段，可以让当前模型生成结果，再由程序验证，形成奖励。根据这类可验证奖励进行的强化学习通常称为 **RLVR**。

这里的“验证”本身也需要设计。日期有不同写法，金额可能含税或不含税，合同附件也可能修改正文约定。一个过于简单的比对程序，可能把正确回答判错，也可能漏掉实际错误。奖励变高，只有在验证器可靠且独立评测也改善时，才有理由被解释为任务表现变好。

RLVR 说明奖励从哪里来，尚未决定怎样更新模型。PPO、GRPO 等方法还会影响优势如何估计、是否训练额外的价值模型，以及怎样组织采样。它们的机制和适用条件放在 T08 讨论。

这几种方式可以组合，也可以只用其中一种。选择依据是当前差距和可获得的反馈。字段抽取不一定需要偏好优化；能够单轮完成的任务，也不必为了训练而改造成多轮 Agent。

## 三、方法选定以后，还需要哪些条件

假设我们先选择 SFT。接下来的问题马上变得具体：示范从哪里来，合同是否有使用授权，训练集和测试集有没有近重复，模型能否装进现有 GPU，一次实验要跑多久。

如果换成需要在线采样的强化学习，系统还要不断生成新尝试、验证结果，再把经验送回训练器。模型尝试一次，通常称为一次 **Rollout**；当前被训练的模型在这个语境下也称为 **Policy（策略）**。采样会占用推理资源，验证可能要调用工具或运行测试，这些都属于训练方案的实际成本。

因此，讨论时需要区分三个相关但不同的对象：

- **模型结构**决定一次前向计算怎样发生，例如 Dense、MoE、注意力机制与上下文长度。
- **训练方法**决定用什么信号、按什么目标更新参数，例如 SFT、DPO、PPO、GRPO。
- **训练系统**负责把数据、模型和计算资源组织起来，处理并行、采样、保存与恢复等工作。

这三个对象互相约束。选择一个更大的模型，会改变显存和通信需求；选择一种需要在线采样的方法，会增加采样组件与调度负担。只比较论文中的最终分数，还不足以判断哪种方案适合自己的资源和任务。

后面的文章用下面八项来检查方案。这里先知道它们各指什么即可，具体问题会在相关章节中展开。

| 检查项 | 以合同抽取为例 |
|---|---|
| 能力目标 | 提高哪些字段的准确率，哪些已有能力需要保持 |
| 训练材料 | 合同、示范、偏好对或模型生成的尝试从哪里来 |
| 学习信号 | 用示范目标、人工偏好还是程序验证结果 |
| 信用分配 | 整条回答或某一步表现的好坏，怎样影响更新 |
| 优化方法 | 选择什么训练目标和参数更新方式 |
| 模型与辅助组件 | 除被训练模型外，是否需要参考模型、奖励模型或价值模型 |
| 系统拓扑 | 各组件怎样分配资源，采样与训练怎样同步 |
| 晋级证据 | 用哪些独立结果判断候选模型可以进入下一阶段 |

有些章节把它们简称为“八层坐标系”。它是一份讨论提纲，各项之间常有来回调整，不要求项目按表格顺序执行。

## 四、训练效果怎样才算成立

继续使用合同抽取的例子。如果训练后的模型在示范合同上表现更好，却仍然处理不了新的合同模板，就需要怀疑它是否只记住了熟悉的表达。若抽取更准确了，普通指令遵循却明显退化，也需要权衡这次训练的代价。

所以，开始实验前就要准备独立评测，并约定怎样比较。对这个任务，至少要分别看字段内容、缺失信息的处理和引用是否正确；还要检查测试材料是否泄漏进训练数据。用多个训练阶段时，每个阶段都应保留检查点（Checkpoint）和回归结果，才能判断收益从哪里来、退化发生在哪里。

这些记录也帮助我们决定是否继续投入。如果 SFT 已经满足要求，后面的强化学习阶段可以不做；如果提高奖励分数的同时，独立测试始终没有改善，就应该回头检查任务、数据和验证器。

为了保留选择的依据，本专题使用 Training ADR（训练架构决策记录）。它沿用架构决策记录的做法，把讨论中容易丢失的假设和取舍写下来。引言先给出简要提纲，T11 再用合同助手演示一份完整记录。

```markdown
1. 能力目标：希望改善什么，怎样测量，哪些能力需要保持
2. 工作负载与训练材料：输入形态、数据来源和使用限制
3. 学习信号与信用分配：反馈来自哪里，怎样用于更新
4. 候选方案及其假设：有哪些选择，各自成立需要什么条件
5. 决策：当前选择及理由
6. 系统影响：数据、组件、资源与运行方式的变化
7. 代价与失败模式：成本、风险和可能失效的地方
8. 验证与晋级门禁：比较方法、独立评测与验收条件
9. 退出条件：何时停止、换方案或回滚
```
