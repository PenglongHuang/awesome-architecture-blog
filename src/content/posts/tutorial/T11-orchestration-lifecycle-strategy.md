> **每增加一个训练阶段，都要说明它解决哪种剩余差距、增加多少成本，以及什么结果会让它退出。**

## 开场：同一个底座，六倍的差距

2026-08-14，z.ai 发布 [GLM-5.3](https://z.ai/blog/glm-5.3)（[官方模型卡](https://huggingface.co/zai-org/GLM-5.3)）。官方模型卡说了两件让评审会场安静下来的事：

- 它与 GLM-5.2 使用**同一个 base model**（官方口径 744B 总参数／40B 激活参数的 MoE 底座；部分二手来源写作 743B，以官方口径为准），**不重训基座**；
- 在 Terminal-Bench 3.0 上，GLM-5.2 为 4.6，GLM-5.3 为 28.3（口径：官方模型卡报告值，同一基准版本）。

28.3 ÷ 4.6 ≈ 6.2。**它意味着什么**：两个模型在预训练意义上是同一个模型——同样的参数骨架、同样的预训练数据历史——只因为后训练流水线被重写，终端类 Agent 基准就拉开了约六倍。这不是「新模型比旧模型强」的常规换代叙事，而是「训练编排本身成为一等生产力」的直接证据。

同一份官方发布还给了两个配套刻度（口径：官方发布值）：DeepSWE v1.1 从 46.2 到 66.9（软件工程 Agent 基准），Agents' Last Exam 从 23.8 到 28.5（长程 Agent 基准）。同时，ExploitBench 分数翻倍——网络攻防能力同步上涨，官方与社区的 dual-use（军民两用风险）讨论随之而来（这条风险线在 [T10 · 安全与评测](/tutorial/t10-safety-spec-evaluation-gate/)已展开）。

先立好本章的第一条纪律（F17，后面反复用到）：

> **判断边界：**「同一底座，TB3.0 从 4.6 到 28.3」只能证明**后训练编排可能带来量级变化**，不能推断「所有任务都会同等提升」。它是单一基准族（终端类 Agentic 任务）、官方自报口径；同一次后训练同时抬高了安全风险面（ExploitBench 翻倍）。引用这类数字时，必须带上基准版本、评测方与「不可全任务外推」的限定。

如果同一个底座只改后训练就能拉开六倍，那么「训练策略＝选一个最强算法」的直觉就破产了。真正的问题变成了三类编排问题：

- **路线问题**：这个能力差距，到底该用训练解决，还是根本不该用训练解决？
- **编排问题**：如果要训，各阶段按什么顺序组合？顺序带来的回退谁来修？
- **演进问题**：下一版模型，是复用底座、继续训练，还是从头来过？有限算力投给谁？

再加上一个贯穿三章的**战略问题**：训练账、推理账、Rollout 账和研发账，怎么合成一个投入决策？

本章把这四类问题合称**整机决策**：整机＝分诊（要不要训、训到哪级）＋编排（阶段怎么组合）＋演进（底座怎么换代）＋算力（钱投到哪）四个旋钮的联合调节。与之相对的**流水线模板**，是把别人公开的阶段图原样接上电源就指望它出活——四个旋钮一个都没调。章名里的「不是」，否定的正是这种接电式复用。

> **本章只解决一件事：面对一个目标模型，如何选择训练路线、编排训练阶段、管理模型族并形成可审计的投入决策？**

本章的推导路线，也是全专题的收束顺序：

```text
第 1 节   训练路线分诊：从"要不要训"开始的决策树
    ↓
第 2 节   阶段编排：流水线是结果，不是模板（GLM-5 sequential RL）
    ↓
第 3 节   复用、继续训练还是从头训练（GLM-5.3 / K3.1 Pro / Inkling）
    ↓
第 4 节   模型族与开放策略（开源阵营洗牌；开放≠透明≠可部署）
    ↓
第 5 节   算力战略（FLOPs→卡时→费用；隐藏乘数；训推配比）
    ↓
第 6 节   Capstone：完整九段 Training ADR 与一次微型推演
```

本章大量回指前面各章：预算三本账（[T02](/tutorial/t02-scaling-budget-three-ledgers/)）、数据配方与 mid-training（[T03](/tutorial/t03-data-recipe-quality-synthesis/)）、Checkpoint 状态机（T05）、示范与蒸馏（T06）、偏好（T07）、RLVR 前提（T08）、Agentic RL 成本（[T09](/tutorial/t09-agentic-rl-environment-credit-async/)）、发布门禁（[T10](/tutorial/t10-safety-spec-evaluation-gate/)）。它们在这里合体。

## 一、训练路线分诊：从「要不要训」开始

### 1. 最贵的错误发生在分诊台

训练决策里最贵的错误，通常不是「选错了算法」，而是**选错了层级**：在不需要训练的地方启动了训练（预算全烧在复现一个 RAG 就能补的能力上），或在需要从头建设的地方贴了一片 LoRA（六个月后撞上能力天花板，前期投入全部沉没）。

分诊的逻辑只有一句话：**先定位「差距」的性质，再选路线**。模型的差距有几种完全不同的成因——缺知识、缺行为、缺品味、缺成功率、缺长程行动力——每类成因对应不同的药，且药的副作用不同：

```text
差距诊断（先做，花的是评测预算，不是训练预算）
    ├─ 缺知识/事实 ──────── 检索可补 → 不训练：Prompt / RAG / 工具调用
    ├─ 缺行为/格式/话术 ─── 示范可教 → LoRA / SFT（T06）
    ├─ 缺领域词汇与知识底子 语料可喂 → 继续预训练 / mid-training（T03）
    ├─ 答案都对但"不稳" ─── 偏好可排 → 偏好优化（T07）
    ├─ 任务可验证但不熟练 ─ 奖励可算 → RLVR（T08）
    ├─ 要在环境里连续行动 ── 轨迹可采 → Agentic RL（T09）
    └─ 以上全都够不着 ────── 才考虑从头训练（T02--T05 全套）
```

### 2. 七级路线对照表

| 路线 | 适合的差距 | 先决条件（不满足就退一级） | 主要代价 | 主属章 |
|---|---|---|---|---|
| 不训练：Prompt／RAG／工具调用 | 知识与事实类差距，模型能力已够 | 有检索库或工具 API；差距能被「查到」补上 | 检索与运维工程；无训练账 | T04（长上下文与 RAG 的边界） |
| 轻量适配：LoRA／PEFT | 行为、格式、领域话术 | 底座已具备能力种子 | 写入深度有限，上限受底座约束 | T06 |
| 全参 SFT／蒸馏 | 任务模式可由示范表达 | 有高质量示范；模型容量足够 | 数据工程＋遗忘管理 | T06 |
| 继续预训练／mid-training | 缺领域知识与词汇 | 数据与 Tokenizer 兼容；配回放 | 通用能力回退风险最大 | T03 |
| 偏好优化 | 输出「都对但不好」 | 偏好可定义、可标注 | 评分器偏差与过优化 | T07 |
| RLVR | 任务可验证、成功率待提升 | 验证器可靠＋基座有能力种子 | 采样账与反投机监控 | T08 |
| Agentic RL | 长程环境任务 | 环境四件套与异步拓扑齐备 | 环境账＋Policy Lag 管理 | T09 |
| 从头训练 | 以上全部够不着能力下限 | 数据、算力、团队、合规、差异化五重门槛 | 预训练主线全套成本 | T02--T05 |

七级不是「先进程度排名」，而是**介入深度与成本的阶梯**。每升一级，账单按数量级上翻，可回滚性按数量级下降——LoRA 训坏了删掉适配器就完事，从头训练走错了是整个季度的集群时间。

> **判断边界：**分诊不是一次性的入园检票，而是每个阶段门禁前的复检——能力目标变了、底座换了、预算砍了，都要重走决策树。
>
> 上一轮的分诊结论只值它当时的证据；把它当作永久判级的团队，会在第三阶段发现自己在用第一阶段的地图走新路。

### 3. 从头训练的五重门槛

分诊树的最底端之所以画得最谨慎，是因为「从头训练」要同时过五道门：

| 门槛 | 要回答的问题 |
|---|---|
| 数据 | 是否有足够体量、且可治理（许可、隐私、污染控制）的独有或可处理语料？ |
| 算力 | 三本账是否复算得出来，且组织付得起研发乘数（第 5 节）？ |
| 团队 | 数据、训练系统、后训练、评测四套工程能力是否齐备？ |
| 合规 | 安全、版权、隐私与目标市场的监管要求是否可满足（T10）？ |
| 差异化 | 现有开放权重＋本分诊框架的上面六级，是否真的够不着目标？ |

2026 年的现实是：开放权重已经把「中档能力」变成免费公共品（第 4 节），五重门槛过不去的团队，正确的战场在六级阶梯的中段，不在最底端。反过来说，[Inkling 2 Small](https://thinkingmachines.ai/news/inkling-2-small) 这类项目展示了门槛过得去时从头训练能买到什么：一套完全按自己部署形态与数据管线定制的底座（594B 总参／17B 激活 MoE，Apache 2.0；权重截至 2026-11-05 待外部安全测试后发布）。

### 4. 「不训练」也是一路线：RAG 与训练的边界

分诊树的最顶端最容易在评审会上被跳过——「我们是要做训练决策的，不训练算什么方案」。但它恰恰是最该先算的一级，因为它与训练路线的对比维度完全不同：

| 维度 | RAG／工具调用 | 训练（各级路线） |
|---|---|---|
| 知识更新 | 索引库即时更新，文档变了立即可见 | 每次更新要再训，存在知识过期的半衰期 |
| 单请求成本 | 检索开销＋长上下文推理 | 模型「记得」知识，请求更短，但训练账前置 |
| 引用与审计 | 天然给出处，可溯源到文档 | 知识融在参数里，出处要靠额外机制 |
| 行为塑造 | 几乎无能为力（格式、风格、任务模式） | 这正是训练的主场 |
| 私有数据治理 | 数据留在检索库，权限模型清晰 | 数据进入权重，删除与合规都变难 |

三个典型判例（教学归纳）：

- **知识每周变** → 训练是贵的错误解：任何「训进去」的知识都在过期；
- **答案必须给出处** → RAG 的结构优势，训练反而要补一套引用机制；
- **输出格式与任务模式不稳** → RAG 几乎无解，这是 SFT 的主场。

所以分诊的第一问永远是：「差距是**知道什么**，还是**怎样做**」——前者先给检索，后者才给训练。两者常并存（合同助手既要查条款又要稳定抽取格式），那就分层给药，每一层的预算分开记。

> **架构智慧：**分诊的输出不是「一条路线」，而是「一条路线＋两条被否决的路线＋否决理由」。否决理由写在纸面上，三个月后能力需求变化时，你才知道该激活哪条备选——这正是本章 Capstone 里 ADR 第 8 段的雏形。

## 二、阶段编排：流水线是结果，不是模板

### 1. 一张阶段图，和它的正确读法

把全专题的阶段放回一张图上：

```text
预训练（T02-T05）
    ↓ 交付：Base Model ＋ Checkpoint ＋ 能力基线（引言的接口约定）
mid-training（T03）：预训练末期定向数据加码（可选）
    ↓
SFT／蒸馏（T06）：格式、行为、任务模式
    ↓
偏好优化（T07）：定义"更好"
    ↓
RLVR（T08）：可验证任务强化
    ↓
Agentic RL（T09）：环境中的长程任务
    ↓
安全与评测门禁（T10）：晋级 / 打回 / 回滚
    ↑__________跨阶段修复：回放、混合训练、on-policy 蒸馏__________↑
```

这张图是**一种可能的顺序，不是所有模型都必须经过的固定流水线**。每个箭头都是一次「交接物验收」：上一阶段的产物（Checkpoint＋能力基线）不过关，下一阶段的方法救不回来。阶段可以跳过（不需要偏好的任务直接进 RLVR）、可以并行（多条能力线各自训练再合并）、也必须为顺序付费——付费凭据就是下面这个案例。

### 2. 主案例：GLM-5 的 sequential RL 全配方

[GLM-5 技术报告](https://arxiv.org/abs/2602.15763)（2026-02，官方技术报告的 arXiv 预印本；744B 总参／40B 激活，预训练 28.5T Token，MIT 开放权重）公开了它完整的后训练编排——「sequential RL（顺序 RL）」是 GLM 对自家三阶段顺序的称呼，不是业界标准术语：

| 阶段 | 内容（官方报告口径） | 编排风险 |
|---|---|---|
| SFT | 扩展 agent／coding 数据；引入三种思考模式 | 为后续 RL 建立行为底座 |
| Reasoning RL | 推理能力强化 | 后续阶段会侵蚀本阶段成果 |
| Agentic RL | 真实 issue-PR 对、Docker 化终端、web 知识图谱环境 | 同上 |
| General RL | 通用能力收束 | 继续挤压前段技能 |
| On-policy 跨阶段蒸馏（OPD） | 修复顺序 RL 造成的早期能力回退 | 官方明确承认回退存在，蒸馏段负责修复 |

这张表最值钱的一行是最后一行：**官方自己承认，多阶段顺序 RL 会侵蚀前段技能，需要专门的蒸馏段把早期能力拉回来**。「先训 A 再训 B 再训 C」不是免费的串行清单——每进一个阶段，都在拿前面的阶段当下注。

用一组教学示意数字（纯示意，非任何真实模型的分数）画出这个形状：

| 能力维度 | SFT 后 | Reasoning RL 后 | Agentic RL 后 | General RL＋蒸馏后 |
|---|---:|---:|---:|---:|
| 推理基准 | 71 | 82 | 74 | 81 |
| Agentic 基准 | 32 | 35 | 58 | 57 |
| 通用指令 | 68 | 70 | 63 | 69 |

形状比数字重要：**每一列的冠军都会在下一列被侵蚀**，末段的修复把前段拉回来一部分，但不一定回到峰值。这就是「流水线是结果」的含义——GLM-5 的四个阶段＋一个修复段，是它的任务组合、数据储备和算力窗口解出来的解，不是可以整条抄走的模板。

### 3. 对照案例：Inkling 的「数据阶段」编排

同一个 2026 年，[Inkling 2 Small](https://thinkingmachines.ai/news/inkling-2-small) 公开的是另一种编排——它编排的主轴不是「信号」，而是「数据质量梯度」（口径均为官方披露，2026-11-05 页面）：

| 阶段 | 内容 | 关键数字 |
|---|---|---|
| H1 预训练 | 常规大规模混合 | 8.4T Token；GB300 NVL72 机架 68 小时；原生 NVFP4 |
| H2 | 未见过的更高质量新数据 | 3.8T Token；上下文扩到 512K |
| H3 | 推理＋Agent 轨迹 | 约 320B Token；上下文扩到 1M |
| H4 | 最高质量轨迹（主要采样自 Kimi K3 及自家早期模型，经正确性与对齐过滤） | 约 34B Token |
| RL | 单次联合 RL Run | 1,075 步、超 17M Rollout、9 天；sampler : trainer = 5 : 3 |

两个案例并排，能读出编排的三条通用律：

- **编排轴不止一根**。GLM-5 沿「信号类型」切阶段（示范→三类 RL），Inkling 沿「数据质量与上下文长度」切阶段（H1→H4 再 RL）。切法由你手里数据的形态决定，不由论文目录决定；
- **阶段边界＝数据边界**。每个阶段的进入条件都是「下一档数据已备好且验证过」——H3 的 320B 轨迹、H4 的 34B 精选轨迹都是要花钱生成的（约 354B Token 的轨迹数据本身就是算力换来的）；
- **越往后越贵 per Token**。从 8.4T 到 34B，Token 数骤降而质量门槛骤升——编排的后段买的是「密度」不是「数量」，这与 T03 的数据分层结论完全一致。

顺带注意 H4 的一个细节：它的轨迹主要采样自 Kimi K3——**跨厂商蒸馏是开放的，编排里可以直接消费别家开放权重当 Teacher**。这是第 4 节「开放阵营」给编排者的直接红利。

### 4. 用能力矩阵决定下一阶段

编排的正确驱动器是**能力矩阵**（T03 引入、T10 收束为证据组）：每一阶段结束，跑一遍「目标能力＋非目标能力＋安全」的矩阵，然后问三个问题：

```text
① 目标能力还差多少？差距属于分诊树上的哪一类？（决定下一阶段用什么信号）
② 哪些非目标能力回退超阈值？（决定是否先回放/蒸馏修复，再前进）
③ 继续训的边际收益 vs 换方案的切换成本？（决定"再加一个阶段"还是"收工发布"）
```

支撑修复的三件工具，全部来自前十章：**回放数据**（把上一阶段的样本混进本阶段，T03）、**混合训练**（多阶段数据同批共训）、**跨阶段蒸馏**（用早期 Checkpoint 当 Teacher 采样新数据，或直接 on-policy 蒸馏，T06）。它们是编排的「利息」——顺序训练欠下的能力债，用它们偿还。

### 5. 编排的物料管理：数据、Checkpoint 与尺子

阶段图只画了箭头，没画箭头下面流动的物料。三个物料对象决定编排能不能真正跑起来：

- **数据复用池**：每个阶段的数据进版本库登记（来源、许可、清洗规则、配比——T03 的质量记分卡），下一阶段从池子里取回放样本。没有版本库的团队，回放只能「大概混一点旧数据」，修复强度不可控；
- **Checkpoint 谱系**：每个阶段的起点与终点快照入谱系树（T05 的 Checkpoint 状态机：参数＋优化器状态＋数据游标＋RNG），后训练的每个分支从谱系上的明确节点出发。回滚不是「回到过去」，是「切换到谱系上的另一个节点」；
- **冻结的尺子**：金标集与回归集在整个编排开始前冻结，所有阶段对着同一把尺子量——尺子中途更换，能力矩阵就断了序列，「回退了多少」无从谈起。

```text
底座 ckpt-0 ── SFT ── ckpt-1 ── RLVR ── ckpt-2（候选发布）
                │                   │
                └── 分支 B（另一切入点）└── ckpt-2'（回滚备胎：SFT 终点＋修复混合）

数据池：v1 示范集 ─┬─→ SFT 主用
                   └─→ RLVR 阶段按 15% 回放（比例是实验变量，不是常数）
尺子：金标集 v1（冻结）── 所有阶段统一评测 ── 发布门禁引用
```

三个物料对象合起来回答一个问题：**编排出事的时候，你能不能退回一个已知状态？**答案是「能」，当且仅当谱系、数据版本、评测尺子三样都在。这也是 Capstone 里 ADR 第 9 段（回滚与退出条件）的物质基础——没有物料管理的回滚条款只是愿望。

> **架构智慧：**别人公开的训练流水线是他的解，不是你的题。复用前先走一遍「任务形态→数据形态→方法假设→系统拓扑」因果链（T01 的错误 4）：GLM-5 需要三个 RL 阶段是因为它的能力目标是 agentic engineering 全谱系；如果你的目标只有其中一角，抄全配方就是在为用不到的阶段付费——还附赠了顺序回退的修复成本。

## 三、底座演进：复用、继续训练还是从头训练

### 1. 下一版模型的三岔口

模型族的每一次迭代都站在同一个三岔口：**复用底座只动后训练**、**在旧底座上继续预训练**、**从头训练新底座**。2026 年的公开案例恰好把三条路都照亮了：

| 案例 | 底座决策 | 改了什么 | 结果（官方口径） |
|---|---|---|---|
| GLM-5.3（2026-08） | 复用 GLM-5.2 底座，不重训 | 重写整个后训练流水线 | TB3.0 4.6→28.3；DeepSWE v1.1 46.2→66.9；Agents' Last Exam 23.8→28.5；ExploitBench 翻倍 |
| Kimi K3.1 Pro（2026-10-23 发布） | 复用 K3 底座（2.8T 总参／104B 激活） | 官方博客称在数百个任务上做大规模联合 RL，大幅加注后训练算力 | Agent Arena 开源权重第一；TB4.0 65.7%（含 86 个 CLI 任务）；AA Intelligence Index 第 4 |
| Inkling 2 Small（2026-11-05） | 自家底座全管线推进 | H1 预训练 8.4T → H2 新数据 3.8T（512K 上下文）→ H3 约 320B 推理与 Agent 轨迹 → H4 约 34B 最高质量轨迹 → 单次联合 RL | H1 仅 68 小时（GB300 NVL72，原生 NVFP4）；RL Run 9 天、超 17M Rollout |

（K3.1 Pro 各分数口径：官方博客与 Artificial Analysis 汇总，2026-11 时点；TB4.0 与 TB3.0 是不同版本，分数互不可比。）

两个「同一底座纯后训练刷新旗舰」的案例（GLM-5.3、K3.1 Pro）互相印证了同一件事：**当代底座的潜在能力池，远没有被预训练终点榨干**。后训练是更便宜的迭代杠杆——不动预训练账单，一两个月就能刷出新一代。但杠杆的方向有限制：

> **判断边界：**后训练放大的是底座已有的能力种子，不能无中生有。T08 的前提二在这里以更大的尺度重演：GLM-5.3 的六倍发生在终端类任务上，正是因为那个底座在这类任务上有足够的种子。复用底座前，先按第 1 节的分诊逻辑给底座做「种子体检」——目标能力在底座上的 pass@k 如果全面为零，后训练杠杆再长也撬不动。

### 2. 三条路的账与险

| 维度 | 复用底座＋后训练 | 继续预训练／分支 | 从头训练 |
|---|---|---|---|
| 预训练账 | 不发生 | 部分（新增 Token 按 6ND 计） | 全额＋研发乘数 |
| 迭代周期 | 周到月 | 月到季 | 季到年 |
| 能力上限 | 受底座种子约束 | 可扩知识面，架构不可换 | 全部自定 |
| 兼容性负担 | 最小 | Tokenizer／数据分布须验证 | 无（自建） |
| 回滚成本 | 低（回到旧后训练 Checkpoint） | 中（可能污染底座） | 高（整条主线） |
| 适合谁 | 底座达标、拼编排 | 领域知识缺口大 | 五重门槛全过 |

### 3. 兼容性检查表：继续训练前的六道闸

选择「在已有底座上继续训练」（无论自家的还是开放权重的），开工前过一遍：

| 检查项 | 查什么 | 不过关的后果 | 主属章 |
|---|---|---|---|
| Checkpoint 完整性 | 参数＋优化器状态＋数据游标＋RNG 是否齐全 | 断点无法续训，进度作废 | T05 |
| Tokenizer 兼容 | 词表、压缩率、特殊 Token 是否延续 | 新语料分词失真，embedding 错位 | T03 |
| 数据分布兼容 | 新语料与底座训练分布的偏移有多大 | 灾难性遗忘 | T03／T06 |
| 架构兼容 | 注意力／专家结构、并行切分是否仍适用 | 系统方案重做 | T04／T05 |
| 许可证与治理 | 底座 license 允许的再训练与商用范围 | 法律与合规风险 | T10 |
| 能力基线 | 底座在目标任务上的种子水平 | RL 阶段无从探索成功轨迹 | T08 |

最后一行常被漏掉，却是三条路共同的隐形前提。模型族的版本管理因此有了明确形态：每个分支（下一节）持有自己的 Checkpoint 谱系、能力基线快照与回归测试集——发布策略不是「哪个分数高发哪个」，而是「哪个分支过了 T10 的证据组」。

### 4. 什么时候必须换底座：五个换座信号

复用底座便宜，但便宜恰恰是它最大的陷阱——团队会在底座已经不够用之后，继续在后训练上追加投入。以下任何一个信号出现，就该把「换底座」提上评审，而不是再加一个后训练阶段：

| 信号 | 判据 | 为什么后训练救不了 |
|---|---|---|
| 种子缺失 | 目标能力的 pass@k 在底座上全面为零（T08 前提二） | RL 探索不到成功轨迹，SFT 只能教格式不能教能力 |
| 结构性缺口 | 底座没有目标模态、上下文或输出长度量级 | 预训练决定的属性，后训练只能微调不能新建 |
| 训推账失衡 | 后训练迭代越快，推理摊销账越难看（部署形态变了） | 底座的激活参数与体积是预训练定死的 |
| 许可证／供给风险 | license 条款变化、权重下架、硬件供给受限 | 法律与供应链问题不在梯度下降的射程内 |
| 迭代天花板 | 连续两轮纯后训练刷新，目标基准增幅持续收窄 | 底座能力池见底的直接观测 |

第五条信号值得展开一句：GLM-5.2→GLM-5.3 的六倍是「同一底座第一轮重写后训练」的收益；它不能推出「第二轮重写还有六倍」。复用路线的收益天然递减——每次刷新消耗的都是同一个预训练种子池。把「第一轮的六倍」当作复用路线的常态期望，是本章错误 2 的变体。

> **判断边界：**换底座是战略级决策（季度尺度、预训练级预算），复用后训练是战术级决策（周月尺度、后训练级预算）。两者不该在同一个评审会上投票——把战术评审拖成战略辩论，或用战术预算拍战略决策，都是编排失序的典型症状。

## 四、模型族与开放策略：你的底座从哪来

### 1. 模型分支：一个底座长出的一树产品

当代模型厂从同一底座派生出一族分支，分支的划分维度是**部署形态与任务域**，而不是「谁更新」：

| 分支 | 定位 | 2026 年的公开锚点（示例） |
|---|---|---|
| Base | 预训练原始交付物，供下游再训练 | GLM-5（MIT 权重；28.5T Token 披露） |
| Instruct／通用 | 指令遵循与通用对话 | 各家旗舰的默认形态 |
| Reasoning | 推理增强、多档思考模式 | GLM-5 在 SFT 阶段引入的三种思考模式 |
| Coding／软件工程 | 代码与仓库级任务 | GLM-5 的 agent／coding 数据扩展；DeepSWE 一系的评测对象 |
| Agent | 长程工具与环境任务 | GLM-5.2／5.3；Kimi K3.1 Pro（主打长程 agentic） |
| Small／Flash | 端侧与小部署 | LFM2.5-350M（28T Token，约 80,000:1 配比，体积 <500MB） |

分支不是营销分类，而是**算力战略的产物**：端侧分支的存在理由是部署形态倒推（T02 第 6 节），Agent 分支的存在理由是采样与环境的账单结构（T09）。给自家产品线画分支图时，每个分支都应该能回答「它的部署约束是什么」——答不上来的分支通常活不过一代。

### 2. 开源阵营洗牌：2026-11 快照

底座从哪来，取决于开放阵营给你什么。而这张地图在 2026 年被重画过：

| 阵营 | 2026 年的关键动作 | 口径 |
|---|---|---|
| Meta MSL | 2026-06-02 发布新旗舰**无开放权重、不再更新 Llama 开源线**；2026-08-05 发布 Muse 系列；截至 2026-09 无 Llama 5 的发布或官方宣布；另有报道称部分产品改用 Google/OpenAI 模型 | 公开报道与维基条目口径 |
| Qwen | [Qwen3.8-Max](https://qwen.ai/blog?id=qwen3.8)（2026-08）**首次把 Max 级模型开放权重**：2.4T 总参／约 95B 激活；上一代 Qwen3.5 旗舰（2026-02）为 397B MoE——一代之内开源旗舰从 0.4T 级跳到 2.4T 级 | 官方博客 |
| Kimi | K3（2026-07）开放权重（MXFP4 量化）；K3.1 Pro（2026-11）复用底座＋联合 RL 后开放权重 | 官方博客与技术报告 |
| Mistral | [Large 4](https://mistral.ai/news/mistral-large-4-oss)（2026-10-29）1.05T 总参／52B 激活，modified MIT，**官方技术报告随权重一起发布** | 官方发布 |
| Z.ai | GLM-5（2026-02）MIT 权重，28.5T Token 与 sequential RL 配方披露 | 技术报告 |

**它意味着什么**：老的常识「Llama＝开源旗舰的默认参照」已经失效——Llama 只保留为开源权重生态起点的历史锚点；开源前沿改由 Qwen3.8-Max、Kimi K3／K3.1 Pro、Mistral Large 4、GLM-5 构成，旗舰开源参数量级从 1T 级迈入 2--3T 级。同时闭源回潮是真的（Meta 一侧），开放加码也是真的（Qwen 把 Max 级放进开放阵营）——两件事同时成立，所以任何「开源已死」或「开源已赢」的单边叙事都过不了这张表。

这张表还要带快照纪律读：它按 2026-11 时点整理，阵营与旗舰的代际在按月变化（例如 Qwen4 截至 2026-11 尚未正式发布，传闻参数一律不进正文）。引用任何「当前阵营」表述，都要写核查日期——这是 T02「时间维度」纪律在战略层的重演。

### 3. 开放的三层区分：权重、账本、部署

「开源」这个词在 2026 年至少压着三个独立命题，混用会直接做错底座选型：

| 命题 | 问的是什么 | 2026 年的反例（证据） |
|---|---|---|
| 权重开放 | 能否拿到参数文件与可商用许可证 | Inkling 账本全开，权重截至 2026-11-05 待外部安全测试后发布 |
| 训练透明 | 能否复算它的训练账本与配方 | K3 权重开放，但训练 Token 数、卡时、数据构成未披露（第三方分析确认此缺口） |
| 可自部署 | 普通硬件能否把它跑起来 | K3.1 Pro 开放权重约 5.6TB（报道口径），消费级硬件难以承载 |

第三行是 F18 纪律所在：[Kimi K3.1 Pro](https://huggingface.co/moonshotai/Kimi-K3.1-Pro) 的权重文件约 5.6TB（2026-11-05 开放，iThome 报道口径）。**它意味着什么**：这个体积远超消费级硬件的存储与显存能承载的范围。但纪律要双向写——**开放权重不等于普通硬件可部署**（不能因为「开源了」就假设自己能跑）；同时也**不能从文件大小一步推断「绝对不可部署」**：量化版本、推理框架支持、集群租赁都在改写部署门槛。文件大小只是把「部署是一道独立的工程题」这件事拍在了桌面上。

同样地，第二行决定了「参照谁学习预算决策」：GLM-5 披露 Token 无卡时（外部可估 FLOPs、估不了卡时），Inkling 三本账可勾稽（T02 第 5 节的披露分层表），K3 只有架构没有账本。借部署找权重开放的，借方法找账本开放的，借结论要克制。

> **架构智慧：**底座选型评审只该问三个问题，对应三层：许可证给不给（权重）、账本教不教得了你（透明）、部署门槛过不过得去（工程）。三个答案都是「是」的候选不存在——2026 年没有同时满分的三好学生，选底座就是在三个不完全的圆里找交集。

### 4. 你的开放策略站位：消费者、参与者还是供给者

开放阵营重画之后，每个训练团队其实要选一个「站位」——你与开放生态的关系是什么。三种站位的动作与风险完全不同：

| 站位 | 典型动作 | 主要收益 | 主要风险 |
|---|---|---|---|
| 消费者 | 用开放权重当底座（第 3 节三岔口的「复用」） | 省掉预训练账；迭代杠杆全在后训练 | 底座供给与许可证的变化（换座信号第 4 条）；与所有人共用同一底座，差异化要靠数据与编排 |
| 参与者 | 像 Inkling 一样消费别家权重当 Teacher（H4 采样自 K3），或向上游回馈数据与评测 | 站在开放生态的能力池上做编排 | Teacher 的偏差与许可边界会流进自己的管线（T06 蒸馏章的风险清单） |
| 供给者 | 像 Mistral Large 4 一样开放权重＋技术报告，用生态换影响力 | 生态位、口碑、下游反馈 | 配方被竞品复用；权重被滥用带来的安全与声誉成本（T10 的 dual-use 议题） |

站位不是三选一的终身身份，而常是同一家公司在不同产品线上的并行选择。但**每条产品线必须写明自己的站位**——消费者的预算表里不该出现「维护开放生态」的隐性成本，供给者的决策里也不该假装自己是纯消费者。

结合第 2 节的阵营表再读一遍：Meta 闭源转向与 Qwen 开放 Max 级，本质是两家公司站在供给者站位上做了相反的注。而你的注不必和他们任何一家相同——站位选择只服从你自己的能力目标、预算与风险边界，这正是引言第 1 层先于第 7 层的又一次重演。

## 五、算力战略：从 FLOPs 到费用的整机账

### 1. 换算链：T02 的链条加上后训练的三行

T02 建立了「FLOPs→卡时→费用」的三层换算。整机视角下，链条向下再延伸三行：

```text
训练目标（能力＋部署形态）
    ↓ 6ND 粗估（T02，MoE 用激活口径）
FLOPs（可复算层）
    ↓ ÷（GPU 数 × 单卡峰值 × MFU）
卡时（要靠系统假设，T05）
    ↓ × 卡时单价
费用（要留区间）
    ↓ × 隐藏乘数
研发账（最终 Run 只是少数）
    ↓ ＋ Rollout 采样 ＋ 环境吞吐 ＋ 评测门禁（常驻项，T09/T10）
整机算力战略
```

### 2. 隐藏乘数：最终 Run 背后的账

[Epoch AI 的分析](https://epochai.substack.com/p/final-training-runs-account-for-a)（2026-03）估算了 OpenAI、Z.ai、MiniMax 三家的研发算力结构：**最终训练 Run 只占研发算力总支出的少数**——OpenAI 约 9.6%（对应约 $5B 的年研发算力支出对约 $0.5B 的最终 Run），另一家约 22.6%；最终 Run 的算力自 2016 年以来约以每年 2.4 倍增长（95% CI 2.0--3.1）。

**它意味着什么**：把「训练一个模型的成本」只按最终 Run 计算，会系统性低估约一个数量级（1 ÷ 9.6% ≈ 10 倍）。被低估的部分全部长在隐藏乘数里：

| 隐藏乘数 | 它吃掉什么 | 展开章 |
|---|---|---|
| 故障与重启 | 恢复点之前的沉没卡时 | T05（Goodput） |
| 消融与超参扫描 | 每个组件「有没有用」的受控验证 | T03／T08 |
| 数据管线 | 清洗、合成、验证、回放的算力 | T03 |
| Rollout 采样 | RL 的生成侧，常驻训练账单 | T09 |
| 环境吞吐 | 环境启动、重置、验证、隔离 | T09 |
| 评测与红队 | 每个候选 Checkpoint 的证据组 | T10 |

两条口径纪律必须跟着这个数字走（T02 已立，这里整机重申）：

- 9.6%／22.6% 是**算力支出估算**（compute spending estimate）口径，不是实际 FLOPs 占比——支出混合了不同年份的采购价格与方式；
- 它是特定几家的估算，**不是行业常数**。乘数的正确用法是「4--10 倍区间先验＋按本团队预测台账逐季校准」，不是精确系数。

宏观刻度（[Epoch AI Trends](https://epoch.ai/trends)，2026-02-05 快照）：前沿语言模型训练算力自 2020 年起约每年 5 倍（90% CI 4--6），前沿训练成本约每年 3.5 倍。**它意味着什么**：任何「参照某模型」的算力规划都必须写上核查日期，并预期一年内失效——去年抄的配比，今年的账已经变了。

### 3. 训推配比：Rollout 是常驻账单，不是训练的尾巴

整机账里最容易被错分类的一行是 **Rollout／推理侧算力**。它不是训练结束后的「部署问题」——在当代后训练里，它是训练账单的常驻部分：

- [Inkling 2 Small](https://thinkingmachines.ai/news/inkling-2-small) 的 RL Run 披露了 sampler : trainer = 5 : 3（口径：官方披露的单次联合 RL Run）——**采样侧算力大于训练侧**。9 天、1,075 步、超 17M 条 Rollout，单条 Token 数 p50 = 43K、p99 = 1.5M（T09 已拆解过它对拓扑与缓存的要求）；
- 同一 Run 的前缀缓存命中率 93%+ 说明：**工程决策直接改写账单**——没有这层缓存，17M 条 Rollout 的采样账可能完全是另一个数量级；
- Agentic RL 任务的环境吞吐（启动、重置、验证）叠加在采样之上，是第二条常驻账（T09 的「每条有效轨迹成本」）。

再往远看一层：训练侧的 sampler 账单与部署侧的推理账单正在合流——T02 的 T²（Train-to-Test）Scaling（[arXiv:2604.01411](https://arxiv.org/abs/2604.01411)，2026-04 提交的预印本）证明，一旦把推理采样计入端到端预算，最优训练配比会大幅移入过度训练区间。**训与推不是两个预算科目，是同一本账的两个科目**——这是整机视角与单章视角最大的差别。

这条合流也给第 3 节的「换座信号」加了一条注脚：底座的激活参数同时写在训练账和推理账上，改任何一边都要看另一边。

### 4. 获取方式：租、云、合作、自建、混合

| 方式 | 适合 | 主要代价 |
|---|---|---|
| 云端租用 | 起步验证、短周期项目 | 单价最高；长期使用账单膨胀 |
| 合作训练 | 有伙伴与数据的领域团队 | 配方与数据边界的谈判成本 |
| 购置自建集群 | 稳定长期负载、数据不出域 | 资本开支＋运维团队＋供应约束 |
| 混合硬件栈 | 单一供给受限时的现实解 | 跨栈的系统适配与调优成本 |

供给约束不是假设题。DeepSeek V4（约 1.6T 参数，预训练数据超 32T Token，HF 模型卡口径）被报道为「预训练主要仍在 NVIDIA 上、部分流程适配华为 Ascend」（MIT Technology Review 口径），另有报道其 V4-Pro 由华为牵头的联合体用至少 1000 片 Ascend 芯片完成全参数后训练（SCMP 报道口径，细节待官方核实）——即便如此也只能写成「分阶段混合硬件」，不是「完全国产化」。**它意味着什么**：算力战略里「供给可得性」本身就是变量，获取方式表要按半年复核，而不是一次定终身。

### 5. 整机预算表：把 T02 的计算器扩成整机版

T02 的 Training Budget Calculator 覆盖了预训练主线的三本账。整机版在输出侧加三行——Rollout、环境、评测——并把后训练编排放进输入。用一组教学假设数字走一遍（与第 6 节团队 X 的推演同一设定：复用底座，SFT＋RLVR 两阶段；所有数字均为教学假设）：

**输入项（每项标口径）：**

| 输入项 | 假设值 | 口径 |
|---|---|---|
| 底座 | 复用开放权重，无预训练账 | 分诊结论（第 1 节） |
| SFT 数据 | 8B Token 示范 | 教学假设 |
| RLVR 任务 | 5 万任务 × 平均 8 条 Rollout | 教学假设；组式路线 |
| 平均 Rollout 长度 | 6K Token（p50 假设，按 T09 口径分档估 p99） | 教学假设 |
| 环境形态 | 轻量（无沙箱长程任务，抽取类短程） | 分诊结论 |
| 评测 | 每候选 Checkpoint 全套证据组 × 20 个候选 | T10 模板 |

**输出项（逐项可复算）：**

| 输出项 | 计算式 | 假设值 | 对应锚点 |
|---|---|---|---|
| SFT 训练账 | 6 × 激活参数 × 8B Token | 略 | 6ND（T02） |
| RLVR 训练账 | 训练步 × 批量的模型侧计算 | 略 | — |
| Rollout 采样账 | 40 万条 × 6K Token × 单 Token 采样成本 | **与训练账同量级或更大** | Inkling sampler : trainer = 5 : 3 |
| 环境账 | 短程任务，按条计价 | 小项 | 长程任务会翻成大项（T09） |
| 评测账 | 20 候选 × 证据组成本 | 常被整块漏算 | T10 |
| 研发乘数 | 以上合计 × 4 倍先验 | 区间 4--10 | Epoch 支出估算口径 |

这张表的用途不是算准，是**暴露结构**：在复用底座＋RLVR 的整机里，采样账与训练账同量级甚至更大（Inkling 的 5:3 就是实证），评测账从不该是零，研发乘数在第一次复盘后就要用实测回填。团队 X 的第一版整机表如果 Rollout 行小于训练行，最可能的原因不是任务特殊，而是忘了算它。

> **判断边界：**算力战略的输出不是「多少张卡」，而是一份带区间的预算表：FLOPs 可复算、卡时靠假设、费用留区间、乘数按先验、Rollout 与环境单列、获取方式带复核日期。任何只给单点数字的算力提案，都过不了 T02 立下的复算关。

## 六、Capstone：完整 Training ADR 与一次微型推演

引言第 9 节给过九段骨架。这里是它的整机展开：预算与模型架构新开第 2／4 段，骨架的候选方案、系统影响、验证门禁、退出条件分别并入第 8／5／7／9 段——前面的九个决策章（T02--T10）每章交付的工程产物，恰好各归一段。

### 1. 九段模板

```markdown
# Training ADR：<项目>：<决策标题>
状态：草案／已接受／已回滚　日期：　复核周期：

1. 目标能力与验收指标
   提升什么（可检验指标＋基准版本）；哪些能力不许回退；部署形态与约束
2. 预算（三本账）
   训练账／推理摊销账／研发账；每个数字标注身份（官方披露／估算／假设）与口径
3. 数据配方与治理
   来源、许可、配比、清洗规则、污染控制；能力矩阵连接数据与评测
4. 模型架构
   Dense／MoE、上下文、模态；由部署形态倒推（T04 的 Architecture ADR 摘要）
5. 训练系统
   并行、精度、Checkpoint、容错；新增组件与 GPU 角色（T05 的配置摘要）
6. 后训练编排
   分诊结论（含被否决路线）；阶段顺序与每阶段信号；回退防护（回放／蒸馏）
7. 评测与安全门禁
   证据组（目标提升／非目标不回退／无投机／受控消融）；安全评测与污染控制（T10）
8. 风险与备选
   每个候选方案的假设与失败模式；复杂度被转移到了哪里
9. 回滚与退出条件
   出现什么信号切换方案或回滚；复盘指标与预测台账的回填计划
```

### 2. 把全系列的合同助手决策拼成一份 ADR

下面延续各章末尾的合同助手项目，并补充一组可复算的场景假设。团队、基线分数、资源与时间线**全部为教学假设**，用于演示记录与比较决策，不是训练效果承诺。后训练阶段是否启动，仍取决于前一阶段验收后是否存在值得解决的差距。

**场景**：虚构的团队 X 要做企业合同审查助手。三个能力目标：条款抽取（字段级、答案可验证）、风险条款问答（要求引用原文出处）、多轮澄清对话。负载：5,000 名法务用户，日均 20 万次请求，平均每请求输入 12K／输出 2K Token。**不许回退**：通用指令遵循、安全拒绝行为。预算：一年窗口，等效 30 万 GPU 时（含研发乘数预留）＋已有的 64 卡集群。

**第一步：分诊（第 1 节的决策树）**。先花评测预算做差距诊断：开放权重＋RAG 的组合在「问答」上已达标（引用出处本来就是检索的强项）；「多轮澄清」达标；唯独「条款抽取」的输出格式与字段一致性不稳定——抽取基准 F1 为 0.62（教学假设），目标是 0.90。提示工程只把它推到 0.71。诊断结论：这是**行为差距＋可验证任务**，属于训练能解决的那一类。

**第二步：选级**。差距落在「LoRA／SFT→RLVR」两级：先用 SFT 建立抽取格式与任务模式（T06），字段一致性这类「对不对」可验证的目标再进 RLVR（T08）。不做 mid-training（领域词汇经基线检查够用）、不做偏好优化（「更好」已由字段比对客观定义）、不做 Agentic RL（任务短程、单轮可完成）、不从头训练（五重门槛里数据、算力、差异化三道都过不去）。底座选型按第 4 节三层筛选（教学假设：某个中档开放权重 MoE，许可证允许商用再训练，部署账在 64 卡集群可承受）。

**第三步：编排与门禁（第 2 节）**。候选阶段顺序：SFT（LoRA 起步验证数据质量，再评估是否需要小规模全参实验）；若独立评测仍有目标差距且验证器审计通过，再进入 RLVR（验证器＝字段级比对，组式路线成立——同一份合同可低成本采出多条可比抽取）。每阶段跑能力矩阵；防回退用回放数据。RLVR 健康监控照搬 T08（Entropy、长度投机、独立测试集）。

**第四步：写 ADR（关键段摘录）**：

```markdown
1. 目标：抽取 F1 ≥ 0.90（自建 2,000 份合同金标集，v1）；通用基准回退 ≤ 2 个百分点；
   安全评测不劣化（沿用 T10 门禁模板）
2. 预算：训练账约 4 万卡时（SFT＋RLVR，估算）；Rollout 采样约 6 万卡时
   （sampler:trainer 按 3:2 假设，待首周实测回填）；研发乘数取 4 倍先验
8. 风险与备选：
   - 方案 A（RAG-only）：假设"格式差距可被提示补齐"——实测证伪（0.62→0.71），否决
   - 方案 B（复用底座＋SFT→RLVR）：假设"底座有抽取种子＋验证器可靠"——基线验证成立，选中
   - 方案 C（从头训 7B 领域模型）：假设"200B Token 领域语料足够"——预算与团队门槛不过，否决
9. 回滚：RLVR 出现长度投机或独立集不涨 → 回退到 SFT 检查点；抽取 F1 连续两轮
   无改善 → 停止加注，复查分诊结论（差距可能其实是检索问题）
```

**备选对比**是这份 ADR 的灵魂：三条路线的假设都写在明面上，任何一条假设被新证据推翻，决策可以有序迁移，而不是推倒重来。

**第五步：时间线与门禁（教学假设的执行视图）**：

```text
第 1--2 周    基线与差距诊断：RAG＋提示工程打满，冻结金标集与回归集（T03/T10）
第 3--6 周    LoRA 快速验证示范数据质量；数据不过关就地修数据，不进全参
第 7--10 周   全参 SFT（小规模）＋能力矩阵验收；通用回退 > 2pp 则回放重训
第 11--16 周  RLVR：组式路线，字段比对验证器；健康监控照搬 T08
第 17--18 周  T10 证据组全跑：目标、非目标、安全、消融；过门禁才发布
贯穿始终     预测台账逐周回填：每项成本与指标的实际值 vs 预测值
```

| 门禁 | 阈值（教学假设） | 不达标动作 |
|---|---|---|
| 抽取 F1（金标集 v1） | ≥ 0.90 | 差距 > 5pp 时复查分诊（可能缺种子，而非训练不足） |
| 通用基准回退 | ≤ 2 个百分点 | 回放混合重训一次；仍超则降级发布范围 |
| 安全评测 | 不劣于底座 | 直接阻断发布（T10 的一票否决项） |
| RLVR 健康 | Entropy 无塌缩、独立集同向提升 | 回退到 SFT 检查点，排查奖励可投机性 |
| 预算 | 累计卡时 ≤ 阶段预算 × 1.2 | 触发第 9 段退出条件评审 |

时间线里藏着一个容易忽略的编排细节：**金标集与回归集在第 1--2 周就冻结**。后训练的每个阶段都要对着同一把尺子量——尺子中途一换，十八周的能力矩阵就断了序列，回退无从谈起。

> **架构智慧：**ADR 的价值在三个时刻最明显——立项时（第 8 段逼你列备选）、评审时（第 7 段逼你亮证据组）、复盘时（第 9 段的回滚信号就是下一次决策的起点）。写得痛苦的地方，恰恰是它挡住事故的地方。

## 七、七种最常见的错误判断

这七种错误没有一种是新发明——它们是前十章各自失败模式在整机层的汇合：分诊错误来自 T01 的「复制答案」、口径错误来自 T02 的账本纪律、三层混同来自开放生态的旧习惯、Rollout 漏算来自 T09 的成本结构。整机决策把十个现场的失败模式压进同一次评审，出错的机会也放大了十倍。

### 错误 1：把别人的阶段流水线当模板抄

GLM-5 的「SFT→三个 RL→OPD 修复」是它的任务组合与算力窗口解出的解，且官方自己承认顺序会侵蚀前段技能。抄全配方等于为用不到的阶段付费，还附赠修复成本。**纠正动作**：用能力矩阵决定下一阶段，每阶段写交接物验收。

### 错误 2：把「同一底座六倍」读成「后训练万能」

TB3.0 从 4.6 到 28.3 是单一基准族、官方口径的量级变化，不可外推到所有任务；同次后训练还带来 ExploitBench 翻倍的安全面变化。**纠正动作**：引用时带基准版本与限定；能力与风险一起看（T10）。

### 错误 3：权重开放＝训练透明＝可自部署三层混同

K3 权重开放而账本未开；Inkling 账本全开而权重待发布；K3.1 Pro 权重开放但约 5.6TB 的体积超出普通硬件承载。三个命题各自独立。**纠正动作**：底座选型按三层分别打勾。

### 错误 4：只算训练账，Rollout 与环境费用记到「以后」

sampler : trainer = 5 : 3 的披露说明采样侧大于训练侧；agentic 环境吞吐是第二条常驻账。把 Rollout 记到「部署阶段再说」，RLVR 的预算从第一天就是错的。**纠正动作**：训推一本账，Rollout 与环境在 ADR 第 2 段单列。

### 错误 5：把 9.6% 当精确系数用

它是特定实验室的算力支出估算口径，不是 FLOPs 占比，更不是行业常数。「1,000 万卡时 ÷ 9.6% ＝ 研发总预算」是伪精确。**纠正动作**：乘数取 4--10 倍区间先验，用预测台账逐季校准。

### 错误 6：分诊跳级

该 RAG 的上了 RL（把可检索的知识差距当成行为差距训练，数据更新还追不上文档变化）；该从头评估的贴 LoRA（六个月后撞底座天花板）。**纠正动作**：先花评测预算做差距诊断，再上训练预算。

### 错误 7：ADR 没有第 8、9 段也敢开工

没有备选方案与退出条件的决策记录，本质是「事后追认文档」。假设破产时团队只能推倒重来。**纠正动作**：立项时第 8 段必须列出至少两条被否决路线及否决理由；第 9 段的回滚信号写进训练监控的告警。

## 本章小结

- 先诊断信息、行为、能力与系统差距，保留“不训练”这一候选，再决定阶段与底座。
- 每阶段独立验收：后续训练需证明边际收益，同时记录能力遗忘、采样、环境和修复成本。
- 完整 ADR 要写清备选、预算、证据和退出条件。没有新证据支持，就不自动进入下一阶段。

## 专题收尾：把八层坐标系装进一份 ADR

十一章走完，把引言的八层坐标系与本章的九段 ADR 对上，就是这本专题的全部：

```text
① 能力目标 ──── ADR 第 1 段（T02 的可检验化 ＋ 本章的分诊）
② 训练材料 ──── ADR 第 3 段（T03 的配方与质量记分卡）
③ 学习信号 ──── ADR 第 6 段（T07 偏好 ／ T08 可验证奖励）
④ 信用分配 ──── ADR 第 6 段（T08 组式基线 ／ T09 Critic 与过程信号）
⑤ 优化方法 ──── ADR 第 6 段（T06--T09 各自的选型，收束于本章的分诊与编排）
⑥ 模型与组件 ── ADR 第 4／5 段（T04 架构 ＋ T05 系统的组件与 GPU 角色）
⑦ 系统拓扑 ──── ADR 第 5 段（T05 并行与容错 ＋ T09 异步拓扑）
⑧ 晋级证据 ──── ADR 第 7／9 段（T10 门禁 ＋ 预测台账与回滚）
预算、风险、回滚（第 2／8／9 段）横贯全部八层——它们是整机的循环系统
```

先把工作台拼起来。引言承诺过「每章交付一个可复用的工程产物，它们可以直接拼成你的工作台」——清单在此：

| 章 | 工程产物 | 在 ADR 里的位置 |
|---|---|---|
| T02 | Training Budget Calculator | 第 2 段（本章扩成整机版） |
| T03 | Data Recipe ＋ Data Quality Scorecard | 第 3 段 |
| T04 | Model Architecture ADR | 第 4 段 |
| T05 | Distributed Training Configuration | 第 5 段 |
| T06 | SFT／Distillation Strategy | 第 6 段 |
| T07 | Reward Model Design ＆ Calibration Report | 第 6 段 |
| T08 | RLVR Training Plan | 第 6 段 |
| T09 | Agent Environment Specification | 第 5／6 段 |
| T10 | Safety ＆ Evaluation Gate | 第 7 段 |
| T11 | End-to-End Training ADR（整机） | 全文 |

然后，从今天起怎么用这本专题：

1. **带着一份空的 Training ADR 倒查。**遇到任何训练提案，先填第 1 段（目标可检验吗？不许回退什么？），卡在哪一段，就回到对应章：预算卡在 T02、数据卡在 T03、系统卡在 T05、信号卡在 T06--T09、门禁卡在 T10——这正是引言承诺过的「按问题路线」。
2. **每个数字写口径与身份。**总参还是激活、训练 Token 还是 Rollout Token、哪个基准版本、官方披露还是估算还是假设——四选一标在数字旁边。这本专题里每一个翻车的判断，起点都是一个没标口径的数字。
3. **复用推理，不复制答案。**GLM-5 的配方、Inkling 的账本、GLM-5.3 的六倍、Epoch 的乘数——都是别人约束下的解。抄进你的 ADR 之前，先重走一遍因果链，确认约束同构。
4. **用预测台账把每次偏差变成先验。**预算会错、外推会错、分诊也会错；让它们错得可归因，下一次决策就站在这一次的误差之上。

训练决策没有终点线——每个发布的模型都是下一个底座的三岔口。但只要八层坐标系还在、九段 ADR 还在更新，你面对的就不是一团迷雾，而是一串可以逐个击破的工程问题。

回到引言的第一句话：训练方案不是算法排行榜，而是一条从能力目标到晋级证据的决策链。十一章走完，这句话现在可以补全后半句——**这条链的最后一环，是把链子本身交给下一个人：一份别人能审计的 ADR，比一个别人复制不了的模型，更有组织生命力。**

## 基础术语速查

| 术语 | 初学者可以先怎样理解 |
|---|---|
| 训练路线分诊 | 先诊断能力差距的性质，再决定不训练／微调／强化／从头训的选级过程 |
| Sequential RL（顺序 RL） | GLM-5 对自家「SFT→Reasoning→Agentic→General」多阶段后训练的称呼；官方承认顺序会侵蚀前段技能 |
| On-policy 蒸馏（OPD） | 用当前策略采样、由更强 Teacher 现场指导的蒸馏；GLM-5 用它修复顺序 RL 的能力回退 |
| 底座复用 | 新一代模型不重训 base model，只在旧底座上重做后训练（GLM-5.3、K3.1 Pro 的路线） |
| 模型族 | 同一底座按部署形态与任务域派生的分支家族：Base／Instruct／Reasoning／Coding／Agent／Small |
| 开放权重 | 能拿到参数文件与许可证；不承诺训练配方公开，也不承诺普通硬件能跑 |
| 训练透明／开放账本 | 能复算别人的训练 Token、卡时与配方——学预算决策要找这一层 |
| 训推配比 | 训练与推理（含 RL 采样）算力的分配关系；Rollout 是训练账单的常驻部分 |
| sampler : trainer | RL 训练中采样侧与训练侧的算力配比（Inkling 披露 5:3，采样侧更大） |
| 隐藏乘数 | 最终 Run 背后的故障、消融、数据管线、评测等开销，使研发账数倍于最终 Run |
| 支出估算口径 | Epoch 的 9.6% 等数字是「算力支出」的估算，不是实际 FLOPs 占比，也不是行业常数 |
| Training ADR | 九段式训练决策记录：目标／预算／数据／架构／系统／后训练编排／评测与安全／风险与备选／回滚 |
