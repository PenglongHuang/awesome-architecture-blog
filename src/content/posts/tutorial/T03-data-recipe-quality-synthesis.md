> **数据配方的价值，要用目标能力的变化衡量；数据量和清洗保留率都只是中间读数。**

读完可以从能力目标反推数据桶，并用配方表与质量记分卡检验清洗、合成和定向训练的收益。

## 开场：同样的 Token 预算，训出两个不一样的模型

先看一个工程现场(以下为教学示意场景，数字是假设的预算，不是任何真实模型的数据)。

两个团队各拿到约 **1T Token** 的预训练数据预算，目标都是"中文通用助手 + 代码 + 数学"。

- **A 团队**的做法：把预算全部换成一份通用网页抓取语料，按抓取量自然混合，训满 1T。
- **B 团队**的做法：把预算切成几份——大部分给多语言网页，但明确拨出份额给代码、数学推理材料、指令式对话和中文技术文档，最后一小段预算在预训练末期定向加码高质量的代码与数学内容。

训完后在同样的评测集上对比：两个模型的总分可能接近，但能力轮廓差别很大。A 的模型更像一个"读遍了网页的人",B 的模型在代码、结构化输出和数学任务上明显更稳，尽管它看过的"网页总量"更少。

这背后有一个被反复验证的对照：[FineWeb-Edu 的 1.3T 精选语料在评测上常能打过 10T 的原始语料](https://presenc.ai/research/open-pretraining-datasets-2026)(该汇总为数据服务商研究页，趋势与 Hugging Face 的开放模型综述互相印证；单个数字以各数据集卡片为准)。这类比较提示质量筛选可能有价值；但数据集总规模不等于实验实际消耗的 Token，不能仅凭 1.3T 与 10T 的规模差推断训练效率，仍需核对模型、训练预算与评测设置。

```text
T02 的结论:预算有限,钱要花在刀刃上
        ↓
本章的问题:同样的 Token 预算,怎么分配才叫"花在刀刃上"
        ↓
配比(给哪几类数据、各给多少)
   × 质量(每类数据长什么样、怎么洗)
   × 时机(哪些数据放在预训练末期再加)
        ↓
同一个 Token 数量级,训出能力轮廓完全不同的模型
```

所以第一条纪律先行：**配比是实验变量，不是行业固定答案。**任何"大模型都配 20% 代码"式的说法，都把别家在特定目标、特定语料池下的实验结论，误写成了可以照抄的配方。本章所有配比数字都会标注来源和口径，能复用的是推导方法，不是数字本身。

把 T02 的三本账接过来，数据预算其实有四个去向，每个去向买的东西不一样：

```text
T02 的数据预算
    ├── 买/采集新数据(买的是覆盖:新语言、新领域、新知识)
    ├── 清洗已有数据(买的是密度:同样 Token 数,信息更纯)
    ├── 合成数据(买的是定向:指定能力的材料,以及更低的单位 FLOP)
    └── mid-training 加码(买的是时机:模型定型前的最后一击)
```

本章接下来的顺序就是这四个去向的展开：先配方(花在哪)、再管线(怎么洗)、再词表(接口)、再合成与 mid-training(两个新去向)、再数据墙与受限训练(宏观约束)、最后归因(怎么知道钱没白花)。

## 一、数据配方：从能力目标反推数据组成

**数据配方(Data Recipe)**可以先理解为一张配料表：总量多少 Token,分成哪几类，每类占多少，来自哪些来源，各洗到什么质量，按什么顺序喂给模型。

### 1. 先写能力目标，再写配料表

顺序不能反。常见的错误是先盘点"手上有什么语料",把它们按存量比例混进去，最后看模型恰好会什么。正确的推导方向是：

```text
能力目标(要模型变好在哪)
        ↓
目标评测集(用什么证明它变好了)
        ↓
数据类别(哪几类材料可能喂出这种能力)
        ↓
来源与质量(每类材料从哪来、洗到什么程度)
        ↓
配比与时机(各占多少、什么阶段喂)
```

**能力矩阵**是连接"数据类别"和"目标评测"的表格，也是本章工程产物的一半：

| 数据类别 | 目标能力 | 对应评测 | 关键风险 |
|---|---|---|---|
| 多语言网页 | 通用语言、世界知识 | 通用理解/问答 | 噪声高、版权与隐私风险 |
| 代码 | 代码生成、结构化输出、推理迁移(待验证假设) | 代码基准、推理基准 | 迁移收益并未在所有设置下成立 |
| 数学与推理材料 | 符号推理、多步计算 | 数学基准 | 高质量语料天然稀缺 |
| 指令式对话 | 指令跟随 | 指令评测 | 与后训练 SFT(监督微调)数据的边界要划清 |
| 百科与工具书 | 事实性知识 | 知识问答 | 时效性、知识冲突处理 |
| 中文技术文档(中文目标时) | 中文技术表达 | 中文评测 | 中文高质量语料相对稀缺 |

### 2. 分层维度：配比不是一维百分比

配料表至少要在这些维度上各做一次决定：

- **来源**:网页抓取、代码仓库、书籍、论文、授权采购、合成。
- **领域与语言**:各领域、各语言的目标份额。
- **质量分层**:同一来源内部再分质量档，例如 OpenCSG 的中文教育语料按质量分档(约 4-5 分与 3-4 分两档，支持课程学习),[其官方页面](https://opencsg.com/blogs/794a4844-9dc5-4c57-8783-5440413def20)说明了分档设计。
- **难度与顺序**:课程学习(Curriculum)让模型先见通用、再见困难。
- **重复与采样权重**:同一份高质量语料可以重复喂，但重复有边界(本章第六节展开);更多时候用**采样权重**控制"名义占比"和"实际见到次数"的区别。**温度采样**则是在多个来源同时可采时，用温度控制配比向高质量来源倾斜的程度——温度越低，越集中在头部来源。

### 3. 代码数据：一条值得单独讲的"迁移假设"

代码在近年高性能预训练配方中的占比显著高于其在自然网页中的占比。[Toloka 2026 年的前沿实践综述](https://toloka.ai/blog/how-frontier-labs-build-pre-training-datasets)给出的经验区间是**代码约占 15-25%**——注意口径：这是该综述梳理前沿实验室公开实践后归纳的经验区间，不是行业共识数字，不同模型、不同目标的配方可以偏离这个区间。

为什么给这么多？主流解释是一个**待验证的迁移假设**:代码是天然的结构化、强因果、带反馈(能运行/不能运行)的材料，模型在代码上学到的"分解问题-组织结构-逐步求解"可能迁移到通用推理。这个假设有不少支持证据，但收益大小依赖模型规模和其余配方，不应预设"加了代码就自动涨推理分"。

### 4. 现役模型的数据披露：少到什么程度

配方是各实验室最核心的实验资产之一，公开披露极少。两个 2026 年的锚点：

- **GLM-5**:预训练数据从 GLM-4.5 的 23T Token 增至 **28.5T Token**,参数从 355B-A32B 增至 744B-A40B,这两个数字在[官方 GitHub 仓库](https://github.com/zai-org/GLM-5)可以核对；但**中文/代码/合成数据的配比未披露**——不要给 GLM-5 编造配比。
- **Kimi K3**:[技术报告](https://arxiv.org/abs/2607.24653)披露了 2.8T 总参数、104B 激活参数、1M 上下文、原生视觉、896 个专家中每 Token 激活 16 个，以及配套的"大规模任务合成"与百万 Token 级 agentic RL;但**预训练数据配方同样未披露细节**。注意单位陷阱：K3 的"2.8T"是**总参数量**,GLM-5 的"28.5T"是**预训练 Token 数**,两个"T"不是一回事，写作和阅读时最容易混。

> **架构智慧：**数据配方的第一性原理是"从要评测的能力倒推材料",而不是"从手头的语料正推能力"。能力矩阵先于配料表；配料表先于清洗管线；每一步都保留"这行配置对应哪个能力目标"的追溯链。

### 5. 配比怎么定下来：从粗到细的实验阶梯

没人能第一次就写对配比。可行的路径是一串从小到大的实验，每一级只为回答一个问题：

```text
第 1 级 小模型 + 小预算
    └─ 回答:哪些数据类别与目标能力相关?(能力矩阵的初筛)
第 2 级 固定类别,扫配比
    └─ 回答:每个类别的大致敏感区间在哪?(加 5% 代码,推理分动不动?)
第 3 级 加入质量变量
    └─ 回答:同一类别,质量档位和保留率怎么折中?
第 4 级 中等规模验证
    └─ 回答:小规模结论外推到目标规模,方向还对吗?
第 5 级 大规模训练 + mid-training
    └─ 回答:最终配方,并留下全套账本
```

两个纪律：

- **每一级都要留"预测值 vs 实际值"的记录。**小规模实验的价值不只是选配比，还校准"我们的外推有多靠谱"这件事本身(这是 T02 实验设计方法的直接复用)。
- **别在低敏感区烧预算。**如果第 2 级显示某类别从 10% 加到 15% 几乎不动指标，就别在第 5 级再为它做昂贵扫描；预算留给敏感变量。

## 二、数据管线：从原始语料到可训练数据

配方决定"要什么",管线负责"造出来"。一条典型的管线长这样：

```text
原始语料(网页 / 代码仓库 / 书籍 / 授权数据)
    ↓ 抽取与解析(HTML→正文、PDF→文本、编码修复)
    ↓ 语言与领域识别、粗分类
    ↓ 去重(精确 → 近似 → 跨来源)
    ↓ 过滤与质量打分(规则 + 质量模型)
    ↓ 隐私与版权治理(退出权、许可登记)
    ↓ 去污染(对齐评测基准)
    ↓ 分桶入库:按 来源×领域×语言×质量档 登记
    ↓ 配比与采样(按配方从各桶取数)
    ↓ 可训练数据集(带版本、带账本)
```

### 1. 去重的三个层次

| 层次 | 做法 | 抓什么 | 漏什么 |
|---|---|---|---|
| **精确去重** | 完全相同的文本(常按哈希) | 整篇镜像、重复转贴 | 改了几个字的转载 |
| **近似去重** | 指纹/最小哈希等相似度聚类 | 轻微改写的重复 | 语义相同、字面重写的副本 |
| **跨来源去重** | 不同来源合并后再去重 | 同一文档被多个语料库收录 | 成本随来源数上升 |

去重不是越狠越好。适度过滤重复能提升数据效率，但去重阈值过紧会误删"合法重复"——比如 API 文档里反复出现的示例、教材里合理的模板句。

顺序也是设计点：先精确后近似，先库内后跨来源——跨来源去重最贵，放在最后只对"幸存"语料做，能把计算量压到可承受的范围。

### 2. 质量打分与质量模型的偏差

现代管线普遍用**质量模型**给文档打分再过滤(范式起源可追溯到 FineWeb-Edu 的教育质量分类器，1.3T 精选子集由此而来)。质量模型自己也是训出来的：人工标注一小批"高质量/低质量"样例，训一个分类器，再让它给全库打分——于是**标注者的质量观，经由分类器，放大成了整个语料池的分布**。质量模型常见的偏差：

- 用"英文网页"训练的过滤器，可能系统性压低少数语言、非主流文体的分数，导致**少数语言被清洗管线吃掉**;
- "高质量"若被隐式定义为"像教科书",长尾知识、口语语料、困难样本可能整体被滤掉；
- 过滤器的偏好会直接变成训练分布的偏好——**清洗规则是配方的一部分，不是中立的基础设施**。

### 3. 怎样证明清洗有净收益：保留率 + 分维度损益

清洗的账必须这样算，而不是"洗得更干净=更好":

```text
清洗前语料池
    ├── 保留率 = 清洗后保留的 Token / 清洗前 Token
    └── 每 1% 保留率的代价与收益
          ├── 收益:通用基准、目标能力、训练稳定性(损失曲线)
          ├── 损失:被滤掉语料覆盖的语言、领域、长尾知识
          └── 对照:同配方、同预算,只改清洗强度的小规模消融
```

**保留率(Keep Rate)**是管线的核心仪表：保留率 30% 意味着七成 Token 被扔掉——它本身不说明好坏。保留率高，可能清洗保守、噪声残留；保留率低，可能误删严重。判断标准只有一个：**固定计算预算的对照实验里，清洗后语料训出的模型在分维度评测上是否净赚**。"分维度"是关键词：总分涨 1 分但某个语言跌 10 分的清洗，对一个多语言模型就是净亏。

把这套账摆成表(数字为教学示意，展示记法而非真实实验):

| 维度 | 清洗 v1(保留率 62%) | 清洗 v2(保留率 41%) | 怎么读 |
|---|---|---|---|
| 通用理解基准 | 基线 | +0.8 | v2 小赚 |
| 目标推理基准 | 基线 | +1.5 | v2 主目标达成 |
| 某低资源语言 | 基线 | -9.3 | 过滤器吃掉了该语言，净亏项 |
| 训练损失稳定性 | 基线 | 略更稳 | 次要加分 |
| 结论 | — | 加语言感知过滤后再测 | 单看前两行会误判"v2 全面更好" |

这张表就是"分维度损益"的最小形态：**每一行对应能力矩阵的一行，任何一行跌破门槛都能否决整条管线**,而不是被总分平均掉。

### 4. 开源数据集的 2026 换代：一份带口径的地图

| 数据集 | 机构 | 规模(口径) | 许可/治理要点 |
|---|---|---|---|
| FineWeb 2 | Hugging Face | ~10T(多语言过滤后) | ODC-BY,多语言 500+ |
| Common Pile | AI2 + EleutherAI + 社区 | ~8T | 显式版权清理的全许可语料 |
| Dolma 3 | AI2 | ~6T | 文档化溯源，OMLo 系列底座 |
| RedPajama 2 | Together | ~30T(raw + filtered 双口径) | 规模大，口径特殊 |
| Nemotron-CC | NVIDIA | ~6.3T(CC 高质量子集) | 质量路线 |
| Common Corpus | Common Pile 生态 | ~2T | 全部无版权/开放许可，[ICLR 2026 Oral](https://arxiv.org/abs/2506.01732),附完整溯源 |

三个提醒：第一，**Token 数不可跨库直接比较**——FineWeb 2 的 ~10T 是多语言过滤后口径，RedPajama 2 的 ~30T 是 raw+filtered 双口径，Nemotron-CC 的 ~6.3T 是高质量子集口径，并列时必须标注(本表数字来自[2026 年开源语料综述](https://presenc.ai/research/open-pretraining-datasets-2026),采用前应回各数据集卡片复核)。第二，2026 年的主趋势是**质量压倒数量、版权合规语料走红、多语言实质扩张**,The Pile 时代的"越大越好"已经让位。第三，中文这边**没有出现 2026 年的新一代开源基线**:现役锚点仍是智源 [IndustryCorpus 5T](https://aihub.caict.ac.cn/datasets/zhinao/Pretraining-Corpus-5T)(约 5T 高质量中文文本)与 OpenCSG 吴悟空系列；还有一个高频引用错误——"万卷-CC"是 **1T Token 的英文 CommonCrawl 语料**,不是中文语料，不能当中文数据案例引用。

### 5. 许可与版权治理：从加分项变成门槛

管线里的"隐私与版权治理"一环，2026 年已经从"合规加分项"变成数据集的准入门槛。宏观背景是版权诉讼与 EU AI Act 等监管框架的推进，使得"语料能不能合法用于训练"成了数据集设计的第一批问题(见[开源语料综述](https://presenc.ai/research/open-pretraining-datasets-2026)对"版权合规语料走红"趋势的梳理)。落到工程上，这一环至少包括：

- **许可登记**:每个数据桶记录来源、许可类型与采集日期，授权不明的语料不入库；
- **退出权(opt-out)尊重**:网页出版者声明不允许训练时，其内容要能从语料池里摘除——Apple AFM 3 的[数据披露](https://machinelearning.apple.com/research/introducing-third-generation-of-apple-foundation-models)就把"尊重出版者退出权"和"默认不使用用户私有数据"写成公开原则；
- **可摘除性**:许可变化时，能按来源把某批数据从训练集里整体下架，这要求前面的"分桶入库"步骤真的按来源登记过。

许可治理也解释了开源语料格局的变化：Common Pile 与 Common Corpus 这类"全部无版权或开放许可、附完整溯源"的语料之所以在 2026 年成为主线(后者拿到 ICLR 2026 Oral),正是因为它们把治理成本前置到了数据集设计阶段，而不是留给下游模型团队。

> **判断边界：**一条清洗规则、一个质量模型、一个去重阈值，只有拿出"保留率 + 分维度能力变化 + 固定预算对照"三样证据，才算证明了净收益。没有这三样，"我们清洗得更严格了"只是一条待验证的配置变更。

## 三、Tokenizer 与词表：数据、模型结构和部署成本的接口

这一节常被数据团队跳过，但它是**数据、模型结构和部署成本三者的接口**——接口选错，两头返工。

**Tokenizer(分词器)**把文本切成模型实际看到的 Token;**词表(Vocabulary)**是所有可用 Token 的清单，词表大小(常见几万到二十几万)是一个要在训练前定死的结构参数。

### 1. Fertility:同一个词，不同词表切出不同开销

**Fertility(生育率/膨胀率)**指平均每个词(或每个汉字)被切成几个 Token。它直接改写三本账：

```text
同样一段中文
    ├── 词表 A:fertility = 1.6 Token/汉字 → 训练费、推理费、上下文占用都更高
    └── 词表 B:fertility = 0.7 Token/汉字(中文词元更全) → 同样的字,更少的 Token
          ↓
有效上下文 = 标称上下文长度 ÷ 你的 fertility
部署成本   = 输入输出 Token 数 × 单价
```

这就是"接口"的含义：**数据侧的一篇文档，经过词表换算，才变成模型侧的 Token 数和账单**。中文、代码、小语种是 fertility 问题最尖锐的三类材料——代码里的缩进、变量名、罕见 Unicode 字符，如果词表没覆盖，会被切得粉碎。

### 2. 词表决策的三角权衡

| 维度 | 词表更大 | 词表更小 |
|---|---|---|
| 压缩率(fertility) | 通常更好，同样的文本 Token 更少 | 更差，罕见内容切得碎 |
| 嵌入参数量 | 词表 × 隐藏层维度的参数更多 | 更省 |
| 低频 Token 学习 | 低频 Token 训练不充分，长尾更脆 | 每个 Token 见得更多 |
| 多语言/代码覆盖 | 有空间给中文、代码、小语种 | 容易偏科英文正文 |

### 3. 换词表的兼容性代价

词表在训练中途几乎不可换：换词表意味着每个 Token 的身份全部改变，已训练的嵌入与模型不兼容，通常只能重训或做昂贵的词表扩展手术(新词元初始化 + 继续训练)。因此正确的时序是：**先定语言与模态覆盖的目标(数据配方的一部分),再定词表，再开始大规模预训练**。这也解释了为什么多语言目标明确的模型(如 GLM 系列对中文的照顾)会在词表设计阶段就投入决策，而不是事后补救。

### 4. 一个算得出钱的例子

同样的产品需求——"能一次读入 6 万汉字的技术文档并回答问题",两种词表给出两份完全不同的账(数字为教学示意，展示算法而非某款产品):

```text
需求:一次输入 60,000 汉字
词表 A:中文 fertility = 1.5 Token/字
    → 实际输入 90,000 Token
    → 需要标称上下文 ≥ 90K 的模型;推理按 90K Token 计费
词表 B:中文 fertility = 0.7 Token/字
    → 实际输入 42,000 Token
    → 标称 48K 的模型就够;推理按 42K Token 计费
```

同样的任务，词表 A 把它推上了一个更贵、上下文更紧张的档位。这也是 T02 推理账在数据侧的入口：**fertility 每差 0.1,百万级日请求量的服务就是一笔可观的成本差**。

### 5. 什么信号说明词表已经"偏科"

词表问题通常不直接报错，而是以这些症状出现：

- 某个语言的输出又慢又贵(fertility 异常高),用户先抱怨价格再抱怨质量；
- 代码缩进、罕见标识符被切得细碎，模型"看不懂"长变量名；
- 换语言后标称上下文没变，但可塞进去的文档页数明显缩水。

出现这些信号时，问题多半不在数据量，而在接口。

> **判断边界：**词表不是"模型结构"章节的附属品，而是数据配方的前置约束。评审一个预训练方案时，先问三件事：目标语言的 fertility 是多少？有效上下文(标称长度 ÷ fertility)够不够目标任务的输入？未来要加的模态/语言，词表还有没有位置？

## 四、合成数据：从补量转向能力定向

合成数据在 2026 年的角色变了：早期它常被当作"语料不够时的填量补丁",现在的定位更接近**降本变量与能力定向工具**。先看定义，再看证据，最后看风险。

### 1. 合成数据的生产管线

合成不是"生成完直接进训练集",而是一条与清洗同等重量的管线：

```text
种子材料(真实语料 / 题库 / 工具调用记录)
    ↓ Teacher 模型生成(改写、扩写、解题、构造任务)
    ↓ 过滤(质量模型 + 规则)
    ↓ 验证(可执行代码跑测试、数学答案对答案、事实核查)
    ↓ 去重与多样性控制(防止生成分布塌缩)
    ↓ 与真实数据按配比混合
    ↓ 训练 + 对照评测(合成/真实/混合三组)
```

[Toloka 2026 综述](https://toloka.ai/blog/how-frontier-labs-build-pre-training-datasets)描述的 **Web Rephrasing** 是一个典型工序：用强模型把低质网页改写成高质量文本、再加验证后入库——该方法 2024 年末提出，综述称其到 2026 年已成为前沿数据管线的常规工序(注意：这是该综述的判断，引用时归到综述名下)。同一综述还提到，人类专家数据(指令式序列、专家推理链、边界案例、对合成数据的人工抽检)已进入预训练与 mid-training,替代了"人类数据只属于后训练"的旧分工。

### 2. 证据与口径：合成到底带来什么

- **降本方向的证据**:[Epoch AI 2026-05 报告的转述](https://techjacksolutions.com/ai-brief/epoch-ai-reports-synthetic-data-gains-cut-frontier-flop-requ)称，合成数据的收益能显著降低前沿模型所需的训练 FLOP(浮点运算量)——即同样能力目标下，合成 + 高质量混合可能比堆原始网页更便宜(注意这是二手转述，引用时标注层级)。
- **占比：**2026 年**没有任何前沿实验室公布精确的合成数据占比**。Apple AFM 3 也只披露类别不给比例(见下文);GLM-5、K3 未披露。凡见到"合成数据已占 X%"的无出处百分比，应视为传言。
- **反方向的风险证据：**模型在自产数据上循环训练可能放大偏差、塌缩多样性(Model Collapse 方向的研究),质量验证不过关的合成数据会污染下游。合成数据的净效果**尚无定论**——结论高度依赖 Teacher 质量、验证强度和任务类型，双方证据都应保留。

一句话并陈双方立场：**降本方向的证据**(Epoch 转述的"合成收益降低前沿 FLOP 需求")与**风险方向的证据**(自产数据循环的偏差放大与塌缩研究)都真实存在，分歧不在"有没有用",而在"在什么验证强度、什么任务类型下净收益为正"。**尚无定论，按实验变量管理。**

因此本章的写法是：合成数据当作**实验变量**管理——真实组、合成组、混合组对照，固定预算，看分维度评测；而不是当作信仰或禁忌。

### 3. 验收纪律：为什么不能只用 Teacher 自评

Teacher 自己给自己的产出打分，等于让生产者兼质检员：它偏好自己的分布，会把"像 Teacher 的"误判为"高质量的"。验收至少要三层：可验证任务用程序验证(代码跑测试、数学对答案);不可验证任务用独立模型或人工抽检；再叠一层分布检查(多样性、难度覆盖、与真实数据的差异度量)。

### 4. 能力定向合成：任务合成的一个现役案例

"补量"之外，合成数据更值钱的用法是**能力定向**:模型缺什么能力，就定向生产围绕该能力的训练材料。[Kimi K3 的技术报告](https://arxiv.org/abs/2607.24653)披露了"大规模任务合成"——为其 general、agentic、coding 三个方向的 RL(强化学习)生产任务与轨迹，配套百万 Token 级、带持久沙箱状态的 agentic rollout。这里的教学要点不在规模，而在形态：**合成对象从"语料文档"演进到了"任务与交互轨迹"**,验证手段也从文本质量打分演进到"任务能不能被完成、代码能不能跑通"。

这带来一条新的归因义务：任务合成的好坏，最终要看用它训出的模型在**保留任务和新生成任务**上的表现差异，而不是看合成任务本身看起来多逼真——合成的分布覆盖比单个样本的质量更重要。

### 5. 三组对照怎么设计

第四节开头说"真实/合成/混合三组对照",具体长这样：

| 组 | 数据 | 回答的问题 |
|---|---|---|
| 基线组 | 全真实，固定预算 | 对照原点 |
| 合成组 | 部分真实换成合成，总 Token 与算力对齐 | 同预算下，合成替换是赚是亏？ |
| 增强组 | 真实全保留，额外追加合成(算力相应增加) | 追加合成的边际收益还剩多少？ |

常见错误是只跑"合成组 vs 基线组"就下结论：分数涨了，分不清是"合成替换有效"还是"总量变大有效";分数跌了，也分不清是合成质量差还是配比没调对。三组齐跑，才能把"替换收益"与"追加收益"分开归因。

> **架构智慧：**合成数据的正确问法不是"要不要用",而是"用合成 Token 替换/新增哪部分预算，单位算力买到多少能力"。它是预算方程里的一个价格变量，不是语料池里的免费补丁——生成有成本，验证有成本，验证不严还有负收益。

## 五、Mid-training：预训练末期的定向配方

### 1. 阶段位置：预训练末期到后训练之间

**Mid-training(中期训练)**在 2026 年的定义已经固化：预训练的最后阶段，定向加码高质量、能力导向的数据(典型是代码、数学、指令式内容),处于"通用预训练"与"后训练(SFT 等)"之间。

```text
预训练(大规模通用混合)
    ↓
mid-training(定向加码:50-500B Token 量级的高质量内容)
    ↓                                  ← 本节主角
SFT / 对齐微调(AFT)等后训练
    ↓
发布模型
```

### 2. 经济学：怎样评估这次定向投入

[Toloka 2026 综述](https://toloka.ai/blog/how-frontier-labs-build-pre-training-datasets)给出的量级是：在预训练末期加入 **50-500B Token** 的专家策划高质量内容，可带来可测的推理、指令跟随与领域任务提升；综述的原话口径是——几百万美元量级的专家策划 mid-training 数据，对下游基准的拉动，超过十倍价格追加的普通网页数据。

先解释"它意味着什么":预训练主体动辄二三十万亿 Token(如 GLM-5 的 28.5T),mid-training 只占其 1% 上下，但它出现在模型"快要定型"的时刻，学习的边际效率最高。这和人的学习类似——最后冲刺阶段读对的几本书，性价比远高于再泛读一整个图书馆。

这也解释了本专题为什么把 mid-training 称为**杠杆最高的第二次配方**:第一次配方(预训练主混合)决定模型的底盘能力，第二次配方(mid-training)以小预算在底盘上做定向增强。两次配方都要从能力目标反推，而不是同质化地"再多喂点"。

### 3. 研究案例：Anthropic 的 Model Spec Midtraining(MSM)

Anthropic 2026 年 5 月公布了 [Model Spec Midtraining(MSM)](https://alignment.anthropic.com/2026/msm)([论文](https://arxiv.org/abs/2605.02087)):在预训练之后、对齐微调(Alignment Fine-Tuning,AFT)之前，先在"讨论 Model Spec(模型行为规范)的文档"上做 mid-training,以塑造后续对齐训练的泛化方式。

注意两个纪律：

- **MSM 是特定研究提出并在其实验设置内验证的方法**,不是全行业通用标准——前沿实验室是否普遍采用规范文本 mid-training,没有公开证据；
- 其**抗压性存在争议**:2026 年 9 月已有反面论文质疑该方法在压力测试下的稳健性。写作与决策时应把"该方向有初步正面结果"与"尚无定论"并陈。

MSM 的数据工程含义值得单独记：训练数据分层从"预训练/mid-training(能力)/后训练"扩成了**四层**——mid-training 这个容器里，现在既装代码、数学这类能力数据，也可能装价值观与规范语料。数据配方的"类别表"变长了。

### 4. mid-training 与 SFT 的边界

mid-training 不是 SFT 的前移。两者数据形态与目标都不同：

| | Mid-training | SFT |
|---|---|---|
| 位置 | 预训练末期，仍以自回归语言目标为主 | 后训练起点，直接对齐目标行为 |
| 数据量级 | 数百亿 Token 量级 | 通常小一两个数量级 |
| 典型材料 | 高质量代码/数学/指令式长文本、(MSM 类)规范文档 | 精标示范、对话、偏好 |
| 回答的问题 | "底盘最后再定向强化什么能力" | "模型应该怎样表现" |

### 5. 分诊：mid-training、继续预训练还是直接 SFT

把 mid-training 放回决策菜单，它和两个邻居解决的是不同问题：

| 候选阶段 | 适用问题 | 数据形态 | 主要风险 |
|---|---|---|---|
| 继续预训练 | 底座整体缺一个**领域**的语料(如某行业文档) | 大量领域文本，自回归目标 | 通用能力回退，需要回放数据缓冲 |
| Mid-training | 底座有基础，要在**能力**(代码/数学/指令)上定向增强，或(MSM 类)预置规范 | 数百亿 Token 精选内容 | 增强过头挤占通用分布 |
| 直接 SFT | 底座能力够，只是**行为**不符合产品要求 | 小量精标示范 | 底座不会的能力，SFT 教不会 |

分诊的判断顺序：先问"缺的是领域语料、能力强度还是行为规范",再选阶段；如果一个模型同时缺三样，阶段编排(先补哪个)就是 T11 的训练编排问题，本章只要求把"第二次配方"的选项放进菜单。

### 6. 一次推演：中文代码助手的第二次配方

用本章方法走一遍(全部数字为教学示意，展示推导，不是任何真实配方):

```text
目标:中文技术问答 + 中等难度代码生成
    ↓ 反推能力短板(来自上一代模型的能力矩阵)
    ① 代码:能写样板,复杂重构吃力 → 代码能力不足
    ② 中文技术术语:口语化表达可以,文档腔不稳 → 领域语料不足
    ③ 指令:基本合格 → 行为不是主要短板 → 不必加大 SFT 前投入
    ↓ 推导第二次配方(mid-training,总量取 120B Token)
    代码(含带测试的开源仓库精选)   45%  ← 对齐短板①,经验区间内取高段
    中文技术文档/规范/接口手册      35%  ← 对齐短板②,来源全部登记许可
    数学与推理材料                  10%
    通用高质量回放数据              10%  ← 缓冲:防通用能力被挤占
    ↓ 验证设计
    固定预算对照 + 能力矩阵逐格 + 遗忘检查(重点盯中文通用问答)
```

三个值得注意的取舍：代码取了经验区间的高段，因为短板①权重最高；10% 的"回放数据"专门用来防遗忘，它不是浪费，是保险；行为短板③没有用数据预算去补——那是 SFT 阶段的账，别在 mid-training 里花冤枉钱。**每一次取舍都回链到能力矩阵的一格**,这就是"从能力目标反推配方"在第二次配方上的样子。

> **判断边界：**mid-training 的高杠杆只属于"底盘已就、目标明确"的模型。如果预训练主配方还没收敛、能力矩阵还在大幅变动，先修第一次配方；在漂移的地基上加码，只会放大错误方向。

## 六、数据墙与数据受限训练

### 1. 数据墙：两个都对的耗尽区间

**数据墙(Data Wall)**指高质量公开文本的存量上限。[Epoch AI 口径的转述页](https://techjacksolutions.com/ai-brief/epoch-ai-reports-synthetic-data-gains-cut-frontier-flop-requ)(原文：Villalobos 等 2024 年论文《Will we run out of data to train large language models?》,2026 年仍是标准引用)给出的估计是：人类公开高质量文本存量约 **300T Token**,按当时消耗增速将在 **2026-2032 年**间耗尽。流通中还有另一个更紧的版本：Toloka 综述转述为 **2026-2028 年**,前提是采用更严格的质量阈值。

两个区间并不矛盾——**口径不同**:前者是 Epoch 原文对"高质量文本"的基线定义下的推算，后者把质量门槛抬高后存量更小、耗尽更早。引用时必须注明口径，不要写成"数据墙将于某年到期"的确定日期。它意味着什么：数据预算的边际成本曲线在变陡，这正是本章把质量、合成与 mid-training 当主变量的宏观背景。

### 2. 三个不能划等号的量

```text
可抓取的公开数据量(万亿亿级原始字节)
    ≠ 可解析成文本的语料量(解析率、语言识别后)
    ≠ 有效训练数据量(去重、过滤、质量阈值、许可合规之后)
```

"可抓取量"直接当"有效训练量"引用，是数据讨论中最常见的口径滑坡。数据墙约束的是最后一层。

这条漏斗为什么值得数据团队自己量一遍：每一层的折损率就是你的**采购议价权**。如果清洗管线稳定把某类语料折掉 90%,那么"再抓 10 倍原始数据"和"把这类语料的清洗质量做上去"是两个可直接比价的选项——前者买覆盖，后者买密度，账算清楚才知道哪个便宜。大多数团队的现状是只有第一层的数字，没有后两层的数字，于是预算讨论只能停留在"再多抓点"。

### 3. 数据受限时怎么办：研究与现实的边界

当高质量数据不足，学术上的应对方向包括：多 Epoch 重复训练(重复有效但边际递减，且过多次重复会伤泛化——这也是本章第一节说"重复是配比变量"的原因)、合成数据补位、以及数据受限条件下的 scaling 研究。[Q Labs 的数据受限 Scaling 研究](https://arxiv.org/abs/2610.37842)探讨了超参数迁移与模型集成(Ensemble)等方向；注意其实验规模有限，结论不能直接外推到前沿模型的收益——引用时应保留"实验规模与外推边界"的说明。

### 4. 重复训练：数据受限时的老办法，及其边界

高质量新数据不够时，最古老的办法是把已有数据多训几个 **Epoch(轮次)**——第 2 个 Epoch 让模型把同样的内容再看一遍。这里只讲定性的共识框架，不给普适数字，因为重复的收益边界强依赖数据规模、模型容量和其余配方：

- **适度重复有效**:高质量语料见到第二次、第三次，学习效率通常仍然为正——这也是第一节"同一份高质量语料可以重复喂"的依据；
- **边际递减，过头伤模型**:重复到一定次数后，新信息趋零，模型开始过拟合训练分布，泛化能力受损；
- **重复是配比的一部分**:"数据集 1.5 个 Epoch、高质量桶 2 个 Epoch"这类配置，应该和数据配比一起写在配方表里，而不是训练脚本里的隐藏默认值。

把重复、合成与数据墙放在一起看，2026 年的应对格局大致是：能买到/洗出高质量新数据就优先新数据；不够时，定向合成 + 有控制的重复 + mid-training 的精准加码，组合使用——每种手段都用自己的实验定边界。

### 5. 去污染：从"质量增强"到"发布阻断"

**去污染(Decontamination)**指把训练语料中与评测基准重叠的内容清出去。[Toloka 综述](https://toloka.ai/blog/how-frontier-labs-build-pre-training-datasets)称，前沿实验室已把去污染从"质量增强步骤"升级为 **release-blocking(发布阻断)的合规步骤**,手段从 n-gram 重叠扩展到嵌入相似度检索——因为字面改写(paraphrase)型的泄漏，逐字匹配抓不到。

污染的影响有多大？有[行业方法论文章](https://www.digitalapplied.com/blog/llm-benchmark-methodology-2026-contamination-leaderboard-guide)估计，同一权重因污染与否，在榜单上可相差 10-20 个百分点(注意：这是方法论博客的估计，不是受控实验结论，引用时标注层级)。研究侧的回应是[把抗污染属性做进基准设计阶段](https://arxiv.org/html/2605.19999v1)(可复现、可靠、有区分度),而不是发布后反复补洗。对数据团队的直接要求：**训练数据入库前先对全部目标评测集做双向检查**(语料对基准、基准对语料),并把污染风险写进数据账本。

> **判断边界：**"数据墙哪年到""污染虚高几分"这类数字，引用时先问三件事：谁估的、口径是什么、有没有受控实验支撑。口径不明的数字宁可不用，也不要为了论证力度给不确定的量加上确定性。

## 七、实验归因：怎样证明某类数据真的有用

数据团队最容易翻车的环节不是清洗，而是**归因**——分数变了，但说不清是哪层配方的功劳。

### 1. 三件归因工具

```text
① 数据消融:固定模型、预算、其他数据,只增删目标类别
        ↓
② 配比扫描:同一组类别,扫几个配比点,看能力曲线而非单点
        ↓
③ 固定计算预算对照:新配方 vs 旧配方,总 Token 数与算力对齐
        ↓
分维度能力矩阵:目标能力↑? 非目标能力有无不可接受回退?
        + 遗忘评估(多阶段训练后旧能力是否退化)
        + 边际收益:每 PFLOP/每美元买到几分能力
```

关键纪律：**总 Token 数和计算预算必须对齐**。"加了新数据后分数涨了"如果同时总量也变大了，收益可能来自"更多"而不是"更好"——这正是本章标题要防的错觉。

### 2. 配比扫描怎么读：看曲线，不看单点

配比扫描(比如代码占比取 10%、15%、20%、25% 四个点)最容易被误读成"找最高分的点"。正确读法是看曲线形状：

```text
目标能力分
  ↑           .--------● ← 25%:又平了?还是开始伤别的维度?
  |      .---●          20%
  |   .-●                15%
  |.-●___________________ 10%     非目标能力(如通用问答)
  +--------------------→ 代码占比   是否同步下滑?
```

- **还在线性段**:加码大概率继续有效，值得为下一档做更贵的实验；
- **进入平台期**:再扫这个变量就是浪费预算，转向下一个敏感变量；
- **非目标能力同步下滑**:已经在借通用能力换目标能力，该停下来重新过能力矩阵。

单点比较看不见这三件事，曲线才看得见。这也是第一章实验阶梯"第 2 级"的产出物：一小组曲线，而不是一个最佳数字。

### 3. 用公开数字练一遍口径意识

GLM-5 的公开锚点可以做一个只依赖披露数字的演算(数字见[官方仓库](https://github.com/zai-org/GLM-5)):预训练 28.5T Token,总参数 744B,激活参数 40B。

- 以**总参数**为分母：28.5T ÷ 744B ≈ **38 Token/总参数**;
- 以**激活参数**为分母：28.5T ÷ 40B ≈ **712 Token/激活参数**。

两个比值都对，但含义完全不同：38 是相对全部容量的"喂料比",712 是相对每 Token 实际计算量的"超训练程度"(T02 已解释推理时代模型普遍超出早期最优喂料比)。**引用任何 Token/参数比，必须写清分母是总参数还是激活参数**,MoE(Mixture-of-Experts,混合专家)模型尤其如此——不写分母的比值没有意义。此外请注意这组演算只用了披露的总量数字，GLM-5 的配比(中文/代码/合成)仍未披露，以上不构成对其配方的任何推断。

### 4. 披露透明度：三家的对照

| 模型 | 披露了什么 | 没披露什么 | 教学要点 |
|---|---|---|---|
| GLM-5 | 28.5T 预训练 Token、744B-A40B 参数 | 数据配比、来源构成 | 总量透明 ≠ 配方透明 |
| Kimi K3 | 2.8T 总参数、104B 激活、896 选 16 专家、任务合成与 agentic RL 概况，权重开放 | 预训练数据配方细节 | **权重开放 ≠ 训练透明 ≠ 可自部署**,三个概念不能互推 |
| Apple AFM 3 | 数据按五类披露：公开信息、授权采购、开源、专项研究、合成；默认不用用户私有数据；尊重出版者退出权 | 各类占比数字 | "类别级透明"与"数字级保密"可以并存 |

Apple AFM 3 的[数据披露页](https://machinelearning.apple.com/research/introducing-third-generation-of-apple-foundation-models)是"类别级透明"的样板：它告诉你数据治理的原则和类别，但不给任何比例——这恰恰说明配比数字本身被视为竞争资产。评估任何模型的数据实践时，先分清它在"类别、原则、数字"三层里披露到了哪一层。

### 5. 遗忘与跨任务泛化：归因的另一半

只测目标能力会漏掉数据改动的两类暗账：

- **遗忘(Forgetting/能力回退)**:为强化 A 能力换入的新配方，可能让模型在 B 能力上退步——尤其多阶段训练时，后期数据分布挤占前期分布。评估方法很朴素：把**训练前**的能力矩阵原样再跑一遍，**逐格对比**,而不是只跑新目标。任何一格跌破产品承诺的底线，都是配方级问题，不是"训练抖动"。
- **跨任务泛化**:模型是学会了"解这类题",还是背住了这批数据的表达习惯？检验方式是把评测换到**同能力、不同来源**的任务上——同能力涨、换来源不涨，说明收益绑定了数据分布，而不是能力本身，上线后的真实收益要打折扣。

把这两条加进归因清单，完整的晋级证据是四件套：**目标能力提升 + 非目标能力无不可接受回退 + 换来源泛化成立 + 固定预算对照**。四件齐，这批数据的功劳才算坐实。

> **架构智慧：**数据决策的晋级证据是一组分维度数字加上一份可复盘的账本，而不是榜单总分的单点提升。总分是结果，账本才是决策资产——下一节把账本的样子画出来。

## 八、七种最常见的错误判断

以下每一条都能在真实评审里见到。它们的共同点是：把一个需要证据的判断，当成了一个可以直接引用的结论。

### 错误 1:把别家配比当行业固定答案照抄

15-25% 的代码占比是 Toloka 综述梳理出的经验区间，不是标准答案。照抄数字而不照抄"从能力目标反推"的方法，等于复制了别人的结论、丢掉了别人的推理。

### 错误 2:清洗保留率越高(或越低)越好

保留率是仪表不是目标。保留 90% 可能噪声残留，保留 10% 可能误删整个语言。唯一合格的标准：固定预算对照下，分维度能力净赚。

### 错误 3:给合成数据编造占比，或当免费补丁

没有任何前沿实验室公布精确合成占比；合成有生成成本和验证成本，验证不严还有负收益。见到"合成已占 X%"的无出处说法，应按传言处理。

### 错误 4:榜单涨分就宣布数据配方有效

分数上涨可能来自污染、评测集泄漏、训练量变大或另一处未记录的改动。没有消融对照的涨分，归因是悬空的——这正是去污染被前沿实验室升级为发布阻断步骤的原因。

### 错误 5:权重开放推出训练透明

Kimi K3 开放了权重，但其数据配方并未随之披露。权重开放、训练透明、可自部署是三个独立命题，互相都不能推出。

### 错误 6:把可抓取数据量当有效训练数据量

从原始网页到有效训练数据，要经过解析、去重、过滤、质量阈值和许可合规的层层折损，数据墙约束的是最后那一层。口径滑坡会让预算估计差出数量级。

### 错误 7:词表决策后置，训练中途才发现 fertility 吃掉了上下文

词表被当成"模型结构的小事"拖到训练前夜才定，结果目标语言 fertility 偏高：同样的标称上下文，塞进去的文档少三成，推理账单多三成。而词表中途几乎不可换——接口决策必须前置。

## 工程产物：Data Recipe + Data Quality Scorecard

把本章方法收拢成两份可以直接落表的文档骨架。配方表回答"模型看什么、为什么这么配";记分卡回答"每批数据过了哪些门槛、证据是什么"。两份表共用一套 ID,评审时对着看。

**Data Recipe(数据配方表)**——回答"模型看什么":

| 字段 | 示例 | 说明 |
|---|---|---|
| 能力目标 | 代码生成、中文技术问答 | 从产品目标翻译来的可评测能力 |
| 目标评测集 | 代码基准 v3.1、中文理解套件 | 注明版本，供去污染对齐 |
| 数据桶 | 网页-多语言 / 代码 / 数学 / 指令式 / 中文技术文档 | 来源 × 领域 × 语言 × 质量档 |
| 各桶配比与采样权重 | 代码 18%(实验区间内取点) | 配比是实验变量，记录取值理由 |
| 阶段归属 | 主体预训练 / mid-training / SFT | 同一桶可能跨阶段复用 |
| 重复与课程策略 | 高质量桶 epoch 2;难度递增排序 | 记录名义占比与实际见次 |
| 词表与 fertility | 词表 150K;中文 fertility 0.8 Token/字 | 数据与结构的接口参数 |
| 决策与消融链接 | ADR-T03-004;消融 #12 | 每行配置可追溯到一个决策 |

**Data Quality Scorecard(数据质量记分卡)**——回答"这批数据值不值":

| 维度 | 指标 | 门槛/证据 |
|---|---|---|
| 来源与授权 | 来源登记、许可类型、退出权遵守 | 逐桶登记，授权不明不入库 |
| 清洗强度 | 保留率、去重率(精确/近似/跨来源) | 与上一版对照，只改一个变量 |
| 质量分布 | 质量模型分数直方图、分语言保留率 | 防过滤器吃掉少数语言 |
| 污染风险 | 对目标评测集的重叠检查(n-gram + 嵌入) | release-blocking,双查通过才放行 |
| 合成数据 | Teacher 与验证方式、抽检合格率、混比 | 三组对照：真实/合成/混合 |
| 训练效果 | 分维度能力矩阵、遗忘评估 | 固定预算对照 |
| 边际收益 | 每 PFLOP / 每美元换来的能力分 | 决定下一轮预算投向 |
| 结论 | 晋级 / 回滚 / 再实验 | 记录判定人与日期 |

两份表合起来，就是本章开头说的"账本":配置在左，证据在右，任何一行数据决策都能复盘。

一份配方实验的最小流转：

```text
改配方(Recipe 表加一行,注明理由与预期)
    ↓
按 Scorecard 门槛过数据(污染双查、保留率登记)
    ↓
固定预算对照训练(消融组 vs 对照组)
    ↓
能力矩阵逐格对比 + 遗忘检查 + 换来源泛化
    ↓
四件套齐 → 更新 Recipe 主版本,记录晋级日期
    ↓ 任一件不齐
回滚或再实验,差异写回 Scorecard 的"结论"行
```

这套流转的要害在于：**配方表的每一行都对应 Scorecard 的一个结论，Scorecard 的每个结论都指向配方表的某次改动**。数据团队最贵的资产不是任何一版语料，而是这张"改动 → 证据"的对应表——人员流动、语料换代之后，它仍然是团队的判断力。

## 把判断用在合同助手上

**教学推演，非真实训练结果。**把条款抽取、带出处问答和澄清对话分别建桶；按合同来源或模板分离训练与评测，降低近重复泄漏。没有真实依据的合成风险解释不能直接入库。若基线显示知识来自检索即可补齐，就暂缓领域继续预训练。

```quiz
  "explanation": "词表是数据与模型结构之间的接口:同样 10 万字,不同 fertility 切出的 Token 数差一倍以上。有效上下文 = 标称上下文 ÷ fertility,这也是词表决策必须在训练前定死的原因之一。"
}
```

## 本章小结

- 从能力目标反推评测集，再反推数据类别和配比。配比需要实验，不存在通用百分比。
- 固定训练预算，联看质量、保留率、分维度能力与遗忘，才能判断一次清洗或合成是否有净收益。
- 合成数据和 Mid-training 都是候选投入方向；是否值得加码，要看独立验证与边际成本。

> **下一章的问题：**数据决定模型「学什么」，但模型的容量、注意力和模态结构决定它「如何表示和处理这些信息」。下一章进入模型骨架设计。

## 基础术语速查

| 术语 | 初学者可以先怎样理解 |
|---|---|
| 数据配方(Data Recipe) | 一张配料表：总量多少 Token、分哪几类、各占多少、什么阶段喂 |
| 配比 | 各类数据在总量中的份额；是实验变量，不是行业固定答案 |
| 采样权重 | 同一桶数据被抽到的相对概率，区分"名义占比"和"实际见次" |
| 保留率(Keep Rate) | 清洗后留下的 Token 占清洗前的比例；仪表，不是越高越好 |
| 去污染(Decontamination) | 把训练语料里与评测基准重叠的内容清出去，前沿实践中是发布阻断步骤 |
| 数据墙(Data Wall) | 高质量公开文本的存量上限；两个耗尽区间口径不同，引用要注明 |
| 合成数据 | 由模型生成、经验证管线筛选后入库的训练材料；当作降本变量管理 |
| Web Rephrasing | 用强模型把低质网页改写成高质量文本再加验证入库的工序 |
| Mid-training | 预训练末期的定向数据阶段，典型量级 50-500B Token 高质量内容 |
| Tokenizer / 词表 | 把文本切成 Token 的分词器与全部可用 Token 的清单；训练前定死 |
| Fertility | 平均每个词/字被切成几个 Token,决定有效上下文和推理账单 |
| 能力矩阵 | 连接"数据类别"与"目标评测"的对照表，数据决策的归因工具 |
