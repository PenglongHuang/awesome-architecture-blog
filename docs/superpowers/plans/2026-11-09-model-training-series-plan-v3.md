## 一、专题定位与学习目标

### 1.1 专题定位

本专题不是基础模型训练技术百科，而是**基础模型训练决策方法论**。

读者完成专题后，应能围绕一个目标任务，独立完成以下判断：

-   是否需要训练模型，还是使用现有模型、RAG、工具调用或微调即可；
-   应投入多少训练、推理和研发预算；
-   如何设计数据配方、模型结构与训练系统；
-   如何选择 SFT、蒸馏、偏好优化、RLVR 和 Agentic RL；
-   如何评估能力收益、识别奖励投机与训练退化；
-   如何建立安全约束、评测证据和发布门禁；
-   如何决定继续预训练、后训练、蒸馏、分支迭代或从头训练。

### 1.2 目标读者与先修知识

目标读者：具备机器学习/深度学习基础，希望理解基础模型训练工程、架构设计和训练策略的工程师、研究人员及技术决策者。

建议先修：

-   Transformer、反向传播、梯度下降和基本概率统计；
-   GPU 显存、吞吐、延迟等基础概念；
-   Python 与基本分布式系统概念。

正文遇到必要的先修概念，应提供简短解释或链接，不假定读者已经熟悉所有训练框架。

### 1.3 学习成果

读者最终应能交付一份完整的 **Training Architecture Decision
Record（Training ADR）**，至少包含：

1.  目标能力与验收指标；
2.  训练/推理/研发预算；
3.  数据配方与数据治理；
4.  模型结构与上下文策略；
5.  训练并行、精度和可靠性方案；
6.  后训练信号与阶段编排；
7.  评测、归因和安全门禁；
8.  风险、备选方案与回滚条件。

### 2.3 全专题统一教学结构

每章沿用 T01 的风格，但不机械套模板。建议采用以下顺序：

1.  **真实问题开场**：用一个工程困境或失败现场提出本章问题。
2.  **本章只解决一件事**：明确边界，避免知识点发散。
3.  **核心原理**：先讲因果机制，再介绍术语。
4.  **方案对比**：比较收益、成本、适用条件和失败模式。
5.  **决策推导**：给出可复用的判断步骤、公式或决策树。
6.  **现役案例拆解**：选 1--2 个有一手资料的案例；不以"新"代替"有证据"。
7.  **失败案例 / 反例**：说明错误选择会造成什么代价。
8.  **工程产物**：提供模板、检查表、配置草案或计算方法。
9.  **Quiz**：以推导题、判断题和场景题为主。
10. **下一章问题**：与下一章开篇明确衔接。

每章不要求堆满所有新技术。术语只在解释问题所必需时引入。

## 三、章节明细

## T02 · Scaling 不是抄比例：训练、推理与研发算力的三本总账

### 一句话点题

模型规模不是越大越好，也不能只按 Chinchilla
比例决定；必须把训练成本、部署后的推理成本和研发试错成本放在同一张账上，结合目标任务与服务负载做决策。

### 本章只解决一件事

**给定目标能力、预算和部署形态，如何决定模型规模、训练 Token
数与推理预算？**

### 内容结构

1.  **开场：同样的预算，为什么有团队训大模型，有团队选择小模型？**
    -   设定一个明确场景：目标任务、请求量、延迟要求、部署周期和预算。
    -   先让读者选择 Dense / MoE、模型规模和训练
        Token，再逐步揭示隐藏成本。
2.  **Scaling Law 与 Chinchilla 的适用边界**
    -   参数量、训练 Token、训练 FLOPs 与损失之间的关系。
    -   Chinchilla 的假设、优化目标与适用范围。
    -   明确 Dense 与 MoE 的参数口径差异：总参数、激活参数不能混用。
    -   不把某一个固定 Token/参数比例写成所有模型的通用配方。
3.  **训练账：训练计算量如何估算**
    -   参数规模、Token 数、训练步数、序列长度和训练 FLOPs。
    -   估算值与实际账单的差异：利用率、重算、通信、故障和实验开销。
    -   给出一个可复算的预算示例。
4.  **推理摊销账：训练最优不等于部署最优**
    -   请求量、输入/输出 Token、并发、延迟、采样次数和服务成本。
    -   Test-Time Scaling 与 Train-to-Test（T²）联合优化的思路。
    -   解释为什么在某些预算假设下，增加训练
        Token、减少模型规模可能更划算。
    -   区分离线 benchmark 最优与真实业务成本最优。
5.  **研发账：最终训练 Run 不是全部成本**
    -   数据实验、架构试验、消融、失败训练、后训练和评测的成本。
    -   使用 Epoch AI
        对研发算力支出的分析作为案例时，明确其统计口径是**算力支出估算**，不是实际
        FLOPs 占比。
    -   不将单个实验室的估算推广成所有公司的固定比例。
6.  **部署形态倒推模型选择**
    -   云端高并发、低延迟服务、端侧、本地部署、Agent
        多轮推理等不同场景。
    -   以服务量和成本目标倒推参数规模、量化、上下文与采样策略。
7.  **实验设计：如何验证 Scaling 决策**
    -   小规模试验如何外推到大规模。
    -   控制变量、学习曲线、置信区间与外推误差。
    -   记录预测值、实际值和偏差原因。
8.  **决策总结**
    -   训练、推理、研发三本账合并。
    -   形成模型规模与预算决策表。

### 重点案例与资料

-   GLM-5：用于讨论公开训练披露的边界；参数量、Token
    数和训练成本等具体数字必须逐项定位到报告原文。
-   T²
    scaling（arXiv:2604.01411）：讨论将测试时采样成本纳入端到端预算后的联合优化。
-   Epoch AI：讨论最终训练 Run 与研发算力支出的区别；明确估算口径。
-   Inkling 2
    Small：作为公开训练账本的案例，但只使用官方已经披露的部分，不称其为完全透明的训练配方。

类型与数量、预估利用率、请求量、平均上下文、输出长度、采样次数。

## T03 · 数据不是越多越好：配比、质量、合成与 Mid-training

### 一句话点题

数据工程的目标不是把语料堆到足够大，而是围绕目标能力设计数据配方，并通过质量评估、消融实验和收益归因证明每一步处理是否有效。

### 本章只解决一件事

**如何从目标能力反推数据配方，并证明数据清洗、合成和再训练带来了真实收益？**

### 内容结构

1.  **开场：同样 1T Token，为什么不同数据配方训出的模型差异很大？**
    -   用代码、数学、知识、对话等能力目标设计不同数据配比。
    -   明确"配比是实验变量"，不是行业固定答案。
2.  **数据配方：从能力目标反推数据组成**
    -   来源、领域、语言、任务、质量和难度分层。
    -   数据重复、采样权重、温度采样与课程学习。
    -   代码数据对通用能力的潜在迁移：作为待验证假设，不预设固定占比。
    -   用能力矩阵连接数据类别和目标评测集。
3.  **数据管线：从原始语料到可训练数据**
    -   抽取、解析、去重、过滤、分类、质量打分、隐私与版权治理。
    -   精确去重、近似去重、跨来源去重和污染检测。
    -   质量模型本身的偏差：过滤器可能误删少数语言、长尾知识和困难样本。
    -   用保留率、质量分布和能力变化衡量清洗收益。
4.  **Tokenizer / Vocabulary：被忽略的基础决策**
    -   词表大小、分词效率、语言覆盖、代码与多模态 Token 化。
    -   Token 压缩率如何影响训练成本、上下文长度和跨语言表现。
    -   词表扩展或更换的兼容性代价。
    -   将词表视为数据、模型结构和部署成本之间的接口。
5.  **合成数据：从补量转向能力定向**
    -   生成、过滤、验证、去重和混合训练。
    -   Teacher 质量、生成分布偏差、错误放大和模型自我强化风险。
    -   用真实数据、合成数据和混合数据做对照实验。
    -   不引用没有官方或可靠研究依据的"合成数据占比超过一半"等说法。
6.  **Mid-training：预训练之后的定向数据阶段**
    -   区分继续预训练、领域适配、能力强化与规范/行为类训练。
    -   讨论 Model Spec
        Midtraining（MSM）作为研究案例：明确它是特定论文提出并验证的方法，不写成全行业通用标准。
    -   说明数据阶段、训练目标和后续 SFT 的关系。
7.  **数据受限与重复训练**
    -   数据可用量、数据质量、重复 Epoch、合成数据和模型容量之间的关系。
    -   讨论数据受限 Scaling 的研究进展及其假设边界。
    -   不将"可抓取数据量"直接等同于"有效训练数据量"。
8.  **实验归因：如何证明某类数据真的有用**
    -   数据消融、配比扫描、固定计算预算对照。
    -   训练前后能力矩阵、遗忘评估和跨任务泛化。
    -   质量收益、数据成本和训练成本的边际收益分析。

### 重点案例与资料

-   FineWeb、FineWeb 2、Common Pile、Dolma
    系列：用于讲数据集构建方法和数据治理，具体版本、规模、语言数量和许可信息须引用对应版本的官方文档。
-   Anthropic Model Spec
    Midtraining：用于解释规范文本进入中期训练的研究路径。
-   Q Labs 数据受限 Scaling（arXiv:2610.37842）：用于讨论超参数迁移和
    Ensemble 等研究方向；必须说明实验规模与外推边界。
-   GLM-5、Kimi
    K3：用于对比公开披露与未披露的数据配方；不从未公开信息推测数据比例。

**Data Recipe + Data Quality Scorecard**

包含：数据来源登记、授权状态、数据类别、清洗规则、保留率、重复率、质量分布、污染风险、训练配比、能力评测结果和消融结论。

## T04 · 骨架不是选新结构：容量、上下文与模态的联合决策

### 一句话点题

模型架构不是追逐最新结构，而是在能力、训练成本、推理延迟、显存、上下文和部署约束之间做联合权衡。

### 本章只解决一件事

**给定任务与部署约束，如何选择 Dense /
MoE、注意力结构、上下文长度和多模态路线？**

### 内容结构

1.  **开场：为什么参数更多的模型不一定更快、更便宜或更好？**
    -   用同一任务对比 Dense 与 MoE 的参数、激活、显存、吞吐和服务成本。
2.  **容量账：Dense 与 MoE**
    -   Dense 的计算与参数关系。
    -   MoE 的路由、专家、激活参数、总参数和负载均衡。
    -   专家数量、Top-K、路由稳定性、专家并行和通信代价。
    -   解释"激活比例低"不等于"训练和部署成本按同样比例下降"。
    -   说明 Dense 在小模型、微调和特定部署场景中的价值。
3.  **注意力与上下文账**
    -   标准 Attention、MQA/GQA、MLA、稀疏注意力和线性注意力的区别。
    -   区分"压缩
        KV""稀疏选择"和"线性复杂度"，避免把不同技术写成简单升级关系。
    -   KV Cache、上下文长度、并发、Prefill / Decode 的成本。
    -   标称上下文长度与有效利用能力的区别。
    -   长上下文与 RAG 的选择边界：详细检索方案回指相关专题。
4.  **多模态账**
    -   原生多模态与连接器/适配器路线。
    -   图像、视频、音频的 Token 化和视觉 Token 预算。
    -   多模态数据配方、对齐阶段和评测方式。
    -   "模型是否真正使用图像证据"的证据义务。
5.  **三笔账如何互相改写**
    -   容量影响训练和部署成本。
    -   注意力影响上下文与 KV Cache。
    -   模态结构影响数据、训练阶段和推理成本。
    -   用依赖图而非技术清单表达架构权衡。
6.  **Architecture ADR：如何做架构选择**
    -   目标任务、硬件、服务负载、上下文和能力要求。
    -   备选架构、成本估算、风险和验证实验。
    -   明确何时应该选择更简单的 Dense 结构。

### 重点案例与资料

-   Kimi K3（arXiv:2607.24653）：官方论文披露 2.8T 总参数、104B
    激活参数、896 个路由专家中每 Token 激活 16 个专家，以及
    KDA、Attention Residuals
    等设计；使用时区分论文披露与作者对收益的解释。
-   GLM-5：DSA 相关设计以技术报告为依据，具体参数与结构逐项核对。
-   其他现役模型（例如 Mistral、DeepSeek、Ling、ERNIE
    系列）：只有在找到对应官方技术报告或模型卡后才纳入，不预先将其写成"行业标准"。

### 工程产物

**Model Architecture ADR**

包括 Dense / MoE
对比、注意力方案、上下文目标、模态路线、硬件约束、训练成本、推理成本、风险和验证计划。

## T05 · 训练系统不是运维：从一步训练到分布式拓扑

### 一句话点题

训练系统设计不是照抄论文里的 GPU
数量，而是从显存、通信、计算和可靠性约束出发，推导出可运行、可扩展、可恢复的训练拓扑。

### 本章只解决一件事

**给定模型、硬件和训练目标，如何设计训练并行、数值精度、优化器和容错机制？**

### 内容结构

1.  **开场：同一训练任务的三种翻车**
    -   模型装不进显存。
    -   GPU 利用率低，通信成为瓶颈。
    -   Checkpoint 恢复后训练状态不一致。
2.  **一步训练的机械**
    -   Forward、Loss、Backward、Optimizer Step。
    -   参数、梯度、优化器状态、激活值和临时 Buffer。
    -   重计算、梯度累积和激活检查点。
3.  **四本显存账**
    -   参数与参数分片。
    -   梯度与梯度分片。
    -   优化器状态。
    -   激活值、KV/临时 Buffer 与通信 Buffer。
    -   用一个具体模型配置做显存估算；假设、精度和框架开销必须明确。
4.  **并行策略：从计算图推导拓扑**
    -   Data Parallel、Tensor Parallel、Pipeline Parallel、Sequence /
        Context Parallel、Expert Parallel。
    -   ZeRO / FSDP 等状态分片思路。
    -   并行维度组合与 GPU 总数关系。
    -   通信拓扑、机内互联、跨机网络和专家路由流量。
    -   MoE 的 Expert Parallel 与负载均衡。
    -   不将某个并行组合描述成适用于所有模型的标准答案。
5.  **数值精度与稳定性**
    -   FP32、BF16、FP16、FP8、MXFP8、FP4/NVFP4 的基本差异。
    -   不同张量使用不同精度的动机。
    -   Scale、量化误差、溢出、梯度异常与验证门禁。
    -   说明硬件支持、框架实现和模型稳定性三者缺一不可。
    -   "前沿标准""主流化"等判断必须给出明确适用范围和证据。
6.  **优化器与训练超参**
    -   AdamW 的状态与更新机制。
    -   Muon 等优化器的设计动机和适用范围。
    -   学习率日程、Warmup、Batch Size、梯度裁剪和权重衰减。
    -   不把研究趋势直接写成全行业普遍采用。
7.  **训练可靠性与 Goodput**
    -   Checkpoint
        不只是模型权重：参数、优化器状态、数据游标、RNG、调度状态等。
    -   Loss Spike 的分类与排查。
    -   故障恢复、节点失效、数据加载瓶颈和网络异常。
    -   MFU、HFU、吞吐、Goodput 与端到端训练时间的区别。
8.  **框架作为工程载体**
    -   PyTorch / torchtitan、FSDP、Megatron、DeepSpeed 等框架的定位。
    -   框架不是架构决策本身；用一个最小训练配置展示配置如何映射到并行拓扑。
    -   RL 训练框架在 T09 深入展开。

### 重点案例与资料

-   Inkling 2 Small：官方披露 H1 使用 8.4T Token、GB300 NVL72、68
    小时、原生 NVFP4；同时注明官方表示 NVFP4 配方细节将在后续披露。
-   GLM-5：用于讨论训练系统和异步 RL 基础设施；引用报告中的具体章节。
-   Mixture-of-Parallelisms、torchtitan
    等研究/工程项目：按论文或官方文档描述，不将单篇研究结果写成普遍工程结论。

包含模型形态、GPU
规格、显存预算、并行维度、通信拓扑、数值精度、优化器、Checkpoint
策略、监控指标和故障恢复流程。

## T06 · 示范不是数据堆：SFT、蒸馏与能力迁移边界

### 一句话点题

SFT
和蒸馏都使用示范信号，但它们解决的问题不同；关键是明确要迁移什么能力、示范来自什么分布，以及学生模型能否真正学会而不是复述答案。

### 本章只解决一件事

**如何选择
SFT、参数高效微调、全参数微调和蒸馏，并判断它们能否带来可迁移能力？**

### 内容结构

1.  **开场：模型会背答案，却不会解决新问题**
    -   展示格式模仿成功、任务泛化失败的例子。
    -   区分训练集拟合与能力迁移。
2.  **SFT 的学习机制**
    -   监督目标、Token-level loss、Teacher Forcing。
    -   数据质量、覆盖度、难度和多样性。
    -   SFT
        能学到格式、行为、知识和任务模式，但收益取决于数据、模型和训练设置；不将其简单概括为"只能教格式"。
3.  **写入深度：LoRA / PEFT 与全参数微调**
    -   参数更新范围、显存、训练成本和遗忘风险。
    -   何时适合 LoRA，何时需要全参数更新。
    -   用目标任务与回归评测决定，不给出脱离场景的绝对规则。
4.  **蒸馏：Teacher 到 Student**
    -   Logit Distillation、Response Distillation、Reasoning Trace
        Distillation。
    -   Teacher 能力、Student 容量、数据分布和任务覆盖。
    -   口径背诵、错误迁移、Teacher 偏差和容量上限。
    -   用同预算直接训练作为对照，避免把蒸馏收益归因错误。
5.  **On-policy 与 Off-policy 蒸馏**
    -   数据来自 Teacher 还是 Student 自己的轨迹。
    -   Student 分布偏移与错误暴露。
    -   On-policy Distillation 的收益、成本和风险。
    -   区分论文提出的方法、模型报告中的具体实践和行业普及程度。
6.  **能力保持与遗忘**
    -   多阶段训练导致的能力回退。
    -   回放数据、混合训练、阶段性评测和能力修复。
    -   以能力矩阵识别"新能力提高、旧能力退化"的情况。
7.  **蒸馏是否值得：收益归因**
    -   同预算对照、推理成本对照、模型尺寸对照。
    -   对目标能力、泛化能力、稳定性和服务成本分别评估。

### 重点案例与资料

-   GLM-5：如果报告明确披露阶段性训练与跨阶段蒸馏，则按原文解释其具体作用；不要将单个模型配方推广为通用最佳实践。
-   Kimi
    系列或其他复用底座的模型：用于说明底座复用与后训练增益，具体数据需模型卡或技术报告支持。
-   InstructGPT 等历史论文：用于方法起源，不要求所有案例都必须是 2026
    年新模型。

### 工程产物

**SFT / Distillation Strategy**

包括目标能力、数据来源、Teacher 选择、Student
容量、训练方式、遗忘风险、对照实验和验收指标。

### Quiz 方向

-   为什么 Teacher 的正确答案不一定能转化为 Student 的可迁移能力？
-   什么时候 LoRA 足够，什么时候需要全参数微调？
-   如何证明蒸馏优于同预算直接训练？

### 下一章衔接

示范告诉模型"应该怎么做"，但很多任务存在多个合理答案。下一章讨论如何定义偏好，并把偏好变成可优化的奖励信号。

## T07 · 偏好不是标注量：奖励信号的生产、校准与防过优化

### 一句话点题

偏好优化的核心不是收集更多 chosen /
rejected，而是定义什么叫更好、确保候选样本有代表性，并让奖励信号足够可靠，避免模型学会迎合评分器。

### 本章只解决一件事

**如何构建偏好数据和奖励模型，并判断离线偏好优化何时失效？**

### 内容结构

1.  **开场：两个答案都正确，为什么标注者和模型评分器仍然意见不一？**
    -   展示偏好标准不明确、评审尺度不一致和上下文缺失的例子。
2.  **偏好信号生产线**
    -   目标规范 → 候选生成 → 比较/打分 → 数据质检 → 奖励建模 → 优化 →
        回归评测。
    -   偏好定义、标注规范和质量控制。
3.  **偏好数据怎么来**
    -   人类偏好、专家偏好、AI Feedback、合成偏好。
    -   候选采样策略与模型分布。
    -   难例、边界案例、分歧样本和数据过期。
4.  **Reward Model 的工作机制**
    -   Pairwise Ranking、标量奖励、校准和排序一致性。
    -   训练集、验证集与分布外评估。
    -   显式 Reward Model、DPO 隐式奖励视角和生成式/基于 Rubric
        的评价方式。
    -   不将不同方法的实验结论直接写成固定性能差距。
5.  **DPO 与其他离线偏好优化**
    -   DPO 的基本目标与 KL/参考模型关系。
    -   适用条件、数据依赖和分布偏移。
    -   其他偏好优化方法按问题分类，不堆砌算法名。
6.  **Reward Hacking 与 Overoptimization**
    -   模型如何利用评分器漏洞。
    -   训练奖励上升但真实能力下降的信号。
    -   KL 约束、奖励集成、Rubric 细化、人工抽检和对抗评测。
7.  **离线信号何时到头**
    -   训练分数持续提高但独立评测不再提高。
    -   候选分布缺乏新信息。
    -   评分器校准恶化或出现明显奖励投机。
    -   何时转向在线 RL，何时应该先修复数据和评分器。

### 重点案例与资料

-   InstructGPT、DPO 原论文：方法起源。
-   2026 年 Rubric / Generative RM
    研究：只有在原论文或官方报告可核验后纳入。
-   GLM-5、Kimi 等模型报告：只引用明确披露的奖励训练信息。

**Reward Model Design & Calibration Report**

包含偏好规范、候选分布、标注一致性、奖励模型指标、校准结果、对抗样例、过优化监控和切换策略。

-   Rubric 更细是否一定让 Reward Model 更可靠？

RLVR 的前提与边界。

## T08 · 可验证不是万能钥匙：RLVR 的前提、收益归因与训练健康

### 一句话点题

RLVR
不是只要有标准答案就值得做；必须确认奖励可验证、难以投机、基座具备必要能力种子，并持续判断训练究竟提高了能力还是只改变了采样分布。

### 本章只解决一件事

**如何判断任务适不适合
RLVR，如何设计奖励与训练过程，并证明收益是真实泛化？**

### 内容结构

1.  **开场：三个团队都使用正确答案作为奖励，为什么结果完全不同？**
    -   奖励可靠、奖励可钻、基座能力不足三种情况。
2.  **RLVR 的基本训练闭环**
    -   Prompt / Task → Sampling → Verification → Reward → Advantage →
        Policy Update → Evaluation。
    -   解释策略、轨迹、奖励、优势估计和策略更新。
3.  **前提一：奖励是否可验证**
    -   程序化验证、单元测试、数学答案、结构化约束和环境状态。
    -   奖励覆盖率、误判率、验证成本和抗投机性。
    -   规则正确不代表奖励完整；检查 Reward Hacking。
4.  **前提二：基座是否具备能力种子**
    -   RL 能否从当前策略探索到成功轨迹。
    -   任务难度、采样预算、成功率和奖励稀疏性。
    -   何时需要先 SFT / 蒸馏，再进入 RL。
5.  **RLVR 到底买到了什么**
    -   pass@k、majority vote / maj@k 等指标的含义。
    -   区分单次采样成功率、Best-of-N、聚合策略和模型能力边界。
    -   展示"采样效率提升"和"能力边界扩展"两种解释。
    -   将争议呈现为研究问题，说明不同论文的设置、指标和反例；不预设单一结论。
6.  **算法与目标函数**
    -   PPO、GRPO 及相关变体的基本思路。
    -   Critic、组内基线、优势估计和 KL 控制。
    -   重点讲清楚算法解决什么问题、引入什么代价，不以算法名单代替解释。
7.  **训练健康度与异常诊断**
    -   Reward、Entropy、KL、成功率、任务难度、输出长度等指标联合观察。
    -   识别熵塌缩、长度投机、奖励饱和、策略退化和能力遗忘。
    -   说明每个指标的适用范围，不把单条曲线当作充分证据。
8.  **实验归因与停止条件**
    -   Base / SFT / RL 对照。
    -   固定采样预算与固定计算预算的比较。
    -   独立测试集、分布外任务和重复运行。
    -   明确继续训练、修改奖励、增加数据或停止训练的判据。

### 重点案例与资料

-   DeepSeekMath、GRPO、DAPO 等历史论文：用于解释算法来源。
-   2025--2026 RLVR 边界研究：并列呈现不同研究结论与实验条件。
-   Kimi、GLM 等公开模型报告：只使用明确披露的 RL 任务和指标。
-   所有 pass@k、maj@k、成功率数字必须附数据集版本、采样次数和评测设置。

### 工程产物

**RLVR Training Plan**

包括任务定义、验证器、奖励函数、采样策略、算法选择、训练监控、对照实验、停止条件和回归测试。

### Quiz 方向

-   一个任务有标准答案，但验证器允许模型通过格式投机拿高分，是否适合
    RLVR？
-   pass@k 不变而 maj@k 提升，至少有哪些可能解释？
-   Reward 上升、Entropy 下降、独立评测不变，应该如何排查？

### 下一章衔接

RLVR 常有明确的答案或验证器；真实 Agent
任务却可能包含几十步工具调用、状态变化和长程目标。下一章把学习环境本身作为核心工程对象。

## T09 · Agentic RL 不是换任务清单：环境、信用分配与异步拓扑

### 一句话点题

Agentic RL
的瓶颈不只是策略算法，而是环境能否真实、稳定、低成本地提供交互，奖励能否归因到正确步骤，以及异步训练能否在吞吐和策略新鲜度之间取得平衡。

### 本章只解决一件事

**如何构建可训练的 Agent
环境，并把长程交互转化为稳定、可扩展的学习信号？**

### 内容结构

1.  **开场：数学题一次生成一个答案，Agent 却要在环境中连续执行几十步**
    -   对比短程问答与软件工程、浏览器操作、工具使用等长程任务。
    -   展示环境、状态和动作如何影响训练难度。
2.  **环境是一等训练资产**
    -   任务定义、初始状态、工具接口、权限边界、环境重置和终止条件。
    -   真实环境、模拟环境、合成环境的优缺点。
    -   Sandbox / Container / VM / MicroVM 的隔离和成本。
    -   环境版本化、可复现性、任务泄漏和状态污染。
3.  **从任务到轨迹**
    -   Observation、Action、Tool Call、Environment State、Trajectory。
    -   长程任务的状态压缩、上下文管理和失败恢复。
    -   如何记录可回放、可审计的轨迹。
4.  **奖励设计与信用分配**
    -   最终结果奖励、过程奖励、步骤级奖励和约束惩罚。
    -   组式基线、Critic / Value Function、Token-level Advantage
        等方法。
    -   何时组内比较足够，何时需要 Critic。
    -   不把某个模型采用的算法选择写成所有 Agent 任务的最佳实践。
5.  **异步训练拓扑**
    -   Rollout Worker 与 Trainer 解耦。
    -   同步、部分异步、完全异步的差异。
    -   Policy Lag / Staleness、版本管理、权重同步和缓存。
    -   吞吐、GPU 利用率、轨迹质量和策略新鲜度之间的权衡。
6.  **环境吞吐与训练经济性**
    -   环境启动、任务执行、重置、验证和回放成本。
    -   长短任务混合、任务并发、失败重试和资源隔离。
    -   统计每条有效轨迹成本，而不只统计生成 Token。
7.  **Agentic RL 的评测**
    -   任务成功率、步骤效率、工具调用正确性、恢复能力和安全违规。
    -   多次运行稳定性、任务难度分层和环境版本控制。
    -   训练环境与测试环境隔离，避免任务记忆和评测污染。
8.  **端到端架构推导**
    -   以一个软件工程 Agent 为例：Issue → Sandbox → Tool Use → Tests →
        Reward → Replay → Update。
    -   画出环境、Sampler、Trainer、Verifier、Monitor 的数据流。
    -   对比同步和异步方案，说明选型依据。

### 重点案例与资料

-   GLM-5：用于研究异步 RL 基础设施与长程 Agent
    任务；具体环境组成和算法按报告原文核验。
-   Inkling 2 Small：官方披露主 RL run 的 GPU、时长、rollout、Token 和
    sampler:trainer 等数据，可作为训练账本案例；每个数字保留原始口径。
-   Hugging Face "Keep the Tokens Flowing" 等异步 RL
    综述：用于梳理开源系统生态，需注明综述统计时间和项目纳入标准。
-   slime、vLLM、veRL、torchtitan
    等：按各自官方文档解释职责和集成关系，不混称为同一种框架。

### 工程产物

**Agent Environment Specification**

包括任务协议、环境镜像、权限边界、状态管理、工具定义、奖励/验证器、轨迹
Schema、回放、并发、监控和版本策略。

## T10 · 防线不是一道墙：安全规格、全生命周期评测与发布门禁

### 一句话点题

安全与评测不是训练结束后的检查项，而是贯穿数据、训练、模型行为和部署的证据链；真正可靠的发布门禁必须同时检查能力、安全、泛化和监控有效性。

### 本章只解决一件事

**如何把安全要求变成可执行约束，并用独立、抗污染、可复现的评测证明模型是否达到发布标准？**

### 内容结构

1.  **开场：离线评测全绿，模型上线后为什么仍然可能出问题？**
    -   评测覆盖不全、分布偏移、奖励投机、环境差异和安全绕过。
2.  **安全规格：把原则转成可执行要求**
    -   Policy / Spec → 风险分类 → 行为要求 → 测试用例 → 训练约束 →
        监控和响应。
    -   明确允许、拒绝、升级人工处理的边界。
    -   同时评估违规率和误拒率，避免只追求拒绝率。
3.  **分层布防**
    -   数据治理：拒绝不合规或高风险训练样本。
    -   训练目标：偏好、奖励和安全微调。
    -   模型内化：让模型理解行为规范与上下文。
    -   运行时监控：输入、输出、工具调用和轨迹监控。
    -   外围控制：权限、沙箱、速率限制和人工审批。
    -   不把任何单一层描述成充分防护。
4.  **白盒监控与 Activation Classifier**
    -   外部文本分类器与内部激活探针的差异。
    -   逐 Token 监控、工具调用拦截和升级复审。
    -   训练数据、探针泛化、底座依赖和模型更新后的再校准。
    -   OpenAI 2026-11-02 的 Activation Classifiers
        文章可作为公开案例；明确它是防御纵深中的一层，而不是安全保证。
5.  **监控本身也可能成为攻击面**
    -   监控策略、告警、评测脚本和训练管线的权限隔离。
    -   Agent 是否能修改自己的监控、测试和发布门禁。
    -   将"监控与被监控对象的权限隔离"作为架构原则。
    -   涉及内部事故的描述，只有找到可公开引用的一手报告后才能写入；否则改为一般威胁模型，不写成已发生事实。
6.  **全生命周期评测**
    -   数据评测：质量、覆盖、污染、版权和隐私。
    -   预训练评测：能力曲线、损失、遗忘和泛化。
    -   后训练评测：任务效果、偏好一致性、奖励投机和稳定性。
    -   Agent 评测：任务成功、工具调用、恢复能力、长程安全。
    -   部署评测：真实流量、分布变化、延迟、成本和事故率。
    -   评测与生产差距：明确任务、样本、统计口径和置信区间。
7.  **CoT 监控：必须区分 Monitorability 与 Controllability**
    -   **CoT Monitorability**：监控者能否从模型 CoT 中识别相关行为。
    -   **CoT Controllability**：模型能否按照指令改变自己的 CoT。
    -   GPT-6 Astra 系统卡报告：Astra 的 CoT Monitorability 相较 GPT-5.6
        Sol 下降；系统卡中 750--1,250 Token 区间的 60.9%（Astra）与
        16.1%（Sol）是 **CoT Controllability** 数值，不是
        Monitorability。
    -   讲清两项指标的定义、实验设置和安全含义，不把两个概念合并。
8.  **评测污染与抗应试**
    -   训练集、验证集、公开基准和隐藏测试集隔离。
    -   时间切分、动态任务、私有测试、变体生成和外部复核。
    -   识别 benchmark overfitting、数据泄漏和测试集记忆。
    -   不将没有来源的"污染会虚高 10--20 分"等数字作为通用事实。
9.  **发布门禁与证据留档**
    -   能力门槛、安全门槛、稳定性门槛、成本门槛和回滚条件。
    -   多次运行、分层报告、置信区间和异常样本审计。
    -   模型卡、数据卡、评测报告、风险接受记录和审批记录。

### 重点案例与资料

-   OpenAI Activation
    Classifiers（2026-11-02）：内部激活探针作为运行时安全监控层。
-   GPT-6 Astra System Card：CoT Monitorability 与 Controllability
    的区分及对应实验。
-   Anthropic Model Spec
    Midtraining：规范文本训练与后续对齐泛化的研究案例。
-   GLM-5.3：后训练能力变化与网络安全能力风险的案例；必须同时呈现能力收益和风险评测，不只引用性能提升。

## T11 · 整机不是流水线模板：训练编排、模型生命周期与算力战略

### 一句话点题

训练的最后一个决策不是选择某个算法，而是判断不同训练阶段如何组合、模型底座如何演进，以及有限资金和算力应该投入到哪里。

### 本章只解决一件事

**面对一个目标模型，如何选择训练路线、编排训练阶段、管理模型族并形成可审计的投入决策？**

### 内容结构

1.  **开场：同一个底座，为什么后训练也可能带来显著能力变化？**
    -   使用 GLM-5.3 与 GLM-5.2
        的公开模型卡作为案例：模型卡称两者使用相同 base model，并报告
        Terminal-Bench 3.0 分数分别为 28.3 与 4.6。
    -   解释该结果说明后训练可能产生显著影响，但不能据此推断所有任务都会有相同倍数提升；必须同时看任务、基准版本、评测设置和其他能力变化。
2.  **训练路线分诊**
    -   不训练：Prompt / RAG / Tool Use。
    -   轻量适配：LoRA / SFT。
    -   领域增强：继续预训练 / Mid-training。
    -   行为与偏好：SFT / Preference Optimization。
    -   可验证任务：RLVR。
    -   长程交互任务：Agentic RL。
    -   从头训练：只有在数据、算力、团队、合规和差异化能力均有充分理由时考虑。
3.  **训练阶段如何编排**
    -   Pretraining → Mid-training → SFT → Preference / RM → RLVR →
        Agentic RL → Safety / Evaluation。
    -   说明这是一种可能的阶段图，不是所有模型都必须经过的固定流水线。
    -   阶段顺序、数据复用、能力回退、回放和跨阶段蒸馏。
    -   用能力矩阵决定下一阶段，而不是按模板堆叠训练阶段。
4.  **继续训练、复用底座还是从头训练**
    -   Checkpoint 选择、数据兼容、Tokenizer 兼容和架构兼容。
    -   底座能力、许可证、数据治理和部署限制。
    -   继续预训练、模型分支、蒸馏和重训的收益与风险。
    -   模型族的版本管理、能力回归和发布策略。
5.  **模型族与开放策略**
    -   Base、Instruct、Reasoning、Coding、Agent、Small / Flash
        等模型分支的定位。
    -   开放权重、开放代码、开放数据、开放训练配方和可本地部署是不同概念。
    -   权重文件大小、推理硬件、量化、许可证和实际部署门槛。
    -   不以单一榜单或某一代模型代表整个开源生态。
6.  **算力战略**
    -   购买/租用 GPU、云端训练、合作训练和自建集群。
    -   从 FLOPs → GPU-hours → 费用的估算链。
    -   故障、消融、数据处理、Rollout 和评测带来的隐藏乘数。
    -   训练与推理预算联动，尤其是 Agentic RL 的环境和 Rollout 成本。
    -   研发算力支出与最终训练 Run 的口径区分。
7.  **Capstone：完整 Training ADR**
    -   给定目标任务、预算、部署约束和安全要求。
    -   选择数据、架构、训练系统和后训练路线。
    -   设计评测、风险和回滚条件。
    -   对比至少两个备选方案，说明为什么不选。
    -   形成可审计、可复盘的最终决策文档。

### 重点案例与资料

-   GLM-5 / GLM-5.3：训练阶段编排与底座复用的案例；GLM-5.3 的
    Terminal-Bench 数据使用官方模型卡并标注 benchmark 版本。
-   Kimi
    K3：开放权重与训练透明度的区别；不能从权重开放推导训练数据和全部配方开放。
-   Inkling 2
    Small：训练账本、硬件与后训练资源投入的案例；权重状态以官方最新公告为准。
-   Epoch AI：算力支出结构的宏观参考，注意估算口径。

## 四、跨章一致性规范

### 4.1 事实与案例规范

1.  案例不以"最新"作为唯一入选条件；优先选择公开资料充分、能解释决策过程的模型和研究。
2.  训练数字必须能定位到官方技术报告、论文、模型卡或官方工程文章。
3.  参数量必须注明总参数、激活参数、专家数量和统计口径。
4.  Token 数必须注明阶段、数据类型、训练/采样口径，避免将预训练 Token 与
    RL Token 混用。
5.  GPU 数量、卡时、训练时长必须注明硬件型号、集群形态和任务阶段。
6.  Benchmark 分数必须注明版本、数据集、采样设置、模型版本和评测方。
7.  "行业主流""普遍采用""前沿标准""首次"等判断必须提供足够广泛的一手证据；否则改为"某论文提出""某模型采用"或"一个公开案例显示"。
8.  对闭源模型，只使用公开披露的信息；不得推测其训练
    Token、算力、数据配比或训练配方。

### 4.2 证据等级

  -----------------------------------------------------------------------------------------------------------------------
  等级                    来源类型                                           使用方式
  ----------------------- -------------------------------------------------- --------------------------------------------
  A1                      原始论文、官方技术报告、官方模型卡、官方工程文章   可支撑具体技术和数字；需定位到章节/表格

  A2                      官方代码、官方文档、官方发布说明                   可支撑实现方式、接口和产品状态

  B                       独立复现、第三方实验、可信研究机构分析             需说明实验条件和独立性

  C                       博客、访谈、媒体报道、行业观点                     用于背景和线索，不单独支撑关键数字或强结论
  -----------------------------------------------------------------------------------------------------------------------

-   对公式中的变量逐一解释单位和统计口径。

## 五、每章写作与验收标准

### 5.1 教学质量标准

每章必须回答：

1.  本章解决什么真实问题？
2.  核心机制是什么？为什么会这样？
3.  有哪些可选方案？各自的代价是什么？
4.  如何根据条件做选择？
5.  有什么真实案例支持？
6.  哪些结论有争议或适用边界？
7.  读者可以带走什么工程方法？

### 5.2 内容交付标准

每章建议包含：

-   1 个真实问题开场；
-   1 个清晰的核心决策问题；
-   至少 2 张有解释价值的图表（架构图、流程图、对比图或计算示意）；
-   至少 1 个完整案例拆解，优先使用一手资料；
-   至少 1 个失败案例、反例或风险分析；
-   至少 1 个工程产物或可复用模板；
-   3--5 道 Quiz，覆盖原理、推导和场景判断；
-   6--12 条术语速查；
-   关键数字和结论均有引用定位；
-   章末下一章问题与下一章开篇精确对齐。

以上是质量下限，不要求为了满足数量而堆砌无价值内容。

### 5.3 可读性规范

1.  每节先讲问题，再引入技术名词。
2.  新术语第一次出现时，用一句人话解释。
3.  复杂技术必须配数据流、计算示例或架构图。
4.  表格用于比较，不用于堆砌名词。
5.  一段只讲一个主要观点；避免一段塞入多个论文结论。
6.  每个关键数字都解释"它意味着什么"，不能只展示数字。
7.  章节开头尽量使用真实工程困境，避免从历史沿革或术语定义开始。
8.  适当使用反例和决策题，让读者参与推导。

### 5.4 图表规范

图表优先解释以下内容：

-   数据如何流动；
-   模型如何计算；
-   资源如何分配；
-   方案如何取舍；
-   失败如何发生；
-   指标如何计算；
-   决策如何形成。

避免为了满足"至少两张图"而制作纯装饰性流程图。

## 八、最终验收标准

整套专题完成后，读者应能面对一个具体模型训练需求，完成以下任务：

1.  计算训练、推理和研发预算，并解释关键成本来源；
2.  从目标能力反推数据配方，设计数据质量和消融实验；
3.  在 Dense / MoE、注意力、上下文和多模态路线之间做选择；
4.  推导显存与并行策略，制定精度、Checkpoint 和容错方案；
5.  根据任务类型选择 SFT、蒸馏、偏好优化、RLVR 或 Agentic RL；
6.  设计奖励、环境、采样、信用分配和训练健康监控；
7.  建立贯穿训练生命周期的评测体系、安全约束和发布门禁；
8.  最终交付一份有备选方案、有数据依据、有风险记录的 Training ADR。

**专题的成功标准不是覆盖了多少模型、论文和算法，而是读者能否基于目标、约束和证据，独立做出一套可解释、可验证、可复盘的基础模型训练决策。**
