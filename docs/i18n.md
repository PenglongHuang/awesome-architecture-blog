# 中英文内容维护

## 本轮范围

中文地址保持原样，英文站使用 `/en/` 前缀。首批英文覆盖「入门篇 / Foundations」的 9 篇文章；其他系列不要求立即翻译。主站共享站点布局、文章和系列组件、搜索组件、主题及交互脚本，不维护两套组件。

英文首页和导航明确说明试点范围。无译文的中文文章显示「暂无英文版」，不生成占位英文页，也不把语言切换按钮指向不相关的文章。课程和架构图继续由原 skill 流程维护；`public/learning/` 未修改，英文导航中标为 `Courses (Chinese)`。

## 内容文件与身份

- 中文：`src/content/posts/tutorial/why-architecture-first.md`
- 英文：`src/content/posts/en/tutorial/why-architecture-first.md`
- 对应地址：`/tutorial/why-architecture-first/` 与 `/en/tutorial/why-architecture-first/`

路径均相对部署前缀；根路径和 GitHub Pages 子路径共用这套规则。

旧中文文件默认 `locale: zh-CN`，无需批量修改。中文默认的翻译身份为 `频道/slug`，例如 `tutorial/why-architecture-first`。英文必须显式声明同样的 `translationKey`，用于语言切换和 hreflang 配对。

英文 frontmatter 示例：

```yaml
locale: en
translationKey: tutorial/why-architecture-first
sourceHash: <核对译文时的中文文件 SHA-256>
series: foundations
order: 1
kind: tutorial
```

其余 title、description、tags、日期等字段按现有内容规则填写。两种语言共享 series、order、kind；正文、标题和标签使用各自语言。配对不依赖英文标题或英文文件名必须与中文一致；改变既有中文 slug 时，应先显式保留原 translationKey，并处理旧 URL 兼容。

## 修改与新增译文

1. 编辑本站中文和英文文件，核对正文、表格、图中文字、Quiz 与决策卡。
2. 中文目标已有译文时，英文内链指向 `/en/...`；目标仍为中文时，在链接文字中明确加 `(Chinese)`。局部锚点必须对应目标页面实际标题 ID。
3. 完成核对后，运行 `pnpm translation:hash tutorial/why-architecture-first.md`，将结果填写到英文的 sourceHash。此命令只输出 hash，不修改文件，也不代表自动完成了翻译审查。
4. 运行 `pnpm validate`，再运行类型检查、测试、构建、链接检查和 E2E。

hash 对完整中文文件计算，统一将 CRLF 换成 LF。中文正文或元数据变化后，validate 会拦截未重新核对的译文；不要只更新 hash 来绕过内容审查。hash 不会验证翻译质量。

## 扩展到新系列

在 `src/data/series.json` 对应系列加入 `translations.en.title` 和 `translations.en.description`，再添加英文文件。声明了英文元数据的系列会被视为完整发布的英文系列，CI 要求该系列所有中文文章都有译文。没有声明英文元数据的其他系列不受完整性要求影响。

目前英文路由开放 tutorial 频道。扩展模板或案例时，复用 `channelStaticPaths(channel, posts, 'en')` 添加相应的英文路由和索引页，再更新英文导航；不要在没有路由时仅添加内容文件。

## 页面、搜索与评论

- Astro i18n 定义语言；`src/lib/i18n.mjs` 提供共享文案，posts helpers 提供语言过滤和配对。
- 列表、上一篇/下一篇、相关推荐和 RSS 均按语言过滤。
- Pagefind 根据 HTML lang 生成和加载对应语言索引；新增语言后必须验证真实搜索结果，不能仅翻译搜索框。
- 中英文页面各自 canonical，存在对应版本时输出双向 hreflang 和中文 x-default；未翻译内容不声明虚假的替代页。
- `/rss.xml` 仅中文，`/en/rss.xml` 仅英文；搜索页保持 noindex。
- giscus 界面随语言变化，继续按 pathname 映射，因此中英文文章各自拥有评论线程。

## 验证

`pnpm validate` 检查重复身份、缺失中文源稿、试点系列缺译、频道/排序一致性、译文修订 hash、Quiz/Decision 数量和中文链接标识。现有构建链接检查继续验证实际站内目标与锚点。

E2E 覆盖中英文切换、英文主题与 Quiz、同语言导航、搜索隔离、RSS 数量及语言、canonical/hreflang 对应关系、无 JS 移动端导航。CI 在根路径和默认子路径两组运行这些用例。
